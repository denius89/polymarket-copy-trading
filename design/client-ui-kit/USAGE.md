# Client UI kit: использование

Дата: 12.10.2026. Источник — [пользовательский интерфейс в Figma](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T) и [техническая спецификация 117](../../docs/117_user_interface_technical_specification_2026-10-09.md).

Набор предназначен для пользовательского приложения Mobile/Desktop RU/EN. Он систематизирует существующий дизайн и дополняет его состояниями компонентов; не меняет бизнес-правила, не реализует приложение и не разрешает live. Итоговые ID, состав и количество объектов находятся в [manifest.json](manifest.json).

## Организация Figma

Четыре секции на единой странице `09 · Client UI kit` имеют роли:

| Секция | Что искать |
| --- | --- |
| Foundations | Семантические токены, типографику и правила визуального оформления |
| Controls | Кнопки, поля и элементы выбора с вариантами состояния |
| Data | Значения, статусы, карточки и повторяемые представления данных |
| Patterns | Составные примеры применения компонентов |

Совместимые существующие variables, styles и master-компоненты переиспользуются. Новый набор не требует параллельной системы цветов или замены каждого существующего master. Точные ссылки и происхождение объектов сверяются с manifest; примеры на страницах Patterns не считаются самостоятельными продуктовыми экранами.

## Связь с текущими экранами

После [исправлений 126](../../docs/126_client_grid_and_ui_kit_fixes_2026-10-12.md) новые native masters kit остаются образцами для будущего применения: прямых instances этих masters на четырёх продуктовых страницах нет. Текущие экраны продолжают использовать прежние Shared/Recovery masters и текстовые стили. Для разработки это две части одной дизайн-системы, а не разрешение автоматически заменить все instances. Выбирайте соответствие по назначению, variant/state, размеру, override RU/EN и реакциям; переносите конкретную семью после сравнения парных экранов. Существующие mobile Button/Action и Shared desktop header остаются источниками текущих реакций, пока их замена не проверена отдельно.

В Controls один канонический обзор переключателя — `Client/Touch switch` (`1982:38469`). Его master (`1982:38468`) содержит `Shared/Switch` (`987:93`) и шесть состояний; исходник и `Client/Icon button` (`1978:794`) лежат в подписанных source panels. Эти панели не являются новыми компонентами. Подробности — [пакет 127](../../docs/127_client_ui_kit_controls_cleanup_2026-10-12.md).

## Компоненты и экземпляры

Используйте нативный Figma-компонент через instance. Вариант выбирайте по его назначению и состоянию; подпись, значение и необязательный элемент меняйте через доступные component properties либо текстовый override. Не отделяйте экземпляр от компонента ради другого языка и не рисуйте поверх кнопки независимую подпись или невидимую область нажатия.

RU и EN используют одинаковую семантику действий. Перевод — override содержимого, а не отдельное разрешение или финансовое правило. Денежные значения, даты, адреса и проценты сохраняют смысл и единицу; длинная строка получает перенос или рост контейнера. В будущей реализации строки должны использовать смысловые i18n-ключи, а не названия Figma-слоёв.

При использовании на mobile и desktop сохраняйте понятные подписи, видимый focus и touch target не меньше 44×44 px. Текст состояния не должен зависеть только от цвета. Проверяйте расширение RU/EN текста, а не уменьшайте шрифт для его размещения.

Для текущих Controls используйте 24×24 мастера иконок внутри 44×44 Icon button; пример по умолчанию показывает Info, нужную иконку задаёт INSTANCE_SWAP. Touch switch имеет область касания 96×60 с центрированным визуальным Shared/Switch 48×44. Сам трек — 48×32. На hover обводку не показывайте; 2 px обводка вокруг трека относится только к клавиатурному `:focus-visible`, для обоих положений On/Off. Disabled не получает focus-обводку. Textarea — 360×182 с минимумом 72 px для области ввода, который сохраняется даже при пустом значении; не уменьшайте его до однострочного поля. Support Draft/Error и Feedback рассчитаны на эту высоту. Подробнее — [проверка от 12.10](../../docs/design/client/ui-kit-controls-and-forms-2026-10-12.md).

## Происхождение и смысл состояний

Существующий вид компонента является исходным дизайном. Добавленные hover, pressed, focus, disabled, loading и другие представления — покрытие UI kit для будущей разработки. Их наличие не означает, что соответствующий серверный сценарий реализован или что все продуктовые экраны уже прошли новую приёмку. Где состояние не относится к компоненту, не используйте его как декоративный вариант.

Не смешивайте визуальное состояние контрола и состояние операции:

- Loading блокирует повторное нажатие, но не доказывает исполнение.
- Requested/accepted означает принятие запроса; confirmed означает подтверждённый результат.
- Pending и unknown не превращаются в failed, cancelled или closed по истечении времени.
- Unknown/unavailable сумма не равна нулю; stale значение сопровождается указанием свежести.
- Partial сохраняет исполненную часть и показывает остаток; резерв не изображается расходом.

Опасное действие требует явного последствия и подтверждения. Передача позиции в ручное управление не означает продажу. Подготовленный пример остаётся отдельно от собственной новой EMPTY-сессии пользователя.

## Размер копии и ограничения

Компоненты показывают два принятых способа размера покупки: фиксированную сумму либо процент от конкретной BUY-сделки трейдера. Процент не считается долей бюджета пользователя. Демонстрационные суммы и процент из макетов — примеры содержимого, не значения токенов или неизменяемые системные константы.

Наличие сегментов выбора не утверждает новые risk-профили. Диапазоны, шаг, округление, минимум площадки, комиссии и разрешённые действия задаются согласованным контрактом и действующей политикой. Disabled-представление объясняет недоступность, но само по себе не обеспечивает серверную защиту.

## Границы применения

Текущие правила клиентской сетки, режимы ширины кнопок, ID новых Figma styles и проверки находятся в [grid-and-button-width.json](grid-and-button-width.json). Существующие экраны и prototype reactions не мигрируют автоматически на новые компоненты. Для замены нужен отдельный ограниченный проход с проверкой текста, размеров и переходов во всех четырёх версиях. Сначала используйте набор в новых или явно порученных изменениях; не заменяйте рабочие экраны массово ради одинаковой структуры слоёв.

Code Connect не создаётся: frontend-компонентов пока нет. Когда реализация появится, её можно связать с согласованными master-компонентами отдельной задачей, сохранив соответствие свойств и состояний.

UI kit не отправляет обращения, не создаёт реальные ордера, не подписывает транзакции и не подключает live. Он не закрывает открытые решения спецификации 117 и не расширяет права пользователя. Общие компоненты для ошибок, ограничений и уведомлений не являются автоматическим утверждением новых emergency/VIP/funding-сценариев.

## Construction records

`build-*.js` are initial-build records with explicit IDs and a COMMON insertion marker. They are not standalone restore scripts and must not be replayed into the working file. Later targeted corrections are recorded in qa.json; manifest.json and the native Figma file describe the final result. The kit has no production frontend or Code Connect mapping.

Common text has TEXT properties. State-dependent copy remains a variant-specific text override so Unknown/Confirmed/Requested are not flattened into one default.
