# Инструкции для Codex

## Перед началом задачи

1. Прочитать `docs/PROJECT_STATE.md`.
2. Прочитать документы, связанные с текущей задачей.
3. Использовать `references/Polymarket_Project_Dialogue_Handoff.md` как исходный контекст, если файл доступен локально. Бриф не публикуется в GitHub; в удалённой копии опираться на PROJECT_STATE.md и документы 07–09, не придумывать отсутствующий контекст.
4. Проверить остаток лимита перед крупным исследованием или архитектурной задачей.

## Текущий приоритет

По решению основателя от 24.09.2026 разработка MVP, wireframes и интерактивного прототипа приостановлена до согласования идеи и архитектуры. Выполнять исследование и документирование по docs/07_strategy_architecture_review.md. Прежние указания перейти к прототипу не исполнять.

## Рабочий процесс

- Один цикл должен давать один проверяемый результат.
- Реализовывать минимальный вертикальный срез и не расширять объём без необходимости.
- После изменения интерфейса проводить визуальную проверку.
- После изменения поведения выполнять соразмерные тесты.
- После завершения обновлять `docs/PROJECT_STATE.md`.
- Архитектурные решения фиксировать отдельным файлом в `docs/decisions/`.

## Безопасность

- Не сохранять приватные ключи, seed phrase, session cookies и рабочие API secrets.
- Реальное исполнение должно быть выключено по умолчанию и включаться явным флагом окружения.
- Не выполнять реальные сделки без отдельного решения основателя о переходе из paper trading.
- Любое неизвестное состояние ордера должно блокировать дальнейшее рискованное действие и создавать запись инцидента.
