# Клиентские страницы «Финал» · расширение и проверка

Дата: 14.10.2026. Статус: визуальный пакет действующего paper MVP и структурная QA завершены; выборочный Present RU/EN mobile выполнен позднее через встроенный браузер, полный ручной проход остаётся открытым.

Файл Figma: [Controlled Copy Trading — Paper MVP](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T). Правки выполняются только на четырёх клиентских страницах «Финал». Админка и исходные клиентские страницы не входят в этот пакет.

Позднее, по уточнению владельца, четыре мобильные страницы получили точные названия: `01 · Мобильная версия · EN` (`29:2`), `01a · Мобильная версия · EN · Финал` (`2499:2`), `02 · Мобильная версия · RU` (`33:2`) и `02a · Мобильная версия · RU · Финал` (`2477:528`). Это мобильная версия единого веб-проекта, а не отдельное нативное приложение. Переименование не изменило ID, экраны, компоненты или переходы; исторические названия в прежних отчётах описывают те же страницы.

## Исходная точка

До этого этапа в каждом «Финал» был скопирован основной маршрут и визуально утверждён один экран: каталог трейдеров на mobile RU/EN либо главная активного демо на desktop RU/EN. Остальные 48 mobile RU/EN, 50 desktop RU и 53 desktop EN состояния маршрута нельзя было считать индивидуально принятым финальным дизайном. Дополнительные действующие сценарии оставались на исходных страницах. [Предыдущий пакет](final-examples-2026-10-14.md) сохраняется как история.

Критерий состава для текущего этапа — действующие сценарии paper MVP по [карте U01–U28](../../34_screen_and_state_map.md). Исторические дубли, заменённые справочные экраны и явно обозначенные FUTURE/live состояния не переносятся как активный MVP. Любой перенос требует проверки видимого дизайна, RU/EN текста и реакций; простое копирование не закрывает критерий готовности.

## Последующие мобильные дополнения

На страницах Mobile RU/EN добавлены формы входа и его ошибок, ответы помощи, каталог и профиль первого посещения, пустая главная, отдельные гостевые профили для периодов 24 часа / 7 дней / 90 дней / всё время. RU/EN профили и каталоги первого посещения остаются отдельным контекстом: активный профиль показывает баланс демо и другой период, поэтому прямой переход гостя на него неверен. Точные основные узлы: RU guest profile `2536:4848`, EN `2536:136100`; RU period section `2539:4848`, EN `2539:10364`.

RU/EN Referral Final: `2557:53886` / `2557:56851`. Экран показывает код и пример статистики, но не обещает неподтверждённые проценты, выплаты, пороги или сроки из старого источника. `Copy invitation link` остаётся runtime-действием: Figma не копирует ссылку в буфер обмена.

RU/EN Notification preferences имеют состояния weekly и daily: RU `2560:47570` / `2560:143136`, EN `2560:143011` / `2560:143216`. In-app сообщения обязательны, Telegram необязателен и не подключён, критические события сразу, weekly — стартовый выбор. Figma демонстрирует выбор, но не сохраняет серверные настройки и не подключает Telegram.

В мобильных основных маршрутах после визуального аудита фильтры Positions (6), Activity (7), Orders (6) и Help размещены полностью, без обрезанной крайней кнопки; кнопки высотой 48 px, следующие блоки сдвинуты без наложений. EN Profile приведён к RU по видимому порядку Language / Notifications / Referral / Feedback. Переходы Language RU↔EN указывают на соответствующие Final Profile. Несколько ранее инертных основных CTA получили цели внутри Final; future-only «Подключить счёт» визуально недоступна в демо.

## Последующие десктопные дополнения

Все основные route-узлы Desktop RU/EN проверены визуально: 50 RU и 52 EN полноразмерных экрана плюс один RU и два EN оверлея. EN списки Positions / Orders / Events / Operations / Notifications / Tickets разделены карточками по принятому RU-ритму. На RU-подтверждении обращения убран пустой блок. First run RU/EN получил более ясные шаги; формы отзыва и обращения показывают поля и основное действие. EN Telegram-состояния переведены, в RU search overlay исправлены две EN-подписи. Рендеры затронутых экранов проверены без обрезки. Экраны real accounts относятся к future/live и не означают доступность реального счёта в MVP.

Desktop Profile: оба URL Language теперь ведут на противоположный Final Profile. Входы в Referral, Notifications, Feedback и Sign in связаны с финальными экранами; RU Help получил явное «Новое обращение». RU/EN Referral `2562:136184` / `2562:180163` не содержит неподтверждённых payout-условий. RU Notification preferences `2562:136270` дополнены; существующие EN weekly/daily приведены к тому же принятому смыслу.

Для принятого Close & stop созданы отдельные подтверждение и ожидание: [RU `2563:136377`](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2563-136377) → `2563:136412`, [EN `2563:136545`](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2563-136545) → `2563:136580`. Текст не обещает мгновенного закрытия; результат остаётся на сверке до подтверждения. Восемь кнопок RU sidebar на этой паре экранов перенаправлены в действующие Final Home / Traders / Positions / Activity.

## Итоговая проверка и границы

Визуально просмотрены все 50 основных мобильных экранных фреймов на язык и все 105 десктопных экранов/оверлеев основного маршрута (50 RU + 1 overlay, 52 EN + 2 overlays). Дополнительные уникальные MVP-состояния проверялись по изменённым экранам и сценарным группам; это не pixel-by-pixel проверка каждого скрытого historical слоя. Исходные четыре клиентские страницы и админка этим пакетом не менялись.

Финальный структурный проход после всех правок:

| Final-страница | Видимые `NODE`-действия | Внешние / пустые / ведущие в скрытый экран | Обрезка детей видимых кнопок |
| --- | ---: | ---: | ---: |
| Mobile RU `2477:528` | 1 148 | 0 / 0 / 0 | 0 |
| Mobile EN `2499:2` | 1 138 | 0 / 0 / 0 | 0 |
| Desktop RU `2477:529` | 1 136 | 0 / 0 / 0 | 0 |
| Desktop EN `2499:3` | 1 103 | 0 / 0 / 0 | 0 |

На каждой из четырёх страниц есть ровно один URL-переход Language, и все четыре ведут к видимому Final Profile противоположного языка: mobile RU `2502:18505`, mobile EN `2498:27461`, desktop RU `2504:3574`, desktop EN `2499:2422`. В новых desktop-секциях не осталось инертных кнопок по проверке button-like имён. На новых mobile-секциях исключения — выбранные weekly/daily варианты, контейнеры и `Copy invitation link`, которая должна работать только в приложении. Поиск в исходном Figma-каталоге остаётся визуальным полем; ввод и результаты должны реализовываться и тестироваться в коде.

Текущие вкладки/пункты навигации без самоперехода, а также обозначенные future-only действия не считаются ошибкой. Прототип не исполняет серверное сохранение, Telegram-подключение, копирование ссылки, сделки или отправку сообщения. Условия альтернативных risk profiles Low/Medium/High остаются открытым UI-01: различие RU/EN компоновки не задаёт новые правила; при разработке опираться на принятый стартовый preset и [спецификацию 117](../../117_user_interface_technical_specification_2026-10-09.md). Экраны real accounts являются future-info, не доказательством готовности live.

Первоначальный запрос к Figma desktop 14.10.2026 завершился ошибкой Computer Use `permissions are not granted`. Позднее установлено, что прямые ссылки `/proto/` открываются во встроенном браузере без входа в Figma. В Present выборочно проверены действительные переходы Final mobile RU: каталог `2498:26322` → профиль трейдера `2498:28378` → период 7 дней `2498:28229`; Final mobile EN: каталог `2502:17367` → профиль трейдера `2502:19420`. Исходный RU маршрут также открылся и выполнил переход старт → активное демо. При этом нажатие Home из открытого Final каталога RU и профиля EN не сменило кадр, хотя реакция Home у RU каталога структурно содержит условный переход. Это **открытый пункт ручной проверки**, не засчитанный как работающий маршрут; нужно сверить состояние сессии и назначение Home до правки реакции. Доступ через браузер снимает блокировку по macOS-разрешениям, но **не означает полного ручного прохода всех клиентских сценариев**. При передаче в разработку открыть свежий main и конкретные Figma-узлы, завершить Present-проверку RU/EN mobile/desktop и тестировать реальные действия в веб-интерфейсе. Документ 117 и открытые бизнес-вопросы сохраняют приоритет над случайным состоянием макета.

Позднее в тот же день обнаруженная реакция Home [исправлена пакетно на RU/EN Final mobile](final-mobile-home-navigation-2026-10-14.md): 110 одноветочных `CONDITIONAL` заменены на уже действующий двухветочный шаблон `empty` / active. RU каталог → главная и EN профиль → главная после правки прошли ручной Present. Ветка `empty` и полный clickthrough ещё не приняты.
