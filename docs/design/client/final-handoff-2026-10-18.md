## Контракт маршрутов и состояний

`sitemap.json` содержит отдельные Final-якоря ручной паузы и возобновления для четырёх версий: Home, локальные каталоги/профили и известные Positions/Activity. Переключение Home → Traders → профиль → Positions/Activity → Home сохраняет текущую session ID, venue и paused/resumed state; ручная пауза не равна ожиданию сверки unknown-заявки. Общие Help, Notifications, Account и историческая симуляция в прототипе не доказывают stateful-возврат. В реализации эти разделы должны возвращать к сохранённой сессии через маршрутизатор, а не копировать Figma destination буквально.

| Состояние для разработки | Дизайн-основание | Следующая проверка |
| --- | --- | --- |
| Первый вход, настройка, вход, пустая демо-сессия | Final-прототип и 117 §4; подготовленный пример отделён | E2E RU/EN: черновик, вход, один EMPTY-start, 0 ордеров/позиций |
| Активно, ручная пауза, возобновление | Final Home/списки и `sitemap.json.finalManualPause` | Возврат из основных и вспомогательных разделов сохраняет состояние |
| Pending/unknown, резерв, stale/partial/offline | 117 §12 и принятая бизнес-логика; общие элементы kit | Перед зависимым кодом принять нужные кадры/копию, затем проверить серверный запрет retry и отсутствие ложного нуля |
| Ошибки, conflict, no permission, истекшая сессия | 117 §12; полная визуальная матрица ещё открыта | Определить затронутые состояния для каждого вертикального среза и проверить клавиатуру/диктор |
| Emergency/VIP/funding в объёме будущего среза | 117 §12, UI-09; не все состояния приняты визуально | Не считать общие компоненты approval конкретного сценария; отдельная приемка до реализации этой функции |

Figma подтверждает композиции и выбранные переходы, но не runtime. Для пользовательской приемки остаются ширины 320/360/1280/1440 px, увеличение текста 200%, клавиатура, диктор, reduced motion, реальные данные, ошибки и финансовые запреты сервера. Готовность каждого вертикального среза оценивается по его состояниям, а не по общему числу кадров в Figma.
