Область — четыре клиентские Final-страницы, пояснение EN mobile и актуализация спецификации 117. Админка и финансовые правила сохраняются.

## Поведение макетов

- Основной вход: «Начать / Get started» → единый email → проверка кода → каталог нового аккаунта без черновика. Вход не запускает демо.
- Гостевой выбор трейдера → настройка → проверка доступен без входа. Нажатие «Запустить демо» гостем открывает email, затем возвращает к проверке. Для запуска требуется отдельное нажатие.
- Фиксированная сумма и процент имеют отдельные возвраты из email и из «Изменить настройки». Процентная ветка не превращается в фиксированную. Черновик сохраняется при показанных ошибках кода и возвратах.
- Существующие active/paused, пустая уже начатая сессия и позиции/незавершённая сверка имеют приоритет перед черновиком. Новые экраны продолжения объясняют результат; вход не возобновляет паузу и не создаёт вторую сессию. Для завершённой сессии без обязательств есть явный выбор нового трейдера.
- В EN mobile восстановлено пояснение «New signals only. Existing orders and positions stay unchanged.» в fixed и percent review. Строки таблицы компактнее, чтобы пояснение помещалось перед кнопкой запуска.
- В desktop подтверждение показывает код из письма вместо повторного поля email. Это учебный ввод; письма не отправляются. Необязательный вариант ссылки и техническая auth-политика остаются по ADR.

## Компоненты и контекст прототипа

Четыре новых экрана продолжения клонируют существующие клиентские before-session шаблоны, сохраняя instances, шрифты Inter, цвета/стили и навигацию. Новых masters, вариантов компонентов, визуальных токенов или изображений целого экрана внутри Figma нет. Состав editable-узлов сохранён в `continuation` каждого `after-*.json`; изображения PNG рядом — отдельные доказательства просмотра.

В коллекции `Prototype · ADR-0048 entry` заведён отдельный контекст каждой версии: AccountState, DraftMode, Origin, ResumeBody, ResumeCta и RouteChosen. SessionStage больше не используется как временное значение `auth-fixed`/`auth-percent` в изменённых переходах. AccountState — **заданный учебный вход**, а не запрос к серверу. Данные аккаунта, позиции, unknown, счётчики и история автоматически не вычисляются этим макетом. Просмотр prepared example не является созданием собственной сессии.

Плагин сохраняет только два блока одного CONDITIONAL и не принимает вложенные CONDITIONAL. Это обнаружено повторным чтением фактических действий: первый сложный вариант не прошёл матрицу. Итоговая процедура компилирует упорядоченные решения в бинарные условия с отдельным guard: только одна ветка выбирает назначение. Сравнения и guard повторно проверяются по выгруженным действиям, а не по тексту скрипта построения. Булевы RouteChosen имеют явно заданный ALL_SCOPES, допустимый для этого типа; строки для тела/кнопки ограничены TEXT_CONTENT, служебные строки не предлагаются как визуальные токены.

## Перед реализацией

Реальные email/аккаунты, провайдер, TTL/rate limit, серверное определение текущей сессии, хранение/версии черновика, reload/Back браузера и перенос между устройствами требуют реализации и проверки приложения. Статический переход не доказывает восстановление введённых пользователем значений. Отдельно проверить изменившиеся правила/недоступного трейдера без молчаливой подмены.

Полная ручная приёмка всех клиентских и административных веток X01/X04 и бизнес-вопросы BL-05–08 остаются открытыми. Пакет исправляет согласованный дизайн входа и его передачу; frontend, live, тарифы и методика рейтинга не запускаются.
