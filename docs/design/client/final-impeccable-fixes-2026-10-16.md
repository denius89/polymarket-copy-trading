## Поведение для реализации

Выбранная строка листа и значение закрытого селектора представляют **один фильтр**. При выборе нового пункта предыдущий маркер исчезает, новый появляется, счётчик и набор записей соответствуют выбору; повторное открытие показывает этот пункт. Для каждой локали здесь 6/6/7 вариантов. Экранные булевы переменные — только механизм Figma-прототипа; в коде нужен один источник состояния фильтра, без отдельного независимого массива флажков. Наличие `CLOSE` в реакции подтверждено структурно, но серверная фильтрация и хранение состояния между сессиями макетом не задаются.

Карточка текущего демо-счёта остаётся источником суммы на Главной; переключение платформ относится к отдельным будущим состояниям. Отсутствующая максимальная просадка показывается один раз на уровне списка, без выдуманного числового значения. В уведомлениях статус и действие видны одновременно и различимы текстом, а не только цветом.

## Проверка и границы

Снимки Figma просмотрены после правок для RU Positions/EN Activity filter, EN Home, EN catalog, EN desktop Home positions card, Positions, Orders, Notifications и review board UI kit. На всех шести списках структурно проверены 6/6/7 строк, сохранённый финальный `CLOSE` и добавленные действия выбора. Проверены узлы/реакции изменённых desktop-ссылок и карточек; новых переходов не создано. Полный ручной Present по всем пунктам, адаптивная реализация, клавиатура, экранный диктор и runtime-данные этим пакетом не проверялись. Итоговый клик-проход RU/EN mobile/desktop остаётся отдельной приёмкой.
