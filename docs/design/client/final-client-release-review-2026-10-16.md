## Проверка маршрутов

Основной маршрут первого запуска проверен в Present на EN desktop: каталог → профиль → настройка → проверка → образец email → подтверждение → проверка настроек → запуск → новая пустая Главная. Отдельно проверены активная Главная и переходы к спискам/деталям в предыдущей [приёмке](../../qa/client-final-acceptance-2026-10-16.md). Изменённые ветки паузы и новые состояния проверены отдельно по каждой локали и размеру; узлы и результаты приведены выше и ниже.

Дополнительно EN desktop пройден в Present: paused `2529:135786` → Resume `2884:143694` → Manage session `2529:135603` → Pause обратно `2529:135786`; paused Positions `2884:144007` содержит ровно три согласованные строки и Home возвращает к паузе; paused Activity `2884:144042` содержит три confirmed события. Пустая EN Home `2504:5634` просмотрена в Present: один счёт $200/0/0, отдельная сессия Momentum Fox, широкий пустой блок позиций, без повторного крупного баланса.

RU desktop также пройден в Present: paused `2529:133953` → Resume `2859:4786` → resumed Positions `2883:143474` с тремя позициями → Home сохраняет активную сессию. Пустая RU Home `2499:3827` просмотрена по снимку: один счёт 200/0/0, отдельная сессия Momentum Fox и пустые позиции. В четырёх новых desktop Positions скрыт унаследованный таб «Заявки»/Orders, поскольку его цель относилась к чужому примеру; отдельный список заявок для этой ручной ветки не проектировался.

Контрольное правило для каждой ветки Home → Positions → Activity → Home: заголовок Home постоянен; режим демо виден без предыдущего экрана; число позиций совпадает с открываемым списком; события относятся к той же сессии; возврат сохраняет паузу или активность. Ручная пауза допускает возобновление новых покупок, но заявка со статусом unknown/ожиданием сверки не превращается в подтверждённую при переходе. Число «доступно» нельзя переносить из другой демонстрационной сессии.

## Границы утверждения

Figma представляет фиксированные кадры и демонстрационные данные. Масштаб текста 200%, клавиатура, экранный диктор, фактическая адаптация к 320/360/1280 px, серверная фильтрация, email, торговые действия и доступность runtime не подтверждаются статическим макетом. Их критерии остаются в [спецификации интерфейса](../../117_user_interface_technical_specification_2026-10-09.md) и принимаются при реализации. Неизвестный результат заявки сохраняет резерв и блокирует повторное рискованное действие до сверки по [бизнес-логике](../../MVP_BUSINESS_LOGIC.md).

Замкнутость состояния проверена для основной навигации Home/Traders/профиль/Positions/Activity. Вспомогательные ссылки на Help, Notifications, Account и примеры исторической симуляции используют общие шаблоны; их обратный путь из ручной ветки не принят как stateful. При реализации возвращать пользователя к сохранённому состоянию сессии через роутер, а не копировать эти демонстрационные связи буквально.
