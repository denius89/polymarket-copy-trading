# Защищённое восстановление доступа

27.10.2026. Учебный маршрут новой админки, по ADR 0046 и границам ADR 0043.

Вход на сайте: «Не получается войти?» → учебный аккаунт → «Начать восстановление». Из рабочего раздела: личный профиль → безопасность → восстановление. Вход в Figma связан с теми же учебными сотрудниками; русский и английский используют общие состояния.

## Как пройти

1. Выберите, что произошло, и действующий запасной способ либо одноразовый код. Это проверка только для восстановления защиты, без рабочих полномочий.
2. Зарегистрируйте основной способ и проверьте его. У владельца отдельно зарегистрируйте **другой физический ключ** и проверьте его. Учебные устройства A/B/C не являются настоящими ключами.
3. Примените проверенную защиту. При неизвестном результате проверяется исходный запрос, повторная отправка закрыта.
4. Выполните новый вход. Сотрудник, язык и рабочий контекст сохраняются; старые сеансы и неиспользованные подтверждения не восстанавливаются.

Смена языка доступна на каждом шаге. На сайте выпадающие списки работают напрямую; в Figma используются подготовленные варианты выбора. Для отказа и неизвестного результата есть явно обозначенные учебные ответы проверки.

## Что не даёт права войти

- Потерянный/уже использованный код, неуспешная проверка и неподтверждённый исход замены.
- Один и тот же физический ключ вместо двух разных ключей владельца.
- Отзыв, блокировка, истечение или изменение назначения. Замена защиты не снимает эти ограничения.
- Подозрение на компрометацию: требуется отдельный разбор инцидента и решение о возврате доступа. Возврат денежных возможностей — отдельное аварийное согласование.
- Отсутствие действующего способа, в том числе у обоих владельцев: защищённая независимая процедура; общего ключа и обхода через поддержку нет.

## Открытое организационное решение

Перед настоящей реализацией нужно утвердить независимых проверяющих, канал и подтверждающие сведения для случая потери доступа обоими владельцами. Прототип показывает ожидание этой проверки, не выдумывает проверяющего и не имитирует успешный обход.

Это браузерная модель: без сервера, настоящих ключей, кодов, документов и доставки уведомлений. Она задаёт требования для реализации. Сервер должен повторно проверять актуальные права, версии, одноразовость, сроки и отзыв; скрытые кнопки не являются защитой.
