# Сверка клиентского интерфейса и админки · 27.10.2026

**Итог: основные денежные и защитные правила согласованы, полное сквозное соответствие пока не подтверждено.** Найдено одно расхождение учебной модели с правилом одной активной сессии, а также четыре пробела связности/формулировок. Это адресная сверка после фиксации дизайна админки v1; дизайн заново не пересобирается.

Исходная main: `3cde405d8a9d19cb18efe7636747debd9f781c95`. Админка — публичный прототип v18; клиент — действующие Final-страницы и дополнительные состояния 19 октября. [Манифест наблюдений](evidence.json), [проверка учебной модели](model-probe.json).

## Найденные замечания

| ID | Приоритет / вид | Наблюдение и последствия | Требуемое исправление |
| --- | --- | --- | --- |
| CA-01 | P1 · расхождение учебной модели | В `prototype/app.js` у Demo Atlas / U-DEMO-001 созданы S-DEMO-001 (Polymarket) и S-DEMO-001B (Limitless), обе с датой 17 октября и без состояния завершения. Функция `activeSessions` включает обе; таблица и карточка не отличают историю от текущей сессии. Новая админка меняет собственную модель; свежая передача состояния в действующий клиентский путь не подтверждена | Подготовить один связанный набор состояний «действие сотрудника → результат пользователя» для ограничений/восстановления, VIP и публичного ответа. Проверить основные и прямые входы. Наличие отдельного кадра не считать сквозной связью |
| CA-03 | P2 · несовпадающие учебные объекты | Клиентская неизвестная заявка: Noor / S-DEMO-002 / ORD-DEMO-03; новая админка: тот же Noor / S-DEMO-002 / ORD-002 / REC-101. Для приёмки одного сценария использовать один user/session/order/ticket/message и одну версию данных на обеих сторонах. Сейчас нельзя выдавать эти разные примеры за одну сквозную проверку |
| CA-04 | P2 · неоднозначная денежная подпись | Клиент RU/EN показывает «Подтверждённое исполнение: $0» / “Confirmed fill: $0”; админка для неизвестного результата показывает «Не подтверждено», модель хранит `fill:null`. Это может означать отсутствие подтверждённых исполнений, но не доказывает фактический нулевой итог | Согласовать подпись: «Исполнение пока не подтверждено» / “Fill not confirmed yet”. Если нужен именно известный итог подтверждённых событий 0, подписать его отдельно и сохранить неизвестный фактический результат. Резерв 20 и запрет повтора уже согласованы |
| CA-05 | P2 · известный пробел контекста клиента | Клиентский handoff подтверждает сохранение сессии для Главная/Трейдеры/Позиции/Активность, но Help/Notifications/Account используют общие шаблоны; возврат в то же состояние не принят. В новой админке профиль/язык сохраняют рабочий контекст в подготовленных сценариях | Проверить клиентский возврат из помощи, переписки, профиля и уведомлений к исходному пользователю/сессии, ручной паузе, ограничению и выбранному объекту. Смена языка и простой просмотр не должны возобновлять торговлю |

CA-01 относится к показанной учебной модели, а не к обнаруженной возможности запустить вторую реальную сессию: реального сервера здесь нет. CA-02/03/05 — ограничения приёмки прототипов, а не доказательство серверной уязвимости. CA-04 — различие смысла подписи, а не найденное фактическое списание.

## Следующий ограниченный шаг

1. Исправить CA-01 и CA-04 на существующих данных/экранах без нового бизнес-правила.
2. Для Noor и Robin связать одинаковые заявки/снимки и одно обращение на обеих сторонах; сохранить различие между примером и реальными данными.
3. Пройти пять пар: неизвестная заявка, позднее исполнение, технический режим/восстановление, VIP и ответ поддержки. Проверить RU/EN и возврат через профиль/помощь. После этого расширять только по обнаруженному расхождению.

Это результат проверки. Клиентский и административный runtime, Figma-холст и публичный сайт данным пакетом не изменялись.

## Охват и ограничения проверки

Свежая визуальная проверка: 17 снимков Figma — 15 клиентских, 2 административных, перечень с IDs в манифесте. Есть RU/EN и mobile/desktop, но не полный перебор каждого сценария во всех четырёх версиях. Один клиентский кадр дополнительно прочитан через metadata. Сопоставлены текущие принятые правила, handoff и исходники публичной админки v18.

Программное чтение текстов/реакций через use_figma не завершилось: запросы остановлены после затяжного ожидания. Вместо него использованы адресные screenshot/metadata, которые завершились успешно. Нового полного графа переходов и ручного прохождения Present в этом пакете нет. Исторические проверки не выданы за повторённые сегодня. Снимок фиксирует видимое состояние, а не работу серверного запрета или доказанный переход.
