## Локальный пример

Все 14 наборов проверок прототипа проходят: 2531 утверждение, включая 65 новых. Проверены семь назначений × RU/EN, прямые вызовы без права, собственный аккаунт/владелец, отмена проверки ключом, привязка к автору/получателю/причине/версии, отзыв права, неизвестный результат без повтора, три подтверждённых последствия, запрет разблокировки через обычное назначение, отдельный инцидент и сохранение его команды после новой операции.

Ручной браузерный проход: владелец A → Нора → причина → последствия → ключ → изменение причины. Старое подтверждение исчезло сразу, поле осталось в фокусе, вернулась проверка последствий. Повторный мобильный проход RU → неизвестный результат → профиль → EN → прежняя команда → подтверждение → инцидент сохранил сотрудника и исходную причину. Чужой пользовательский текст автоматически не переводится. Журнал явно ограничен текущим учебным проходом.

Снимки после исправлений, viewport 1440 и 390; полоса прокрутки может исключать 15 px из изображения. Горизонтальное переполнение мобильного документа не обнаружено. Физические устройства не проверялись.

Независимый finish reviewer нашёл и повторно проверил два дефекта: старый инцидент брал новую команду по сотруднику; редактирование причины оставляло прежнее подтверждение видимым. Оба исправлены, вердикт **ship** для представленного локального среза. Documenter подтвердил повторное использование существующих токенов, Inter, оболочки и форм; глобальная дизайн-система не переписывалась. Унаследованный отступ перенесённой второй кнопки на мобильном экране не принят как новое правило системы. Figma этим независимым вердиктом не покрывается.

## Figma: фактически пройденное

- Владелец A, настольная версия: вход → сотрудники → Нора → защита → учебная причина → последствия → ключ → команда → неизвестный результат → профиль → EN → возврат к прежней команде → подтверждение → инцидент → условия восстановления → инцидент → карточка той же Норы со статусом блокировки.
- Владелец B, мобильный корень 390: EN → меню → сотрудники → Нора → защита → потеря устройства → последствия → ключ → команда → подтверждение → связанный инцидент. Прокрутка позволяет дойти до действий ниже первого экрана. Это проверка мобильного макета в Present, не физического телефона.
- [Неизвестный результат RU](evidence/figma-unknown-desktop-ru.png), [инцидент EN](evidence/figma-incident-desktop-en.png), [результат mobile EN](evidence/figma-result-mobile-en.png), [инцидент mobile EN](evidence/figma-incident-mobile-en.png), [журнал выбранных нажатий](evidence/figma-trace.json).
- [Чтение структуры](evidence/figma-structure.json): все 12 добавленных корней существуют, 210 корней на странице; нативные тексты/экземпляры кнопок, ни одной растровой заливки, текстовых слоёв шириной менее 8 px не найдено. Это не автоматическое доказательство отсутствия любых пересечений.
- Исправлены видимость действия отправки до проверки ключом, привязка подписи результата к объекту команды и мобильные возвраты. Рецепты сохранены в пакете. Настольные и мобильные реакции используют прежние общие RU/EN переменные.

После обновления режима Figma часть динамических подписей исчезала из дерева доступности, оставаясь видимой на холсте. Такие действия проверялись по изображению; полный скринридерный проход не заявлен. В существующем профиле EN наблюдались узкие подписи части бокового меню — отдельная общая вычитка, не закрытая этим пакетом. Сайт поддерживает свободный текст и историю нескольких команд; Figma только подготовленные значения и текущую команду. Figma не заменяет серверную защиту.
