# Защита аккаунта сотрудника

26.10.2026 · ограниченный учебный срез ADR-0046. [Границы требований](brief.md), [проверка](verification.md).

[Публичный пример](https://shadow-admin-demo.denisfedko.chatgpt.site) · [Figma: настольный вход](https://www.figma.com/proto/lxPP2um7FvIbt02K8eeH4T?node-id=3990-108&starting-point-node-id=3990-108&scaling=scale-down) · [Figma: мобильный вход](https://www.figma.com/proto/lxPP2um7FvIbt02K8eeH4T?node-id=4160-650&starting-point-node-id=4160-650&scaling=scale-down).

## Как проверить

1. Войти учебным владельцем A или B → «Сотрудники и права» → Нора Азиз → «Защита аккаунта».
2. Указать причину, проверить три последствия и выполнить учебную проверку физическим ключом. Изменение причины требует повторной проверки.
3. В «Учебных состояниях» выбрать неизвестный результат. Отправить команду; аккаунт не считается заблокированным. Перейти в профиль, сменить язык, вернуться к той же команде.
4. Выбрать подтверждённый успех и проверить прежнюю команду. Открыть связанный инцидент, журнал и условия восстановления. Блокировка не закрывает инцидент и не отменяет отправленные операции.

На сайте причина вводится свободно; в Figma доступны подготовленные варианты. Локальный журнал инцидентов сохраняет точную связь с каждой командой в текущем проходе. Figma показывает одну текущую команду, без каталога исторических инцидентов. Проверка ключа, уведомления, блокировка и отзыв сеансов — симуляция, не реальные действия.

- [Модель сайта](../prototype/staff-security.js), [регрессионные проверки](../prototype/check-staff-security.cjs), [публикация v11](publication-evidence.json).
- Общая карта теперь содержит 210 корней: 105 настольных + 105 мобильных. RU/EN используют общие корни; это не 420 экранов.

Следующий отдельный пакет — системные ограничения и связность аварийного управления. Защита другого владельца, проверка личности после взлома и фактический возврат доступа остаются открытыми защищёнными процедурами; общая приёмка админки не завершена.
