# Защита аккаунта сотрудника · ограниченный срез

26.10.2026. База main `79b48999309951e38ec9914bb6486665565cb169`.
Режим Operate, продолжение согласованной оболочки сотрудников: Inter, существующие токены, сетка, компоненты и контекст вошедшего сотрудника. Новый визуальный стиль не вводится. Источник требований — ADR-0046, раздел «При подозрении на взлом»; личный профиль и свои сеансы уже реализованы отдельно.

Маршрут: карточка сотрудника → защита аккаунта → причина → последствия → свежая учебная проверка физическим ключом → отправка → подтверждённый/неизвестный результат → связанный инцидент и последние действия → отдельные условия восстановления.

В этом срезе команду выполняет только действующий владелец для другого сотрудника, не владельца. Руководитель и аудитор читают; остальные роли не получают сведения о чужой защите. Это консервативная граница учебного интерфейса, не новый принятый серверный каталог полномочий. Блокировка другого владельца и возврат доступа требуют отдельной защищённой процедуры и остаются открытыми, без кнопки обхода.

Подтверждённые последствия показаны отдельно: блокировка входа/новых действий, завершение сеансов, отзыв неиспользованных подтверждений. Уже отправленные операции могут завершиться; сверка и резервы сохраняются. Неизвестный результат не доказывает блокировку и запрещает повтор. Изменение причины, получателя, версии или автора требует новой проверки. Уведомления обоим владельцам — учебная очередь, доставка не доказана. Инцидент не закрывается по одному факту блокировки. Возврат из инцидента/профиля и смена RU/EN сохраняют контекст.
