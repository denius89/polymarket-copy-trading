## Контракт Q06

- HTTP 200 с сессией содержит обязательную сводку. Скрытые по правам группы отсутствуют и перечисляются в `restrictedGroups`. При разрешённой сводке без финансовой группы суммы не подставляются.
- HTTP 200 с `session: null` применяется к подтверждённому отсутствию текущей сессии при отдельном праве по всем площадкам. При чтении по ID отсутствующий и скрытый ресурс дают одинаковый 404. Первая сессия из списка никогда не подставляется.
- HTTP 503 означает, что обязательные данные или чтение не подтверждены. Успешный Q06 выдаётся после сохранения обязательного аудита. Списки заявок и событий требуют собственных разрешённых источников.

Для синхронизации с клиентским UX используйте одну видимую идентичность AP09: `S-DEMO-EMPTY-01` (символ `SS` в контракте), Polymarket, снимок `1`, `asOf=2026-11-02T12:02:00.000Z`. Финансирование, свободные средства и капитал равны 200 виртуальным USD. Резерв, стоимость и оценка позиций, результат и счётчики равны нулю. На момент передачи [клиентский продуктовый кадр 2532:21021](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2532-21021) использует другую учебную идентичность. До переноса общего снимка в штатный клиентский маршрут и сравнения двух продуктовых экранов сквозная проверка X07 остаётся открытой.

Источники: [AP09, §8](../../../../technical/first-session/database-api-response-examples.md), [DB-API-09, §§13–14](../../../../technical/first-session/database-q06-absence-design.md), [Q06, §§3.6 и 11](../../../../technical/first-session/backend-api-forms-addendum.md).

## Восстановление и вход

В single второй владелец подтверждает точный запрос действующим ключом. В pair оба новых ключа ограничены recovery до подтверждённого завершения общей операции. После завершения прежние ключи и входы отзываются. Каждый участник проходит новый вход, а сервер проверяет актуальное назначение. Случай потери нужного кода без рабочего способа входа остаётся за G01.

Источники: [Auth policy, §§17–18](../../../../technical/first-session/auth-policy.md), [D02/v6, R33–R42](../../../../technical/first-session/backend-auth-d02-contracts.md), [staff login и доступ](../../../../technical/first-session/backend-auth-contracts-addendum.md).

HTML v21 и октябрьские экраны с заявками, общим внешним восстановлением и несколькими активными входами — исторические учебные примеры. Актуальные состояния открываются по штатным путям выше. 44 технических кадра доступны через один пункт «Учебная проверка сценариев» и исключены из продуктовой карты. Текущую проверку и её пределы см. в [свидетельствах](verification.md).
