## Работа сотрудника

Таблица показывает тему/ID и автора при наличии контекста, категорию, статус, ответственного, дату и связь с поддержкой. Поиск, категория, статус, ответственный и период работают совместно. В HTML есть произвольный поиск, календарь и сортировка; в Figma — подготовленные значения. Все три учебных отзыва помещаются в выборку; пагинация не изображается без необходимости.

В карточке исходный текст отделён от обработки. Оригинал, язык, источник и переданный контекст неизменны. Английский отзыв остаётся английским в русском интерфейсе. Категория, статус и ответственный сохраняются отдельной кнопкой; выбор в поле ещё не меняет запись. Внутренняя заметка доступна только назначению с правом обработки и не отправляется пользователю.

«Разобрано» означает завершение обработки отзыва. Это не обещание исправления продукта, не успешная торговая операция и не закрытие обращения. Нет рейтинга пользователя или автоматического решения по его деньгам.

## Связь с поддержкой

- FB-101 / Demo Noor / Polymarket / S-DEMO-002 можно связать с существующим T-101 после выбора и подтверждения. Сохраняется одна связь; повтор не создаёт дубликат.
- FB-102 / Demo Robin / Limitless / S-DEMO-005 уже связан с T-102. Обращение и отзыв открываются друг из друга.
- FB-103 получен без пользователя, площадки и сессии. Эти данные не угадываются. Подбор обращения по похожей теме недоступен.

Связывание не создаёт новый тикет, не отправляет сообщение и не меняет статусы. Ответ пользователю отправляют в существующей переписке поддержки с её отдельными проверками доставки. Переходы к пользователю/сессии и обратно сохраняют текущего сотрудника; назначение ответственного не меняет вошедшую учётную запись.

## Доступ и контекст

Использованы прежние семь учебных назначений: владельцы A/B, руководитель операций и операции/поддержка читают и обрабатывают три отзыва. Аудитор читает без внутренних заметок и изменений. DEMO-R1 читает только отзыв Demo Noor; маркетинг не получает пользовательский контекст. Это конкретные демонстрационные права, а не новая неизменяемая матрица ролей. В продукте проверяются отдельные `feedback.view/manage`, права на обращение и области обеих записей при каждом действии.

RU/EN меняется в личном профиле; возврат сохраняет открытый отзыв, фильтры, черновики и связи. Новый учебный вход и перезагрузка начинают заново. Локальные данные живут только в памяти вкладки; Figma использует переменные сеанса прототипа.

## Конфликт и история

HTML сохраняет автора/STAFF-ID, время действия, версию и прежние/новые значения обработки. Устаревшая версия не перезаписывает запись. Учебный переключатель имитирует изменение версии другим сотрудником; черновик заметки сохраняется. Перед повторной правкой сотрудник отменяет устаревшие изменения и видит актуальные значения.

В Figma показаны подготовленный конфликт и последнее событие с автором, а не полноценный конкурентный серверный журнал. Внутреннюю заметку можно выбрать из примера; свободный ввод и несколько записей доступны локально. Подготовленная заметка в Figma не является новым сообщением при каждом повторном нажатии.

## Источники и границы

Правила взяты из [ADR-0011](../../../../decisions/0011_shadow_controls_rating_admin_and_ui_foundation.md), [ADR-0029](../../../../decisions/0029_configurable_admin_roles_and_unified_operations.md), [ADR-0036](../../../../decisions/0036_support_queue_and_conversation_first_release.md), уточнения ADM-11 в [брифе 118](../../../../118_admin_console_figma_design_brief_2026-10-09.md) и [спецификации 115](../../../../115_admin_console_technical_specification_2026-10-09.md). Старые макеты не восстанавливались. Композиция продолжает действующие таблицу и карточку поддержки, UI kit и 12-колоночную сетку; новое визуальное направление не выбиралось.

Не входят: создание нового обращения из отзыва, объединение/удаление оригиналов, связь с ещё не пересобранным инцидентом, массовые операции, SLA, вложения, реальная доставка и серверная авторизация. Полный технический режим должен блокировать обычные продуктовые изменения; его связанный рабочий экран и серверное применение остаются отдельным пакетом. Это дизайн-прототип, не подтверждение работающего backend.

Следующий пакет этапа 3 — инциденты, затем денежная сверка и оставшиеся торговые состояния. Приёмка композиции владельцем и общая приёмка админки открыты.
