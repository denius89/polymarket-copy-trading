## Замечания

### INC-FR-01 · P2 · Поиск не находит пользователя по его ID

Место: `prototype/incidents.js:18`, подпись поля в строке 20.

При роли `lead` запрос `U-DEMO-009` возвращает пустой список, хотя INC-102 связан именно с этим пользователем. Поиск сравнивает `id`, `name`, `title`, `sid`, но пропускает `uid`. Сотрудник копирует ID из карточки/поддержки и получает ложное отсутствие инцидентов. Подпись «по пользователю или ID» не объясняет ограничение.

Исправление: включить `uid` в индекс; целесообразно включить также связанный `ticket`, чтобы скопированный T-103 работал предсказуемо. Добавить проверки точного ID пользователя и отображение его рядом с именем в таблице, если поиск по ID поддержан.

### INC-FR-02 · P2 · Переход из инцидента стирает черновик обработки обращения

Место: `prototype/incidents.js:25`, ветка `a === 'ticket'`.

Воспроизведение: в T-103 выбрать новый статус и ответственного, не нажимая сохранение; открыть INC-102 через ссылку в обращении; вернуться кнопкой «Обращение T-103». `support.statusDraft` и `support.assigneeDraft` безусловно становятся `null`, хотя открывается то же обращение. Текст ответа сохраняется, но два других рабочих изменения теряются без предупреждения.

Исправление: хранить черновик обработки на записи обращения либо хотя бы не сбрасывать его при открытии уже выбранного `support.id`. При смене записи не переносить чужой черновик. Проверить цикл T-103 → INC-102 → T-103 и переключение RU/EN в середине цикла.

### INC-FR-03 · P2 · Возврат к инциденту остаётся на карточке другого пользователя

Место: `prototype/app.js:48` (`return-users`), `prototype/app.js:40` (показ обратной ссылки), `prototype/incidents.js:25` (установка `returnContext`).

Воспроизведение: INC-102 → «Открыть пользователя» → «К пользователям» → Demo Atlas. Получено `{route:'user', userId:'U-DEMO-001', incidentId:'INC-102', returnContext:true}`. На чужой карточке сохраняется «Вернуться к инциденту», связанный с Demo Orion. Основное меню очищает флаг, но кнопка возврата в список обходит этот сброс.

Исправление: завершать связанный контекст при возврате в общий список и проверять соответствие uid/sid перед показом ссылки. Добавить цикл через общий список и другого пользователя; аналогично проверить сессии. Не сбрасывать контекст при переходе в личный профиль для смены языка.

### INC-FR-04 · P2 · После отмены проверки теряется клавиатурная позиция

Место: `prototype/incidents.js:25`, `:31`, `:33`.

Открытие использует нативный `dialog.showModal()` и переводит фокус в причину — это хорошо. Однако отмена, Escape и успешное подтверждение полностью заменяют разметку через `render()`. Исходная кнопка уничтожается, а новая не получает фокус. Нативное восстановление не может вернуть фокус на удалённый элемент. В отличие от профиля здесь нет сохранения логического триггера и восстановления после перерисовки. Это вывод по коду; фактический `activeElement` необходимо подтвердить браузером.

Исправление: сохранить селектор/логическое действие, после отмены и Escape фокусировать новую кнопку «Проверить закрытие» / «Возобновить разбор»; после успешного изменения — текущий заголовок/статус или доступное следующее действие. Проверить клавиатурой: открыть → Tab/Shift+Tab внутри диалога → Escape → фокус вернулся на триггер.
