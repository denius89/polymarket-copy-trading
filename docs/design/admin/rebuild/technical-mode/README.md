# Технический режим и проверка остановки

26.10.2026. Базовый commit: `bc6a3f9c4b048ff8d45811f706b8b8199c1c376e`.

Продолжение управления по текущему плану. Основания: ADR-0043 (один уполномоченный включает ограничение; независимое восстановление), ADR-0045 (полное отключение выбранной среды), ADR-0047 (отдельное разрешение восстановительного маршрута и перевода).

[Публичный прототип](https://shadow-admin-demo.denisfedko.chatgpt.site) · [Вход Figma](https://www.figma.com/proto/lxPP2um7FvIbt02K8eeH4T?node-id=3990-108&starting-point-node-id=3990-108&scaling=scale-down).

## Маршрут

1. Войти владельцем или руководителем операций. На сайте: «Управление → Технический режим». В Figma: «Аварийное восстановление → Технический режим».
2. Указать причину, проверить последствия для всей среды Paper Alpha / Polymarket + Limitless, пройти учебную проверку личности и включить режим. Второй сотрудник не задерживает усиление ограничения.
3. Команда принята — ещё не подтверждение остановки. Нажать «Проверить отключение сервиса». Учебный ответ по умолчанию теперь подтверждает остановку всех трёх групп; основной маршрут не требует искать выбор ответа.
4. Другие ответы доступны отдельно в «Демо: другие ответы системы». Выбор сам ничего не применяет: вернуться и проверить исходную команду. Неизвестный результат не разрешает повторную отправку.
5. После подтверждения всех компонентов нажать «Выключить технический режим». Указать основание и получить проверку готовности. Одна точная область/версия, свежие проверки, два разных сотрудника — владелец и другой уполномоченный. В текущих учебных назначениях это два владельца. При передаче сотрудник явно выходит, следующий входит самостоятельно. Режим остаётся включённым до подтверждённого применения восстановления.
6. После подтверждённого снятия вернуться к техническому режиму. Неизвестный результат восстановления сохраняет ограничение. Старые заявки не запускаются заново.

## Роли и границы

- Оба владельца и руководитель операций включают ограничение при действующем праве `emergency.activate` на всю среду/обе площадки. Просмотр доступен также операциям и аудитору; маркетинг и ограниченное назначение не получают аварийные функции.
- Изменение причины или назначения отменяет подготовленное подтверждение. Смена языка не меняет введённый текст, роль, команду или запрос восстановления.
- На сайте включение закрывает обычную навигацию; остаются инциденты, безопасная сверка, восстановление, журнал этого примера и свой профиль для языка/сеансов. Это поведение учебного интерфейса, не серверная защита.
- Сверка ничего не отправляет. Уже отправленные сделки/переводы могут завершиться. Прямые операции вне Shadow не блокируются.
- После подтверждённой частичной остановки поздний ответ об отказе не снимает ограничение. Новый цикл включения получает новую команду и не использует старое восстановление.
- Полное восстановительное пополнение, остальные точечные области ограничений, компрометация владельца и защищённое восстановление личности остаются отдельной работой. Общая приёмка админки не закрыта.

## Реализация и доказательства

Сайт хранит учебное состояние в памяти вкладки. Нет запросов к площадкам, настоящих ключей, серверных запретов, уведомлений и денежных действий. Перезагрузка сбрасывает пример. В Figma — редактируемые слои, действующие компоненты/токены и подготовленные варианты причины/ответов; свободный ввод и подробный журнал доступны на сайте. Глобальная блокировка всех исторических переходов Figma этим пакетом не утверждается: проверяется новый маршрут и его связь с восстановлением.

Текущая доработка понятности: [clarity-verification.md](clarity-verification.md). Первоначальная проверка: [verification.md](verification.md). Исходники построения описывают изменения, а не являются резервной копией Figma.
