# Сохранение визуальной системы — технический режим

26.10.2026. Режим Impeccable: **Operate**. Это описание ограниченного расширения действующей админки; глобальные `DESIGN.md`, `PRODUCT.md` и настройки навыков не изменялись.

Проверены [направление](brief.md), [границы сценария](README.md), [реализация](../prototype/technical-mode.js), [общие стили](../prototype/style.css) и сохранённые снимки [RU](evidence/local-desktop-ru.png), [EN](evidence/local-mobile-en.png). Выводы ниже относятся к локальному артефакту. Публикация и ручная проверка Figma этим разбором не подтверждаются.

## Что сохранено

- **Палитра:** фон `--bg`, панели `--surface`, границы `--line`, основной и приглушённый текст `--text`/`--muted`. Фиолетовые `--accent` и `--selected` продолжают обслуживать действия и выделение. Новый набор цветов не введён.
- **Типографика:** действующий стек Inter с системными резервными шрифтами; основной текст 14 px, заголовок страницы 28/36 px, заголовки секций 18 px, пояснения 12 px. Это значения CSS, а не доказательство загрузки конкретного шрифта на каждом устройстве.
- **Компоновка:** общий каркас с боковой навигацией и рабочей областью; внутри — основной контекст и колонка действий через существующий `support-layout`. При ширине до 1050 px содержание становится одноколоночным, до 640 px контекстные панели также идут последовательно. Список последствий перестраивается в вертикальные пары до 600 px.
- **Поверхности:** прежние панели с тонкой границей и скруглением; новое оформление теней, декоративных иллюстраций или графиков не добавлено. У этого сценария нет временного ряда, который требовал бы графика.
- **Управление:** общие кнопки, поле причины с подписью, штатный список учебных ответов, раскрываемые пояснения и журнал. Состояние недоступности действия задаётся настоящим `disabled`; фокус и переносы наследуются от существующей системы.

## Новые сочетания существующих элементов

**Намерение и факт остановки разделены.** До команды список описывает будущие последствия. После команды та же область показывает подтверждение каждой из трёх групп: приложение/API, новые торговые и денежные действия, продуктовые фоновые задания. Текст статуса явно различает принятие команды, частичную остановку и неизвестный результат.

**Действие раскрывается по шагам.** Причина → проверка последствий → учебная проверка личности → включение. Кнопка включения недоступна до требуемой проверки. После отправки вместо новой команды предлагается проверка прежней.

**Аварийная навигация связана с состоянием.** В локальном примере обычное меню заменяется допустимыми аварийными маршрутами. Профиль остаётся доступен для личного контекста; это не смена сотрудника или повышение его прав.

**Восстановление использует уже существующий маршрут.** Подготовка доступна после подтверждения остановки; восстановление связано с исходной командой. Новый цикл включения не должен наследовать подтверждения прошлого цикла. Эти правила принадлежат этому сценарию, а не становятся новыми общими правилами оформления всей админки.

## Пределы и неканонизированные наблюдения

После повторного сохранения проверены окончательные снимки по тем же путям: RU показывает десктоп с боковым меню и двумя колонками, EN — прямую узкую страницу с мобильным меню и последовательными блоками, без рамки iframe. По записи основного прохода ширина окна составляет 1280 px и 390 px соответственно; полностраничные снимки не ограничены высотой окна. Точные размеры и пределы проверки остальных состояний фиксируются отдельно в QA.

Расстояния между соседними кнопками и нижними панелями оцениваются по окончательному рендеру; случайное сближение элементов не закрепляется как правило UI kit. Фиолетовая информационная полоса используется и для статуса «Выключен»: её цвет не следует трактовать как подтверждение остановки или безопасности. Смысл задаёт явная формулировка состояния.

Этот документ не удостоверяет серверную авторизацию, выполнение остановки, работу физического ключа, доставку уведомлений, все роли во всех браузерах либо равенство глобальной навигации HTML и Figma. Ограничения учебного состояния и незавершённые сценарии сохраняются в README и итоговой проверке пакета.
