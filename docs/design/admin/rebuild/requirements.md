## Роли: задачи, информация и границы

Ниже — назначение пресетов, не автоматическая выдача каждого перечисленного действия. Перед показом действия проверяется фактическое разрешение, область и срок назначения.

| Контекст | Основные задачи | Нужные данные | Разрешённые действия и ограничения |
| --- | --- | --- | --- |
| Два владельца | Управление продуктом, финансами, доступом и критическими решениями | Общая сводка и детали в рамках продукта | Два отдельных личных аккаунта одной системной роли; индивидуальный журнал. Двойное подтверждение только в оговорённых случаях |
| Руководитель операций | Приоритеты, инциденты, координация сотрудников | Очередь проблем, сессии, обращения, подключения | Дополнительное управление инцидентами/назначениями по разрешениям; не получает права владельца из названия пресета |
| Операции и поддержка | Найти пользователя, разобрать сессию/обращение, сверить результат | Минимально необходимый пользовательский контекст, торговые события, обращения | Поддержка и операции объединены; нет сделок за пользователя, чужих ключей и повторной отправки неизвестной операции |
| Маркетолог | Тексты, переводы, объявления, аудитории и кампании | Контент, согласия, агрегированная аналитика | Просмотр/редактирование/публикация/запуск отдельно. Нет обязательного согласования владельцем при выданном праве. Точные балансы, PnL, содержание обращений и security-инциденты не становятся фильтрами рекламной аудитории |
| Аудитор | Проверка действий и результатов | Разрешённые журналы и данные | Просмотр; экспорт и финансовые сведения выдаются отдельно |
| Кастомная роль | Задачи по выбранному набору прав | Только разрешённые данные | Явные действия, площадка, среда, раздел и срок; нет самоповышения или обхода действий только для владельца |

У каждого сотрудника свой профиль, язык, защита и свои сеансы. Управление собственной учётной записью не выдаёт дополнительные продуктовые полномочия. Роли не переключаются автоматически при переходе по ссылке.

## Обязательные продуктовые границы

- Демо-торговля предусмотрена для обеих площадок. Exness не входит в план. Демо-балансы виртуальные, реальные деньги не суммируются с ними. Реальный режим имеет отдельный допуск по площадке, не включается дизайном переключателя.
- Paper Alpha: комиссия Shadow 0%; 1% допустим лишь как явно неактивный пример будущей платной версии. Партнёрский VIP и пользовательский VIP — разные условия.
- Новые реквизиты партнёра: второй владелец и затем 24 часа ожидания. Обычная выплата — один владелец; превышение защитного порога — два; жёсткий запрет не обходится вторым подтверждением. Полный адрес доступен для зрительной проверки.
- У владельца основной и запасной физические ключи проверяются отдельно. Восстановление не возвращает отозванные сеансы/подтверждения. Ключ входа не является ключом кошелька.
- Восстановительное пополнение при полном отключении: сначала два владельца разрешают точный маршрут ограниченного восстановления, затем отдельно подтверждают перевод. Сервис целиком не включается от пополнения.
- Неизвестное не равно нулю/отказу. Уже отправленное может завершиться вне Shadow; отмена и сверка не гарантируют отмену на площадке.

## Исходные вопросы этапа пересборки

Актуальный остаток после v1 — в [условиях допуска](v1-final/backlog.md). Таблица ниже сохраняет исходные вопросы, не является новой очередью рисования.

| Вопрос | Когда и как решаем |
| --- | --- |
| Окончательные названия групп и плотность таблицы | Проверить первый маршрут; не менять продуктовые права ради меню |
| Точные показатели и расчёт PnL для сводки | Определить единицы, источник, период, учёт расходов и реализованный/нереализованный результат до нанесения чисел на график |
| Формат полностью интерактивного прототипа | Этап 1: проверить ввод, фильтр, календарь и сохранение; Figma-симуляцию не объявлять свободным вводом |
| Поля, доступные конкретному сотруднику операций | Сверить назначение и принцип минимального контекста; отсутствие права отличается от отсутствия данных |
| Подтверждённые возможности площадок и численные настройки сборщиков | Предметная проверка перед соответствующим пакетом; не выдумывать API и новые торговые параметры |

Открытые вопросы не мешают подготовить структуру и первый маршрут; зависимые показатели и действия до решения не объявляются принятыми.


27.10.2026 — [Восстановление доступа сотрудников и владельцев](access-recovery/README.md): отдельный вход без рабочих прав, проверка личности → новая защита → проверка исходного результата → новый вход. Замена защиты не снимает блокировки и не возвращает старые сеансы или подтверждения. Неподтверждённая независимая процедура явно остаётся открытой.
