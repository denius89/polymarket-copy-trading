## Как пройти

1. Войти владельцем A. Открыть Noor и нажать «Посмотреть как клиент». «Активность» на сайте / «Исходная заявка» в Figma ведёт к ORD-002. Исполнение не подтверждено, резерв 20 $.
2. Открыть помощь, профиль, сменить язык и вернуться. Должны остаться Noor, S-DEMO-002 и ORD-002. Вернуться в админку: владелец A и прежний рабочий экран сохраняются.
3. В админке открыть поддержку T-101, подготовить и отправить публичный ответ. Внутренняя заметка сохраняется отдельно. Клиентская переписка показывает только отправленный ответ, с тем же T-101-M1; доставка/прочтение не объявляются подтверждёнными без данных.
4. У Robin открыть ORD-005 и выбрать позднее исполнение. На сайте клиентский просмотр использует тот же снимок: 12 $ исполнено, 8 $ в резерве, 32 $ стоимости позиций, 160 $ доступно. Запрос отмены не равен отмене остатка.
5. Подготовить будущие условия VIP нужного пользователя и опубликовать через существующее подтверждение двух владельцев. Открыть его клиентские условия. Черновик не заменяет опубликованную версию; текущая комиссия Paper Alpha всегда 0%.
6. Включить технический режим через существующую учебную процедуру. Клиентский просмотр показывает «Сервис временно недоступен» без продуктовой навигации. После восстановления старые заявки не повторяются, резервы не освобождаются автоматически.

## Данные и права

Сайт и локальный HTML используют один объект состояния в памяти вкладки. Подтверждённое частичное исполнение Robin: 8/12/28; позднее: 12/8/32; окончательная отмена остатка: резерв 0, доступно 168, стоимость 32. Это учётная стоимость, не рыночная оценка и не прибыль. Сверка сохраняет собственное исходное свидетельство и не подменяется переключателем учебного исхода.

Клиентский язык и язык сотрудника независимы. Ссылка `#client/U-DEMO-002/order` указывает на клиентский контекст после разрешённого учебного входа, не выдаёт доступ сама. Просмотр с суммами доступен только назначению с доступом к пользователям и деньгам в его области; ограниченное назначение, маркетинг и аудитор не получают расширенных прав. Публичный клиентский экран не содержит STAFF-ID, заметок, проверок сотрудников и внутренних подтверждений.

## Figma и объём

В административной странице добавлены 30 редактируемых клиентских состояний и два окна выбора языка, общих для RU/EN. Итого 262 корня: 131 desktop + 131 mobile; 168 экранов и 94 окна. [Desktop mapping](figma-desktop.json), [mobile mapping](figma-mobile.json). Компоненты Alert, Rules и Button взяты из принятого клиентского kit. Скриншоты не заменяют слои.

Совместная ветка на одной странице сохраняет переменные сотрудника и клиента при native-переходах Figma. Исходные Final-страницы RU/EN остаются отдельными страницами: переход языка кодирует подготовленное состояние прямой ссылкой на соответствующий кадр. Для проверки изменяемого состояния от действий администратора использовать совместную ветку; переход по ссылке между страницами не является общим серверным сеансом.

Подготовленные Figma-примеры не заменяют весь клиентский продукт. Native-просмотр из карточки ограничен Noor с неизвестным результатом и Robin с частичным/поздним исполнением; другие снимки доступны в HTML, без подмены их подготовленным состоянием. Текст публичного сообщения остаётся исходным при смене языка интерфейса. Сайт поддерживает больше учебных исходов; полный ввод и серверные проверки Figma не выполняет. Реальные интеграции, авторизация, денежные команды и условия запуска G01–G07 не менялись.
