# Контракт понятности настроек финансов

Граница: дизайн, учебные состояния, документация. Источники правил: ADR-0035, ADR-0038, ADR-0046 и ADR-0047. Новых ставок, пределов, ролей, сроков согласий и финансовых правил пакет не вводит.

| Объект | Подтверждение | Эффект |
| --- | --- | --- |
| Обычный тариф Shadow | Один действующий владелец | Новая версия с областью, причиной и временем; только новые начисления |
| Денежная реферальная лестница / партнёрское денежное исключение | Два разных владельца точной версии | Согласия не переносятся на изменённую версию |
| Источник: добавить / изменить / включить повторно / архивировать | Два разных владельца | История, долги, резервы и незавершённые операции не исчезают |
| Экстренно отключить источник | Один владелец | Блокировка новых отправок; не ручной успех старых операций |
| Изменить защитные правила | Другой владелец проверяет точную версию | Незаполненная версия не активируется |
| Обычная полная выплата | Один владелец, если правила допускают | Сумма — весь доступный подтверждённый долг одной площадки |
| Сработал защитный порог | Дополнительный другой владелец | Проверяется вся выплата; дробление не обход |
| Новые реквизиты получателя | Два согласия +24 часа после второго | Не применяется автоматически к любой правке источника |
| Жёсткий предел / полное техническое отключение | Подтверждения не обходят запрет | Для восстановления сначала явно разрешают нужный маршрут |

Paper Alpha: комиссия Shadow 0%, платная версия не активна, реальные отправки выключены. Будущие 1% — пример. USD и внутренний учёт 1 USDT=$1 не являются обещанием внешнего курса. Клиентские средства исключены из реестра собственных источников.

Баланс кошелька, пригодные средства, свободный остаток, долг партнёрам и доход — разные категории. Неизвестные и несвежие данные не заменяются нулём, успешным подключением или неограниченным лимитом. Ожидаемые и несопоставленные средства не становятся доступными от просмотра. Резервы уникальных операций и операционный резерв вычитаются один раз.

Обычные переходы не присваивают сотрудника/роль/права. RU/EN используют одинаковую семантику. Подготовленные примеры другого участника должны оставаться явными отдельными сценариями, а не рабочей сменой личности. Кнопки симулятора, истории, схемы, заполненного примера и возвращения называются по результату перехода. Важные денежные ограничения видны без наведения; подсказка не является единственным носителем правила.
