Переключатель RU/EN ведёт к соответствующему состоянию. Поля и результаты статические; кнопки меняют макет, не выполняют операции. Возврат к исходным спискам показывает исходный демо-пример, а не сохранённое runtime-состояние.

## Что показано

- Health/metadata обеих площадок, устаревшие данные, локальная изоляция выбранного подключения. Изоляция в Shadow отделена от внешнего отзыва ключа; деньги не считаются доступными по одному зелёному health.
- USDT/USD: синтетическое отклонение, ручные пороги и источники, проверка незаполненных настроек. Внутренний учёт остаётся 1 USDT = $1. Рыночное значение в макете — пример, не текущий курс. Боевой резервный источник не подключён.
- Два Owner, единая Operations, кастомная роль «Маркетолог», предпросмотр прав, сохранение шаблона роли и конфликт версии. Owner-only права исключены из кастомных ролей; экспорт отдельный.
- Отзыв admin-сессии и блокировка скомпрометированного сотрудника, без отключения пользовательского копирования по одному отзыву admin-сессии.
- Список журнала, запись AUD-041 и запрет экспорта. Защищённая копия журнала не выдаётся за подтверждённую.
- GLOBAL_STOP: последствия → причина → включение одним уполномоченным сотрудником → неполное применение → подтверждённое применение → проверка Owner A → независимый Owner B → поэтапное восстановление / блокировка. Submitted/unknown остаются на сверке; старая очередь не отправляется автоматически.

TECH_MODE, DEPOSITS_OFF, WITHDRAWALS_OFF и PARTNER_PAYOUTS_OFF показаны отдельными ограничениями. Полный жизненный цикл в этом пакете нарисован только для GLOBAL_STOP. Восстановление отдельного подключения и учётной записи не переиспользует GLOBAL_STOP: их собственные формы ещё предстоят.

## Что ещё требуется по дизайну

1. Вход администратора, отозванная сессия, назначение/изменение/отзыв ролей и восстановление при потере обоих Owner.
2. Собственные формы восстановления подключения и учётной записи; остальные аварийные scope и операции.
3. Успешное сохранение USDT-настроек, недоступность/расхождение источников, доставка предупреждений.
4. Журнал: фильтры, пагинация, разрешённый экспорт и состояния проверки целостности.
5. Поддержка, тексты/языки, объявления внутри приложения; затем сквозная вычитка с коллегой.

Ротация ключей, массовые внешние рассылки, конструктор лендинга, вложения и SLA — позднее. Frontend и live остаются на паузе. Конструкционные скрипты — справочный источник построения, а не точная резервная копия Figma; не запускать повторно поверх существующих экранов.
