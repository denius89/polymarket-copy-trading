# Маркетинг · дизайн-пакет 08

Источник: [115 §15](../../../115_admin_console_technical_specification_2026-10-09.md), [118 ADM-18 / P-07](../../../118_admin_console_figma_design_brief_2026-10-09.md), [ADR-0031](../../../decisions/0031_admin_permissions_and_autonomous_publishing.md), [ADR-0033](../../../decisions/0033_in_app_marketing_first_external_campaigns_later.md).

## Границы
Только объявления внутри приложения. Внешние email/Telegram/push, провайдеры и расходы рассылок — позже. Это редактируемые макеты и статический прототип, не система отправки. Управление численными тарифами, VIP и деньгами сюда не входит.

## Содержание и запуск
Редактор: внутреннее название, назначение сообщения, размещение, RU/EN заголовок и текст, аудитория и период с явным UTC. Текстовый формат, без произвольного HTML и платёжных CTA. Неизменяемая опубликованная версия; черновик не показывается клиенту. Проверяются обязательные переводы, разрешённые ссылки/формат и ограничения выбранного размещения. Конкретные ограничения длины должны прийти от размещения; универсальный лимит не выдуман.

Контрольные состояния: draft → validated → publishing/ scheduled → active → paused / ended. Pending не равен подтверждению, unknown не равен ошибке или успеху. При неизвестном результате повторная публикация заблокирована до проверки статуса. Подтверждённая ошибка сохраняет черновик и требует проверки перед повтором.

Подтверждение публикации — проверка параметров самим сотрудником, а не Owner approval. Автор, время, до/после, версия содержания, аудитории и политики записываются в журнал.

## Права
По 115: marketing.view/edit/segment/test_send/publish/pause/export_aggregate. Проверка среды, площадки и раздела действует независимо от роли. Нет обязательного согласования с Owner.
Просмотр не даёт права редактирования/публикации/паузы; редактор без publication может сохранить черновик. Выбор аудитории требует segment; запуск, планирование и повторный запуск — publish; пауза — pause. Агрегированный экспорт требует отдельного права, персональные выгрузки не входят в V1.
Тестовая ветка макета — локальный просмотр без enqueue, доставок и изменения клиентских счётчиков. Это не внешняя тестовая рассылка и не обходит права сегментирования.
Scheduler повторно проверяет текущие права сотрудника, project controls, назначение/канал, частоту, consent и suppression. Отозванное право блокирует начало показа; восстановление прав не запускает старое задание автоматически.

## Аудитория
AudienceDefinitionVersion задаёт разрешённый сегмент; AudienceSnapshot фиксирует содержание и политику. UI показывает только агрегаты и причины исключения, без контактов, балансов, PnL и текстов обращений.
Неизвестное правило согласия блокирует targeted marketing; отсутствие отказа не означает consent. Неизвестное согласие отдельного клиента исключает его. Поздняя отписка/ограничение проверяется перед enqueue и delivery.
Показанный RU/EN сегмент обеих площадок — учебный пример, не решение о production сегментации. Условие CP-DEMO-2 и frequency FP-1 — фиктивные идентификаторы, не утверждённые численные правила.

## Пауза и версии
Пауза прекращает новые постановки и показы только после подтверждения применения. Ранее увиденная история и факты прочтения остаются. При ошибке паузы последняя подтверждённая версия остаётся active.
Восстановление A-1 создаёт новый черновик A-3. Оно не переписывает A-1/A-2, не возобновляет показы и требует новой проверки аудитории/периода перед publication. В этом прототипе ветка заканчивается сохранением A-3; полная повторная публикация не изображается уже выполненной.

## Сверка с клиентским интерфейсом
| Админка | Клиент |
| --- | --- |
| Draft / validated / scheduled до старта | Объявление ещё не доступно |
| Active и eligible | RU/EN объявление на разрешённом размещении |
| Available | Может открыть; не считается показом/прочтением |
| Display / read | Отдельные подтверждённые события |
| Late suppression | Новая доставка исключена |
| Pause подтверждена / ended | Новые показы прекращены; ранее увиденная история остаётся |
| Unknown / failed | Админка не утверждает, что клиент увидел объявление |
| Внутренний журнал / аудитория | Клиент не видит сотрудников, агрегаты и причины исключений |

Локализованный customer preview является частью admin preview. Общие клиентские прототипы не изменены: окончательное размещение и read/consent controls должны пройти отдельную совместную вычитку при сверке пользовательского интерфейса.

## Передача в разработку
Список узлов, переходы, проверка и превью хранятся рядом. Скрипты сборки — история операций, не backup и не источник runtime-авторизации. Перед реализацией читать актуальную Figma и принятую версию репозитория. Consent purpose bindings, допустимые размещения, frequency policy, TTL снимка, end-of-window и read evidence — подтвердить перед backend; не трактовать демо как production конфигурацию.
