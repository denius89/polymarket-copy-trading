# Limitless: исполнение, realtime и сверка

Дата проверки официальных документов: **2026-10-06**. REST production: `https://api.limitless.exchange`; Socket.IO: `wss://ws.limitless.exchange/markets`, транспорт WebSocket. [OpenAPI](https://docs.limitless.exchange/openapi.json): OpenAPI 3, `info.version: 1.0` — это версия спецификации, не обещание неизменности поведения. EIP-712 domain version `1`. Все возможности ниже **документированы, но не проверены торговым запросом**. Чтение документации/spec выполнено; credentials, approvals, сделки и подключения к приватному stream не создавались. Партнёрские операции дополнительно **требуют партнёрского доступа**. SDK пакет в этом исследовании не устанавливался; фиксировать фактически выбранную версию перед реализацией.

## Routing, сеть и precision

Для CLOB получить точный рынок, token IDs и `venue` через `GET /markets/{slug}`. `venue.exchange` — EIP-712 verifying contract. Venue документирован как постоянный для данного рынка и допускает кэширование. BUY требует USDC approval exchange; SELL simple — CTF approval exchange; SELL NegRisk — approval exchange **и** adapter. Для AMM/FPMM использовать отдельные `/amm/*`; универсальный endpoint, автоматически маршрутизирующий CLOB/AMM, не документирован. Решение по типу рынка берётся из market metadata; не маршрутизировать только по наличию slug. [Venue](https://docs.limitless.exchange/developers/venue-system), [AMM](https://docs.limitless.exchange/developers/amm-trading).

Base mainnet, chain ID `8453`; официальные docs говорят, что sandbox/testnet/mock deployment отсутствует. Следовательно paper trading — собственная симуляция проекта, а не тестовый режим площадки. Native USDC Base: `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`; CTF ERC-1155: `0xC9c98965297Bc527861c898329Ee280632B76e18`. Для on-chain аналитики docs требуют учитывать три активные версии venues; выбирать verifying contract из рынка, не из одной глобальной константы. [Introduction](https://docs.limitless.exchange/developers/introduction), [Smart contracts](https://docs.limitless.exchange/user-guide/smart-contracts).

CLOB: USDC и shares имеют 6 decimals. `makerAmount`/`takerAmount` — integer raw units; makerAmount floor `100` raw units (это API dust floor, не минимум web UI). Для GTC/FAK цена `[0.01, 0.99]`, до трёх десятичных знаков; collateral equation должна быть точной, без округления. BUY maker=price×contracts, taker=contracts; SELL наоборот. FAK makerAmount является hard spend cap, takerAmount — защищённым minimum output, поэтому это не обычная гарантия точного количества shares. FOK price отсутствует, takerAmount=`1`, makerAmount — максимальный collateral BUY / shares SELL. `nonce=0`, expiration отсутствует либо `0`; GTD/ненулевое expiration не поддерживаются. `postOnly` только GTC. [Create order](https://docs.limitless.exchange/api-reference/trading/create-order), [Signing](https://docs.limitless.exchange/developers/eip712-signing).

Хранить исходные JSON/raw integer strings и нормализованные Decimal/BigInt, не JS floating point. У WS единицы различаются: book size raw 1e6; OME lifecycle remainingSize JSON number в shares; OME EXECUTION remainingSize string raw 1e6; SETTLEMENT amountContracts/amountCollateral decimal strings в человеческих единицах. Не использовать общий parser без discriminator. [Market data](https://docs.limitless.exchange/developers/websocket/market-data), [Order events](https://docs.limitless.exchange/developers/websocket/order-events).

## Матрица CLOB endpoints

Все paths относительно REST base; нет pagination у mutations. Auth — scoped HMAC. Создание/отмена требуют `trading`; чтение собственных заявок — HMAC без специального scope. Partner REST read: header `x-on-behalf-of`, требует `delegated_signing` и принадлежность sub-account. Cancel query `onBehalfOf` также требует `trading`+`delegated_signing`. Create client-signed partner order допускает `trading` + owned target; unsigned server signing дополнительно `delegated_signing`.

## Lifecycle и ошибки

`201` означает принятие заявки, а не финальное списание. `execution.settlementStatus`: UNMATCHED, MATCHED, MINED, CONFIRMED, RETRYING, FAILED, DELAYED, CANCELED. Matching и settlement учитывать раздельно; MATCHED provisional, FAILED означает отсутствие выполненного trade. GTC partial remainder может остаться в книге и заполниться позже. FAK terminal FILLED/PARTIALLY_FILLED/KILLED, остаток killed; FOK full-or-reject, 400 при rejection, может также появиться KILLED event, никогда PARTIALLY_FILLED. Не считать `UNMATCHED` доказательством open: zero-fill FAK terminal KILLED в historical status выглядит UNMATCHED. [Create](https://docs.limitless.exchange/api-reference/trading/create-order), [Events](https://docs.limitless.exchange/developers/websocket/order-events).

Некоторые рынки имеют `settings.takerDelayMs`. FAK/FOK удерживаются, GTC — только если пересекает книгу; postOnly не удерживается. DELAYED имеет eligibleAt и нулевые totalsRaw, до release заявка не в книге и не emits order/book events. До eligibleAt можно отменить; race при release возвращает 409/ORDER_RELEASE_IN_PROGRESS. Maintenance может отложить fill за eligibleAt: не закрывать по таймеру. [Create](https://docs.limitless.exchange/api-reference/trading/create-order).

clientOrderId≤128, trim/nonblank, уникальный; повтор **409, без replay ответа**. Сохранять его до submit; после timeout сначала lookup by client ID. `UNKNOWN` — inconclusive, не known failure: reconcile оба ID cancel-replace, не отправлять новую replacement вслепую. STOP_ON_FAILURE suppresses replacement только при неуспешной отмене; ALLOW_FAILURE может создать новую заявку при живой старой. Даже cancel SUCCESS + replacement FAILURE допустимо; даже replacement SUCCESS может содержать nested execution FAILED. [Cancel replace](https://docs.limitless.exchange/api-reference/trading/cancel-replace), [Batch](https://docs.limitless.exchange/api-reference/trading/cancel-replace-batch).

STP default cancel_maker; cancel_taker/cancel_both отклоняют incoming order; placement response CANCELED + STP_TAKER_REJECTED. Default может отменить собственные conflicting makers; `stpMakerCancels` только placement, OME cancellation reason STP_MAKER_CANCELLED. Historical status не сохраняет CANCELED/STP reasons; user-orders CANCELED сохраняет cancel state. recvWindow≤10000ms, timestamp Unix ms top-level; stale/future 425 требует fresh order; maintenance 425 с trading-mode code требует refresh availability. [Create](https://docs.limitless.exchange/api-reference/trading/create-order).

Maintenance: normal; post_only (postOnly GTC и cancel); cancel_only (cancel); disabled (ни create, ни cancel). Читать GET /maintenance/status startup/before actions и учитывать response как более свежий. Scheduled notice не означает enforced active state. Heartbeat не заменяет kill switch/REST сверку, партнёрский token не может выставить его для subaccount. [Maintenance](https://docs.limitless.exchange/developers/maintenance-mode), [Heartbeat](https://docs.limitless.exchange/api-reference/trading/heartbeats).

## WebSocket и reconnect

Socket.IO namespace `/markets`, WebSocket only. Authenticated handshake HMAC canonical message: ISO timestamp + newline + GET + newline + `/socket.io/?EIO=4&transport=websocket` + newline (empty body), token headers lmts-api-key/lmts-timestamp/lmts-signature. Fresh headers на каждом reconnect; authenticated subscribe в течение 30 sec handshake. Через 24h load balancer закрывает connection (1006); resubscribe обязателен, subscription server не сохраняет. Socket.IO ping/pong автоматический, клиентский самодельный PING не нужен. `system` subscription ack; `exception` auth errors. [Overview](https://docs.limitless.exchange/developers/websocket/overview).

`subscribe_order_events` без payload охватывает **только owning profile handshake**, все его рынки, maker/taker. Делегированные заказы owned sub-account, не попадают в partner stream; никакого WS onBehalfOf нет. Требуется REST status/user-orders с delegated header либо отдельная auth самого sub-account. Это не stream лидера/всех трейдеров. Документированный public stream всех market trades отсутствует. [Events](https://docs.limitless.exchange/developers/websocket/order-events), [Market data](https://docs.limitless.exchange/developers/websocket/market-data).

orderEvent discriminator source→type: OME PLACEMENT/UPDATE/CANCELLATION — resting lifecycle; OME EXECUTION — terminal FAK/FOK. SETTLEMENT MATCHED→MINED/FAILED, correlate tradeEventId+orderId; MATCHED не содержит clientOrderId; eventId namespaces отличаются. Между OME и SETTLEMENT ordering не гарантирован. Taker arrival fill агрегирован в одну tradeEventId независимо от числа makers; GTC later fills имеют другие trade IDs. semantic occurredAt/matchedAt/publishedAt раздельно, отсутствующий semantic time null; legacy timestamp не подставлять вместо них. Server dedup window 60 sec не является гарантией replay/durable recovery. [Events](https://docs.limitless.exchange/developers/websocket/order-events).

Рекомендация адаптеру (не контракт площадки): persist IDs, raw frames, ingestion time, latest states; при disconnect маркировать данные stale, fresh HMAC reconnect+subscriptions, REST reconcile tracked order IDs, per-market LIVE/CANCELED/MATCHED/UNMATCHED orders, positions/history. Для partner subaccounts REST — основной путь order reconciliation. Status-batch не возвращает historical CANCELED; сверять user-orders и собственный журнал отмен. У book WS full snapshots, coalesced updates; заменять книгу, не diff для извлечения trades. version растёт в рамках publisher, может restart после failover; fallback snapshot version 0 принимается лишь до первого live frame. Initial snapshot после subscribe, missing expected slug — REST fallback. [Status](https://docs.limitless.exchange/api-reference/trading/order-status-batch), [User orders](https://docs.limitless.exchange/api-reference/trading/user-orders), [Market data](https://docs.limitless.exchange/developers/websocket/market-data).

## AMM partner endpoints

HMAC `trading`+`delegated_signing`; owned Privy server-wallet profile; legacy keys/EOA subaccounts не поддерживаются. Optional body onBehalfOf. Positive integer string amounts в collateral units; USDC 6 decimals. Нет pagination.

| Метод/path | Вход | Ответ/ошибки |
|---|---|---|
| POST /amm/allowances/check | market slug/checksummed FPMM address, side BUY/SELL | 200 status confirmed/missing, confirmed bool, wallet/token/spender fields; BUY currentAllowance, SELL operator approval |
| POST /amm/allowances/approve | same body | 200 already confirmed либо 202 submitted + transactionId/userOperationHash; асинхронно сверять check |
| POST /amm/buy | market,outcomeIndex 0 YES/1 NO,collateralAmount,idempotencyKey; optional slippageBps default100 max1000,onBehalfOf | 201 SUBMITTED + expectedShares/minShares, transactionId/userOperationHash, optional txHash |
| POST /amm/sell | market,outcomeIndex,collateralReturnAmount,idempotencyKey; optional slippageBps/onBehalfOf | **Exact collateral output**, expectedShares/maxShares; это не sell exact shares. 201 SUBMITTED |

[Все AMM поля, результаты и ограничения](https://docs.limitless.exchange/developers/amm-trading), [OpenAPI](https://docs.limitless.exchange/openapi.json). Ошибки docs: 400 invalid,403 scope/legacy/wallet/target,409 closed/key conflict,422 balance/quote too small,429 rate,502 chain/quote/Privy,503 approval/trading unavailable. Документированный rate shared 10 requests/10sec per caller; 429 retryAfterSeconds; bucket token/actor profile/wallet whichever available. idempotencyKey ≤128 nonblank, scoped target profile, retained 24h; same parameters replay result, different→409. After 24h не считать replay guaranteed. CLOB clientOrderId и AMM idempotencyKey имеют разные semantics. Конкретный REST endpoint статуса transactionId/userOperationHash для AMM в прочитанном разделе не назван; выяснить у партнёра. SUBMITTED не считать mined. Не обещать AMM events через CLOB orderEvent.

## Fees, quota и открытые вопросы

Документировано: taker-only CLOB, maker realized fee zero; BUY charge contracts, SELL USDC; AMM обычно 0.40% (исключения для рынков). CLOB dynamic representative range BUY 0.40–3.00%, SELL 0.42–1.50%; closed-form curve не опубликована. `feeRateBps` — configured signing rate, `effectiveFeeBps` фактическая execution rate; totalsRaw/terminal MINED — reconciliation. На maker provisional event может быть ненулевая informational estimate, не учитывать как списание. Не вычислять exact fees интерполяцией таблицы. [Fees](https://docs.limitless.exchange/user-guide/fees), [Events](https://docs.limitless.exchange/developers/websocket/order-events).

Числовая общая quota CLOB/REST/WS в прочитанных источниках не найдена; не переносить AMM 10/10 на все endpoints. SDK retry docs рекомендуют respect Retry-After/backoff и позволяют raw response inspection, но generic retry helper не доказывает безопасность повторного submit после unknown outcome. [SDK error handling](https://docs.limitless.exchange/developers/sdk/typescript/error-handling).

Вопросы перед live copy: partner quotas; order retention/replay после disconnect; delegated WS roadmap и отдельная subaccount auth; cancel race/failure rollback semantics; unknown resolution SLA; heartbeat delegation; AMM completion read; runtime market schema routing fields; supported future collateral/network changes; fee quoting для paper точности. Эти ответы здесь **не проверены**, возможности сверх опубликованного контракта не обещаются.

## Fee signing и безопасное отображение ошибок

На fee-enabled рынке signed `feeRateBps` должен равняться текущему `effectiveFeeRateBps` **владельца заявки**, а не только `rank.feeRateBps`. Fee-disabled рынок подписывается с0. `effectiveFeeRateBps=null` не позволяет придумать ставку. Несовпадение даёт400 с `code=FEE_RATE_MISMATCH` и `expectedFeeRateBps`: пересобрать/переподписать только после проверки известного отказа; изменение JSON уже подписанного order недопустимо. Partner не читает private child profile через owner endpoint: для signed child flow rate берётся из mismatch response; unsigned delegated flow подписывается server-side. Источник: [Changelog 23.09](https://docs.limitless.exchange/changelog), [Private profile](https://docs.limitless.exchange/api-reference/portfolio/get-profile). Runtime здесь U/P.

| Наблюдение | Отображение в документ23 / действие |
|---|---|
| Auth401 / scope403 | CREDENTIAL_INVALID / PERMISSION_MISSING; запрет новой команды, refresh разрешений, без tight retry |
| `FEE_RATE_MISMATCH` | FEE_UNRESOLVED / AFTER_REFRESH; известный отказ не считать fill |
| HTTP409 reuse clientOrderId | CLIENT_ORDER_ID_CONFLICT / AFTER_RECONCILIATION; lookup, не новый случайный ID |
| HTTP409 cancel-release race | CANCEL_UNKNOWN либо pending по доказанному payload; REST сверка old order, возможные fills сохранить |
| Maintenance425 | Соответствующий MAINTENANCE_* code; refresh operational snapshot, не обходить mode |
| Freshness425 | EVENT_STALE/known validation failure по payload; не смешивать с maintenance |
| HTTP429 | RATE_LIMITED, respect endpoint Retry-After/retryAfterSeconds; безопасные reads backoff, mutations только после проверки результата |
| Timeout/connection lost5xx | SUBMISSION_UNKNOWN/CANCEL_UNKNOWN, AFTER_RECONCILIATION; отсутствие ответа не доказанный отказ |
| OME partial + successful cancel remainder | CANCELLED с сохранёнными confirmed fills; provisional MATCHED отдельно |
| REST UNMATCHED | Не однозначно OPEN: возможен zero-fill terminal FAK. Нужен orderType, historical/terminal evidence |
| Новый raw status/error | UNKNOWN / blocking reconciliation finding, raw сохранить |

Это рекомендация сопоставления с текущим core contract, а не новые бизнес-правила или список guaranteed platform error codes. Платформенный state и settlement state хранить раздельно; mapping проверяется fixtures и партнёрским spike.
