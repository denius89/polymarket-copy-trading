# Limitless: публичные данные, история, PnL, discovery и referral

Дата проверки: **2026-10-06**. Статус всех контрактов ниже — **документировано**, кроме явно отмеченных попыток GET. Источники: официальные markdown-страницы и [OpenAPI](https://docs.limitless.exchange/openapi.json), `info.version=1.0`, production REST `https://api.limitless.exchange`. Это версия документа спецификации; она не подтверждает номер развернутого backend. Более новые специализированные страницы иногда подробнее/новее общего OpenAPI: расхождения приведены отдельно.

### Семантика истории и данных лидера

Public history предназначен для чужого адреса; private `/portfolio/history` — для собственного authenticated профиля, delegated read требует поддерживаемой partner delegation. Public адрес не дает право читать его ордера, управлять ими или подключиться к приватному order stream. `GET /markets/{slug}/user-orders` — собственный effective profile, а не public endpoint произвольного лидера. [Own orders](https://docs.limitless.exchange/api-reference/trading/user-orders), [Private history](https://docs.limitless.exchange/api-reference/portfolio/history).

HistoryEntryDto содержит blockTimestamp, market, collateralAmount/outcomeTokenAmount/outcomeTokenAmounts, outcomeIndex, outcomeTokenPrice, strategy. Возможны tradeEventId/orderId/makerMatchId/transactionHash; не все обязательны. Стратегии включают Buy/Sell/Limit Buy/Limit Sell/Market Buy/Market Sell/Split/Merge/Convert. Поэтому запись истории нельзя автоматически трактовать как новый executable BUY/SELL. Определить нормализацию fill и fallback dedup только после проверки фактического ответа. Разделять tradeEventId, orderId и makerMatchId: это разные идентификаторы. Источник: [Private history](https://docs.limitless.exchange/api-reference/portfolio/history), [OpenAPI](https://docs.limitless.exchange/openapi.json).

Market events атрибутированы **taker**, если public profile доступен. Они не обещают всех maker-side сделок выбранного трейдера. `makerAmount`/`takerAmount` в этом response сейчас равны collateral cost; `matchedSize` raw 6-decimal token quantity; side 0BUY/1SELL, price weighted average, tokenId taker position, txHash settlement. Использовать для подтверждения finalized активности рынка, не как универсальный сигнал лидера. Источник: [Market events](https://docs.limitless.exchange/api-reference/trading/market-events).

Trading feed включает BOUGHT/SOLD/RESOLVED/PARLAY_PLACED/PARLAY_RESOLVED. `facts` фиксируют event-time значения; market subject гидратируется текущим состоянием на момент чтения. `facts.realizedPnl/averageEntryPrice/roi` на SOLD доступны только когда close-data покрывают fill полностью. Featured первая пустая страница может fallback to all; response effectiveAudience объясняет фактически выданный поток. Feed 24h window, cursor и public history не устанавливают SLA времени доставки, replay на произвольный срок, ровно-однократность или universal leader events. Источник: [Feed](https://docs.limitless.exchange/api-reference/feed/trading-feed).

### PnL и accuracy

Realized-pnl — best-effort projection, а не синхронный ledger всех торговых действий. `windowStart` строится от закрытой UTC 5-minute boundary. Backend группирует categories; unattributed — `other` без slug/path/icon; point breakdown содержит top3 named categories плюс residual Other. Negative raw сохранять signed string/decimal; usd nullable. Текущий prose явно описывает `timeframe=all`: permanent hourly history, categories и breakdown пустые. Global OpenAPI enum all не содержит; это новое расхождение D, actual all response U. Наличие all не доказывает полную lifetime историю с момента создания аккаунта. Не выдавать `current` недельного окна за lifetime PnL. [Realized](https://docs.limitless.exchange/api-reference/public-portfolio/realized-pnl).

Accuracy: resolved won/lost/total/since, не profit/ROI; null означает нет данных, не 0% и не ошибку. Успешные object/null ответы допускают CDN 15s (`max-age=0,s-maxage=15`), errors no-store. Не описаны правила hedged YES+NO, BREAK_EVEN, partial exits и учета нескольких outcomes; уточнить до ранжирования лидеров. [Accuracy](https://docs.limitless.exchange/api-reference/public-portfolio/accuracy).

Public positions `RESOLVED`/winning outcome в API **не гарантируют** on-chain payout уже settled и мгновенный redeem. [Positions](https://docs.limitless.exchange/api-reference/public-portfolio/positions).

Unrealized leaderboards — live projection: READY текущий complete snapshot; STALE/DEGRADED last complete snapshot и no-store; BUILDING empty data и retry shortly. ETag для market page-specific; biggest ETag для metric/marketPageId/limit variant-specific. Не считать empty BUILDING нулевыми позициями. [Market leaderboard](https://docs.limitless.exchange/api-reference/leaderboard/unrealized-pnl-market), [Biggest](https://docs.limitless.exchange/api-reference/leaderboard/biggest-positions).

Public Socket.IO `subscribe_unrealized_pnl` / `unrealizedPnlProjectionChanged` — **invalidation hints**, а не leaderboard payload или событие сделки лидера. Scope MARKET с numeric marketId, либо BIGGEST_POSITIONS; schemaVersion1. После hint refetch matching REST. Max50 MARKET scopes/connection, additional дают UNREALIZED_PNL_SCOPE_LIMIT; biggest не считается. Не проверено соединением. [PnL WebSocket](https://docs.limitless.exchange/developers/websocket/unrealized-pnl).

## Комиссии, география и referral

[Fees](https://docs.limitless.exchange/user-guide/fees), проверено по документу 2026-10-06: AMM flat0.40% с возможными market promotional исключениями; CLOB maker liquidity без fee, taker BUY0.40–3.00% в outcome tokens, SELL0.42–1.50% в USDC. Closed formula curve не опубликована, illustrative points недостаточны для точного simulator. Фактический execution возвращает effectiveFeeBps/usdFee/contractsFee; signed feeRateBps должен совпадать с profile/market (`FEE_RATE_MISMATCH`). Это не обещание zero fee у любой GTC заявки: немедленный matched portion может быть taker. Paper simulator должен явно обозначать approximate fee либо использовать документированные execution values для retrospective analysis.

[ToS](https://docs.limitless.exchange/user-guide/terms-of-service), last updated **2026-09-15**, проверено 2026-10-06: 18+/legal majority, legal capacity, applicable-law eligibility и sanctions checks. Доступ запрещен из Russia, Belarus, Cuba, Iran, North Korea, Syria, Crimea/Donetsk/Luhansk. Trading запрещен для United States of America, **`Republic of China`** (так написано в источнике; не заменять самостоятельно на PRC/Taiwan), Ontario и Alberta. Не найден документированный geo-check endpoint в изученной спецификации. API availability ≠ trading legal eligibility. Также ToS запрещает создавать аккаунт от имени другого человека и несколько accounts; partner subaccounts требуют письменного уточнения contractual разрешений, не переносить self-service условия на partner onboarding автоматически.

[Referral program](https://docs.limitless.exchange/user-guide/referral-program) — **программа площадки Limitless**, отдельная от собственной referral/affiliate программы нашего copy-service. First referrer permanent attribution; earnings только eligible finalized CLOB taker fills; maker fills и Community user-generated markets не accrue. Rate определяется **собственным** maker+taker CLOB volume с запуска программы: Starter$0→10%, Bronze$25k→18%, Silver$250k→25%, Gold$3m→32%, Diamond$20m→40%. Daily tier refresh00:15UTC, pinned partner tier floor может быть выше; применять live ladder API, не hardcode. Pending unresolved conservatively valued, payable после resolution; daily UTC batched USDC payout в trade wallet, minimum$1, остаток переносится. Referral share вычитается до maker rebate pool. Не превращать этот revenue share в обещанную комиссию copy-service.

## Проверки и открытые вопросы

Четыре public GET без auth 2026-10-06T11:18:38Z (`/markets/active?limit=1&page=1`, biggest-positions?limit1, referral leaderboard?limit1, feed/trading?audienceall&limit1) дали HTTP403 с body `error code: 1010`. В этих четырёх первоначальных попытках payload не получен. Использовался Python urllib default User-Agent. Параллельный GET `/markets/active?limit=1&page=1` со стандартными User-Agent curl/8.7.1 и Accept application/json получил 200 (evidence [public-request-evidence.json](public-request-evidence.json)). Поэтому403 не трактовать как отсутствие публичного доступа или обязательность API key; Дополнительные GET с этими headers дали200: biggest positions limit1; exact market details **без include**; orderbook; market events limit1/page1; public account history limit1,positions,realized-pnl timeframe1d,accuracy. Эти результаты подтверждают доступность и top-level shape на одном рынке/публичном адресе; не полную pagination, completeness, все типы рынков или semantics private API. Sanitized evidence хранит keys/counts без адреса/имени лидера; адрес получен из public leaderboard. Первый default-urllib403 — клиентский доступ, не доказательство lack public auth. Evidence: [public-request-evidence.json](public-request-evidence.json) и [verification.md](verification.md). Secret/account/order не создавались.

Расхождения, которые нужно проверять при следующей задаче:

1. Public history prose: limit optional default20 и max100; OpenAPI required=true без min/max; public schema generic, prose same private HistoryResponseDto. В запросе явно передавать limit20 до уточнения.
2. Biggest positions prose: metric=pnl и marketPageId поддержаны; global/embedded OpenAPI показывает только limit. Не считать extra params production-verified.
3. `/markets/{addressOrSlug}` include required в spec, хотя базовый GET в guides встречается без include; GET без include реально дал200 на одном CLOB рынке; required=true в spec расходится с этим наблюдением. До SDK integration уточнить поддерживаемые include значения.
4. Public history реальный200 содержал только data и nextCursor, **totalCount отсутствовал**, хотя private HistoryResponseDto помечает totalCount required. Клиент должен переносить отсутствие totalCount; public schema generic, поэтому не объявлять private schema полным runtime contract. Public history cache observed max-age60/s-maxage60, positions max-age5/s-maxage15, PnL max-age15/s-maxage30, market events30s + SWR30s. Это единичное наблюдение, не SLA; важно для задержек copy signals.
5. Не найдена доказанная гарантия, что public history exhaustive real-time и однозначно связывает все maker fills/AMM/split/merge. Нужны completeness/lag/reorg/dedup/backfill условия от партнера.
6. Accuracy accounting, public PnL retention/coverage/fee inclusion, caching invalidation после изменения history; SLA projection восстановлений.
7. Какие endpoints разрешены API consumers разных географий и какие partner contractual исключения на delegated accounts, exact meaning `Republic of China`.
8. Realized-pnl prose включает timeframe=all, global spec enum только1d/1w/1m. Поддержку all и полноту permanent hourly history проверить отдельно.
9. Разрешена ли referral attribution для partner-created subaccounts, какая есть привязка к реферальной ссылке/партнеру, нет ли отдельного тарифа; не обнаружен write endpoint для такого назначения в приведенном public referral API.

Для paper: discovery/book/history подходят как документированные read primitives; хранить provenance/time/retrieval status, gaps и fee estimation label. Для future copy: публичную историю использовать как наблюдение лидера и сверку, собственный private/delegated order stream — как источник выполнения follower. Кандидаты adapter mapping (требуют сверки с docs/23): listMarkets/getMarket/getOrderbook/getPriceHistory → public market routes; getLeaderActivity → public history с нормализацией/cursor; getLeaderPositions/PnL/Accuracy → public profile routes, не execution signal; own/delegated execution оставить private contracts. Это техническое предложение, не изменение business rules.
