# Авторизация, partner accounts и движение средств Limitless

Дата проверки официальной документации: **2026-10-06**. Статус всех возможностей ниже: **документировано; не проверено authenticated/live запросом**. Партнерские права **требуют разрешения Limitless на аккаунте**; публичное наличие страницы не подтверждает предоставление прав нашему сервису. Accounts, credentials, permissions, ордера и переводы в этом исследовании не создавались. OpenAPI: `3.0.0`, `info.version = 1.0`; это версия описания, не гарантия единой версии каждого маршрута. Примеры ниже — иллюстрации схемы, без реальных учетных данных и фактических ответов.

## 1. Уровни доступа

Публичные market/orderbook/portfolio reads не требуют пользовательской авторизации. Новая programmatic-интеграция использует **scoped API token + HMAC-SHA256**, а не cookie login и не legacy static API key. Собственная торговля доступна self-service с `trading`. Создание счетов других пользователей, managed wallets и delegated signing относятся к Programmatic/Partner API: Limitless сначала включает capabilities на аккаунте платформы. В таблице Programmatic API «Self-service: Yes» означает возможность самостоятельно derive разрешенный scope после его включения, а не безусловный доступ любого пользователя. [Authentication](https://docs.limitless.exchange/developers/authentication), [Programmatic API](https://docs.limitless.exchange/developers/programmatic-api).

| Scope / auth | Документированные полномочия | Граница |
|---|---|---|
| `trading` | Place/cancel orders, server-wallet redeem/split/merge | Для обычной self-signed CLOB заявки еще нужна EIP-712 подпись владельца |
| `account_creation` | Create/list/recover partner-created child profiles | Не позволяет присоединить чужой существующий профиль |
| `delegated_signing` | Server signing и delegated REST reads | Для торговых mutations нужен также `trading`; delegated REST reads требуют `delegated_signing`; только собственные child profiles |
| `withdrawal` | Server-wallet ERC20 withdrawal | Адрес назначения ограничен allowlist; не дает изменять allowlist |
| `admin` | Admin-protected endpoints | Только admin-provisioned, не self-service; для MVP не заявляется |
| Privy identity auth | Derive/capabilities, withdrawal-address management | `identity: Bearer <identity_token>`; не подменять access token |
| Legacy `X-API-Key` | Старые ключи продолжают работать «пока» | Новые не выдаются; server-wallet/AMM endpoints их отклоняют |
| Session | Отдельные portfolio операции все еще описывают session auth | Не проектировать новый programmatic flow вокруг session |

Источники: [Authentication](https://docs.limitless.exchange/developers/authentication), [Programmatic API scopes](https://docs.limitless.exchange/developers/programmatic-api), [Withdraw](https://docs.limitless.exchange/api-reference/portfolio/withdraw).

**Расхождения официальных источников.** В `openapi.json` верхний `info.description` все еще говорит API key required и удаление cookie «within weeks»; актуальная Authentication page уже требует HMAC и объявляет legacy keys deprecated. Не превращать относительный старый текст в конкретный срок миграции: **датированного обязательного deadline не установлено**. Security metadata у capabilities/derive имеет `HmacAuth`, но prose требует Privy; для server-wallet operations schema пишет `limitless_session`, а page допускает API token/Privy/session. Enum derive/capabilities OpenAPI перечисляет три scope без `withdrawal`, но актуальный Programmatic API и Withdraw page описывают `withdrawal`. Это дефекты согласованности документации; будущий агент обязан проверить actual capabilities и схему до подключения. [OpenAPI](https://docs.limitless.exchange/openapi.json), [Authentication](https://docs.limitless.exchange/developers/authentication).

## 2. HMAC protocol и управление токенами

Все day-to-day private REST запросы подписывать заголовками `lmts-api-key` (tokenId), `lmts-timestamp` (ISO-8601, окно ±30 секунд от server time), `lmts-signature` (base64 HMAC-SHA256). Secret сначала декодировать из base64. Canonical message — timestamp, HTTP method, **полный path + query string**, точные bytes JSON body, разделенные `\n`; GET body пустой. Подписанные bytes должны совпадать с отправленными, порядок/encoding query не менять после подписи. HMAC аутентифицирует HTTP запрос, EIP-712 авторизует CLOB order; это разные подписи. Secret хранить backend/BFF, не browser bundle. Источник: [HMAC signing](https://docs.limitless.exchange/developers/authentication).

| Method / path | Auth; параметры / body | Response; pagination | Документированные ошибки | Источник |
|---|---|---|---|---|
| GET `/auth/api-tokens/capabilities` | Privy identity; без body | `partnerProfileId`, `tokenManagementEnabled`, `allowedScopes`; нет pagination | 401 | [Capabilities](https://docs.limitless.exchange/api-reference/api-tokens/get-capabilities) |
| POST `/auth/api-tokens/derive` | Privy identity; optional `label` ≤128, `scopes` array; default `[trading]` | 201: `apiKey` (=tokenId), `tokenId`, `secret`, `createdAt`, `scopes`, `profile {id,account}` | 400 invalid scopes/profile; 401; 403 disabled management / scope not allowed | [Derive](https://docs.limitless.exchange/api-reference/api-tokens/derive-token) |
| GET `/auth/api-tokens` | Authenticated actor; token management enabled; guide says Any, OpenAPI HmacAuth | Active non-revoked array `{tokenId,label,scopes,createdAt,lastUsedAt}`; no pagination declared; no secret | 401; 403 | [List](https://docs.limitless.exchange/api-reference/api-tokens/list-tokens) |
| DELETE `/auth/api-tokens/{tokenId}` | Authenticated actor; token management enabled; path string | 200 message, token immediately unusable | 400 missing/already revoked; 401; 403 | [Revoke](https://docs.limitless.exchange/api-reference/api-tokens/revoke-token) |

Secret возвращается только при derive, recovery secret нет. Authentication prose упоминает expiry как преимущество scoped tokens, но точный lifetime и expiry field в перечисленных DTO не определены: **не проверено**, уточнить у Limitless. Нельзя считать `lastUsedAt` сроком действия. Секрет/identity никогда не записывать в examples/logs/docs. [Authentication](https://docs.limitless.exchange/developers/authentication), [OpenAPI schemas](https://docs.limitless.exchange/openapi.json).

## 3. Partner subaccounts, ownership и recovery

| Method / path | Auth; input | Response / pagination | Errors | Источник |
|---|---|---|---|---|
| POST `/profiles/partner-accounts` | HMAC `account_creation`; `displayName` optional ≤44, `createServerWallet` optional default false; true также требует `delegated_signing`; EOA mode требует `x-account` EIP-55, hex `x-signing-message`, `x-signature` | 201 `{profileId,account}`; no pagination | 400 partner own address/creation failure; 401 failed EOA proof; 403 insufficient auth/scope; 409 existing profile | [Create](https://docs.limitless.exchange/api-reference/partner-accounts/create-partner-account) |
| GET `/profiles/partner-accounts` | HMAC `account_creation`; optional `account` exact case-insensitive EVM address, `limit` default25 cap25 min1, `page` default1 min1; **не** `x-on-behalf-of` | `{data:[{profileId,account,displayName}],limit,page,hasMore}` | 400 invalid query; 401; 403 | [List/recover](https://docs.limitless.exchange/api-reference/partner-accounts/list-partner-accounts) |
| GET `/profiles/partner-accounts/{profileId}/allowances` | HMAC `account_creation` + `delegated_signing`; owned server-wallet child id | live-chain readiness schema ниже; no pagination | Полный HTTP error перечень не указан на GET page/spec; не выдумывать | [Check](https://docs.limitless.exchange/api-reference/partner-accounts/check-allowances) |
| POST `/profiles/partner-accounts/{profileId}/allowances/retry` | Те же scopes; no body required | Same readiness shape; submits only still missing targets | 409 wallet retry in progress; 429 with `retryAfterSeconds`; 503 limiter unavailable | [Retry](https://docs.limitless.exchange/api-reference/partner-accounts/retry-allowances) |

Server-wallet child имеет managed Privy wallet; partner не держит user private key и подает unsigned order с `onBehalfOf`. EOA child сам подписывает каждую заявку: `ownerId = onBehalfOf = child.profileId`, `maker/signer = child EOA`. HMAC partner не заменяет EOA signature. Существующий ранее созданный профиль нельзя adopt/link: POST дает409, публичного adoption endpoint нет. GET recovery возвращает только детей этого партнера. Для учета сохранить собственный user id, wallet→profileId и ownership mode; не хранить «session object» как substitute order signing. [Programmatic API EOA flow](https://docs.limitless.exchange/developers/programmatic-api).

Readiness fields: `profileId`, `partnerProfileId`, `chainId`, `walletAddress`, `ready`, `summary {total,confirmed,missing,submitted,failed}`, `targets[]`. Target: `type` (`USDC_ALLOWANCE`/`CTF_APPROVAL`), `tokenAddress`, `spenderOrOperator`, `label`, `requiredFor` (`BUY`/`SELL`/`SPLIT`), `confirmed`, `status` (`confirmed`/`missing`/`submitted`/`failed`), `retryable`, optional `transactionId`, `txHash`, `userOperationHash`, `errorCode`, `error`, `lastFailedAt`, `currentAllowance`. `ready=true` только когда все targets подтверждены on-chain. `submitted` означает submission текущим retry, **не confirmation**. Recovery: GET → если missing/failed и retryable, POST retry → после submission вновь GET; 429 ждать `retryAfterSeconds`, 409 кратко ждать и GET. Значение chainId84532 в официальном JSON example — **пример**, не доказательство production Base Sepolia; production chain определяется фактическими market/config/contract данными. [Check](https://docs.limitless.exchange/api-reference/partner-accounts/check-allowances), [Retry](https://docs.limitless.exchange/api-reference/partner-accounts/retry-allowances).

## 4. Delegated reads и события

`x-on-behalf-of: <childProfileId>` перечислен актуальным Programmatic prose для GET `/portfolio/positions`, GET `/portfolio/history`, GET `/markets/{slug}/user-orders`, POST `/orders/status/batch`, GET `/v2/orders/status/{id}` (последний отсутствует в global spec, параметры/схема U, см. раздел8). HMAC token должен иметь `delegated_signing`, child принадлежать partner. Без header endpoint читает caller. Invalid header / unsupported delegation =400; missing scope / not owned =403 с намеренно generic message. Не распространять header на все private routes. Mutations используют body/query `onBehalfOf`, что не взаимозаменяемо с read header. [Programmatic API delegated reads](https://docs.limitless.exchange/developers/programmatic-api).

**Order events partner handshake не включает child orders.** `subscribe_order_events` доставляет events только orders handshake profile. Ни `onBehalfOf`, ни `x-on-behalf-of` не расширяют WS; delegation — REST-only. Для child status нужны delegated batch/status/user-orders reads или отдельная авторизация самого child, доступность последнего flow для managed child не подтверждена. Public history чужого лидера не является authenticated own-order stream и не дает SLA универсальной доставки сделок. [Order Events](https://docs.limitless.exchange/developers/websocket/order-events).

WS HMAC canonical path фиксирован `/socket.io/?EIO=4&transport=websocket`; authenticated subscribes следует emit сразу после connect, не позже30 секунд timestamp: сервер заново валидирует handshake headers при subscribe. Новый private subscription позже30 секунд требует нового соединения с свежей подписью. После disconnect заново подписать handshake и subscribe. LB закрывает соединение через24 часа (часто1006); subscriptions не сохраняются. Для gap recovery использовать REST, для непрерывности docs предлагают второе соединение перед24-hour cutoff. Это документированное поведение, не измеренная гарантия. [WS Overview](https://docs.limitless.exchange/developers/websocket/overview).

## 5. Redeem / split / merge / withdrawal

Все четыре операции — managed server wallets, не EOA/user-managed smart wallet. Legacy keys отклоняются. Body `onBehalfOf` выбирает owned child; omit — own managed wallet. Responses обозначают submitted transaction; eventual settlement нельзя выводить только из HTTP200. [Programmatic API](https://docs.limitless.exchange/developers/programmatic-api).

| Method / path | Scope/auth и body | Response | Errors | Источник |
|---|---|---|---|---|
| POST `/portfolio/redeem` | apiToken `trading`, Privy/session; required `conditionId` bytes32; optional `onBehalfOf` | 200 submitted; `hash`, `userOperationHash`, `transactionId`, `conditionId`, `walletAddress`, `marketId` в illustration | 400 not resolved/no balance;401;403 no server wallet/scopes;404 market;409 in progress | [Redeem](https://docs.limitless.exchange/api-reference/portfolio/redeem) |
| POST `/portfolio/split` | apiToken `trading`, Privy/session; `conditionId`, `amount` positive raw collateral string, `venue` market object; optional `onBehalfOf` | 200 submitted; `conditionId`, `operation:SPLIT`, `route:clob/negrisk`, `walletAddress`, optional transaction identifiers |400 invalid amount/condition/adapter;401;403;409 split/merge already running | [Split](https://docs.limitless.exchange/api-reference/portfolio/split) |
| POST `/portfolio/merge` | Same; amount raw complete sets, same venue routing | 200 submitted; `operation:MERGE`, other fields as split | Same as split | [Merge](https://docs.limitless.exchange/api-reference/portfolio/merge) |
| POST `/portfolio/withdraw` | apiToken `withdrawal`, Privy/session; required `amount` raw token integer string; optional `token` (recognized collateral ERC20; default USDC), `onBehalfOf`, `destination` |200 submitted; illustration `hash,userOperationHash,transactionId,walletAddress,token,destination,amount` |400 invalid amount/balance/token;401;403 server wallet/scope/destination;409 operation running | [Withdraw](https://docs.limitless.exchange/api-reference/portfolio/withdraw) |
| POST `/portfolio/withdrawal-addresses` | **Privy identity only**, `address` required, `label` optional; HMAC forbidden |201 `{id,profileId,destinationAddress,label,createdAt,deletedAt}` |400;401;403 Privy required | [Add](https://docs.limitless.exchange/api-reference/portfolio/add-withdrawal-address) |
| DELETE `/portfolio/withdrawal-addresses/{address}` | Privy identity only; path address, no body |204 soft-delete |400 invalid;401;403;404 missing | [Delete](https://docs.limitless.exchange/api-reference/portfolio/delete-withdrawal-address) |

No pagination for these mutations. Split/merge: 1 USDC→1YES+1NO and converse; USDC6 decimals means `1000000` raw =1USDC/full set. `venue.adapter` routes NegRiskAdapter, otherwise market `venue.exchange` required and standard ConditionalTokens route. Required split collateral approvals and NegRisk merge ERC1155 approval provisioned ahead; no extra approval submitted here. Simple merge burns own tokens and needs no allowance. Sponsored4337 operations can lack synchronous tx hash: persist `transactionId`/`userOperationHash`. Detailed read-after-write status endpoint for these identifiers, retry idempotency and finality policy are **not established** on these pages; do not invent `/transactions/{id}`. [Split](https://docs.limitless.exchange/api-reference/portfolio/split), [Merge](https://docs.limitless.exchange/api-reference/portfolio/merge).

Resolved API status не гарантирует redeemability: CTF payout must be on-chain (`payoutDenominator(conditionId)>0` if checking on-chain). `winningOutcomeIndex` fixed YES0/NO1, null may mean unresolved or split resolution; split resolved market имеет non-null `payoutNumerators` и обе стороны могут redeem в указанном ratio. Redeem один condition per call, batch endpoint нет. NegRisk redeem через adapter с YES/NO balances, standard через ConditionalTokens full partition. EOA должен sign on-chain claim через UI/direct contract; auto-redeem для EOA не заявлен. [Redeem](https://docs.limitless.exchange/api-reference/portfolio/redeem), [Programmatic lifecycle](https://docs.limitless.exchange/developers/programmatic-api).

Withdrawal explicit destination: caller account, caller smart wallet или active allowlist **caller partner profile**; child whitelist не используется. Omitted destination — caller Etherspot smart wallet if exists, otherwise caller account. Это не unrestricted user payout и не bank/off-ramp. Add/delete allowlist requires отдельный Privy identity, withdrawal-scope token этих прав не имеет. Allowlist activation delay, max entries, audit trail/list endpoint, replacement policy и user-specific withdrawal destinations пока **не проверены/не документированы** в этих страницах. [Withdraw](https://docs.limitless.exchange/api-reference/portfolio/withdraw), [Add](https://docs.limitless.exchange/api-reference/portfolio/add-withdrawal-address).

Funding: перечисленные partner endpoints создают wallet/profile и approvals; прямого partner deposit/fiat deposit endpoint в изученной матрице нет. До будущей интеграции отдельно подтвердить supported collateral/network, chain finality, gas sponsorship limits, external deposit detection и recovery. Не выводить transfer capability для любых ERC20 из generic слова ERC20: withdraw допускает только platform-recognized collateral. [Withdraw](https://docs.limitless.exchange/api-reference/portfolio/withdraw), [Programmatic API](https://docs.limitless.exchange/developers/programmatic-api).

## 6. AMM partner endpoints

Документированы HMAC `trading`+`delegated_signing`; only managed server-wallet profiles, legacy keys forbidden. Market slug либо checksummed FPMM address; outcomeIndex0YES/1NO. Все суммы positive integer strings raw collateral (USDC6dec). Slippage default100bps, max1000bps. `POST /amm/buy` body market,outcomeIndex,collateralAmount,idempotencyKey, optional slippageBps,onBehalfOf;201 `SUBMITTED`, expectedShares,minShares,transactionId,userOperationHash, optional txHash. `POST /amm/sell` использует **collateralReturnAmount: exact collateral target**, не exact shares;201 expectedShares,maxShares. Это intent-level AMM trade, не CLOB limit order. [AMM Trading](https://docs.limitless.exchange/developers/amm-trading).

`POST /amm/allowances/check` body market,side BUY/SELL,optional onBehalfOf; response status confirmed/missing,confirmed,walletAddress,tokenAddress,spenderOrOperator,currentAllowance (BUY only). `/amm/allowances/approve` same body; already approved200confirmed, new sponsored submission202submitted with transaction identifiers; then poll check. BUY ERC20 approval и SELL ERC1155 approval независимы, per wallet/market/side. AMM idempotencyKey required ≤128 nonblank; retained24h per target profile; same key+same params returns original result, different params409. Four endpoints share per-caller10requests/10seconds,429retryAfterSeconds. Errors400invalid body;403scope/legacy/ownership;409closed/deadline/key mismatch;422balance/too-small-slippage;429;502RPC/quote/Privy. [AMM](https://docs.limitless.exchange/developers/amm-trading).

## 7. Вопросы партнеру до будущего live copy trading

1. Подтвердить enabled scopes (`withdrawal` отсутствует в OpenAPI enum), Privy/HMAC auth discrepancies и session support/deprecation dates.
2. Token lifetime, rotation без interruption, max active tokens, secret recovery невозможность и clock tolerance operational policy.
3. Существующие пользователи не adoptable: есть ли согласованный migration/consent flow вне публичного API?
4. Managed child credentials: можно ли легально/технически открыть child-owned WS; есть ли future partner aggregate order stream, delivery replay/cursor и SLA?
5. Withdraw destination constraints для индивидуальных пользователей, list/audit/activation policy allowlist, supported collateral и network/gas costs.
6. Для redeem/split/merge/withdraw: idempotency, timeout/unknown reconciliation, supported status lookup по transactionId/userOperationHash, finality, safe retry и limits.
7. Funding/deposit confirmation and balance freshness, sponsorship budgets и loss-of-access recovery, ownership/export/migration managed-wallet accounts.

Это вопросы, не обещания API и не новые бизнес-правила MVP. Paper integration может пользоваться public data независимо от partner approval; live delegated-account lifecycle потребует отдельной верификации и разрешений.

### Response semantics для private reads

`ProfileResponse` содержит `tradeWalletOption` (`eoa`/`smartWallet`/nullable), `embeddedAccount`, `smartWallet`, `client`, а также профильную/referral metadata. Для ownerId использовать `id`. Private profile page/schema всё ещё называет `rank.feeRateBps`, но [changelog23.09](https://docs.limitless.exchange/changelog) требует текущий `effectiveFeeRateBps` для fee-enabled order signing; rank alone небезопасен. Это ещё одно официальное расхождение; не использовать hardcoded schema fee. Подробности [execution](execution.md). EOA address re-casing403 на `/profiles/{account}` отличается от case-insensitive account filter partner recovery. [Profile](https://docs.limitless.exchange/api-reference/portfolio/get-profile), [OpenAPI](https://docs.limitless.exchange/openapi.json).

`positions.clob[].positions` содержит raw-token decimal-string `cost`, `fillPrice`, `realisedPnl`, `unrealizedPnl`, `marketValue` (USDC1=1000000), balance/orders/market data; AMM position has `outcomeIndex`, optional collateralAmount,outcomeTokenAmount,account. `rewards.todaysRewards` вопреки названию означает последний completed minute epoch, а не calendar-day total; `totalUserRewardsLastEpoch` такое же окно; `totalUnpaidRewards` суммарная невыплаченная сумма. Все rewards raw1e6-scaledUSDC. Это отдельные балансы, не realized PnL. [Positions](https://docs.limitless.exchange/api-reference/portfolio/positions), [Position schemas](https://docs.limitless.exchange/openapi.json).

`history.data[]` имеет blockTimestamp,collateralAmount,market,outcomeTokenAmount,outcomeTokenAmounts,outcomeIndex,outcomeTokenPrice,strategy и optional CLOB `tradeEventId`, `orderId`, `makerMatchId`, settled transactionHash. Maker strategy=`Limit Buy`/`Limit Sell`, taker=`Market Buy`/`Market Sell`, AMM=`Buy`/`Sell`, и Split/Merge/Convert/Claim. **Дискретное расхождение**: page включает `Claim`, global HistoryEntryDto enum его не содержит. Для importer unknown strategies должны сохраняться как raw value до проверки, а не теряться. Dedicated fills endpoint не заявлен, history — источник own CLOB fills. History **не включает deposits/withdrawals**; отдельного API transfer-history endpoint docs не предоставляют, предлагают query on-chain Base USDC transfers. Отсутствуют historical orderbook snapshots. [History](https://docs.limitless.exchange/api-reference/portfolio/history), [Schema](https://docs.limitless.exchange/openapi.json).
