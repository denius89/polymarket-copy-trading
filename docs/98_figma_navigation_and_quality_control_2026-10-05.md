# Управление маршрутом и качеством Figma · 05.10.2026

Дополнение: [проход по интерфейсам 104](104_figma_interface_completion_pass_2026-10-05.md) восстановил пять основных desktop EN экранов и выровнял рынки на четырёх рабочих страницах. Стартовый лист и карта ниже остаются точкой входа; детальная интерактивная приёмка дополнительных состояний ещё требуется.

## Одна актуальная точка входа

[Стартовый лист](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=3-2) выбирает устройство, язык и режим проверки. На нём есть ссылка **«Открыть карту экранов»**.

[Карта экранов](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=1664-2) показывает последовательность ключевых экранов в четырёх столбцах: mobile RU, mobile EN, desktop RU, desktop EN. В карте 11 шагов и 44 прямые ссылки; все цели существуют. Это текущий навигатор для приёмки, а не новая версия интерфейса продукта.

Рабочие холсты тоже разложены одинаково: основные экраны в пяти блоках, связанные состояния в колонках A–D. [Как устроен холст — 99](99_figma_canvas_structure_2026-10-05.md).

## Как проходить

1. **Первый запуск:** знакомство → каталог → профиль трейдера → настройки копирования → проверка перед запуском → запуск → **новая пустая сессия**. На мобильном знакомство состоит из трёх сторис, на ПК — из одного обзора. В карте прямыми ссылками покрыты первые пять опорных экранов. Условный участок от проверки до пустой сессии нужно проверять в Present как цельный путь.
2. **Активное демо:** открыть отдельный подготовленный пример со стартового листа → главная → позиции → заявки → события → средства → помощь. Подготовленная история не является автоматическим продолжением новой пустой сессии.
3. Сначала пройти mobile RU, затем desktop RU. После этого сравнить те же задачи в EN. Не требуется просматривать все 53 дополнительные состояния для оценки основного пути.

## Правило контроля изменений

Для каждого следующего изменения экрана фиксировать: **сценарий → предыдущий экран → текущий экран → следующее действие → состояние (Current/Future/Proposed) → RU/EN и mobile/desktop → статус проверки**. Если один и тот же шаг на четырёх страницах расходится по смыслу, это отдельная ошибка, а не четыре разных продукта. Неиспользуемые варианты остаются в архиве 90–96 и не задают маршрут.

Замечание для дизайна записывать как «где начал → что нажал → куда попал → куда ожидал попасть → ссылка на экран». Для визуальной проблемы добавить снимок и отметить, мешает ли она понять действие или только требует полировки.

## Что ещё не покрыто этой картой

Карта даёт ясный **первый слой**, но не объявляет полную проверку всех ответвлений. Следующий контрольный слой — каталог дополнительных состояний (ошибки, ожидание, unknown, помощь, деньги и управление позицией) с владельцем решения и отметкой проверки для каждого языка/размера. При маршрутной проверке отдельно сверить условные переходы после экрана проверки настроек: наличие экрана не доказывает, что все ветки Present ведут в правильное состояние.

Старые ссылки на служебное меню сценариев в [инструкции 54](54_colleague_figma_clickthrough_guide.md) сохранены только как исторический материал; для текущей проверки использовать стартовый лист и новую карту.
