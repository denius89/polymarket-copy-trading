# Paper-копия: источники цены, ликвидности и расходов

Дата: 05.10.2026. Область: первый paper-сценарий; это проверка документации API и правило расчёта, а не подтверждение качества фактического потока котировок или готовая реализация. Решение — [ADR-0028](decisions/0028_paper_quote_depth_and_expense_evidence.md).

## Что подтверждено источниками

| Площадка | Подтверждённые поля и ограничения | Вывод для paper-копии |
|---|---|---|
| Polymarket | Официальный [CLOB book](https://docs.polymarket.com/market-data/prices-order-books) возвращает уровни bid/ask с ценой и размером для конкретного outcome token; в модели есть timestamp, который может отсутствовать. [Market Details](https://docs.polymarket.com/market-data/market-details) содержит состояние рынка и доступность книги. | Для покупки можно оценить полную сумму по уровням ask именно нужного исхода; одной лучшей цены недостаточно. Отсутствующий или непроверенный timestamp нельзя считать доказательством свежести. Нужны правильный token ID, состояние рынка и проверка границ данных. |
| Polymarket | [Trading Fees](https://docs.polymarket.com/trading/fees) описывает taker fee, зависящую от рынка и цены, и правила округления; ставки различаются по категориям. | Тариф нельзя подставить универсальной константой. Для конкретного рынка нужно получить применимые параметры и версию правил, проверить расчёт на ответе площадки. |
| Limitless CLOB | Официальный [Get Orderbook](https://docs.limitless.exchange/api-reference/trading/orderbook) возвращает YES bids/asks, token ID, midpoint и lastTradePrice. Документация предупреждает, что lastTradePrice может относиться к другому моменту; свежесть REST-книги не гарантирована. Книга NO получается преобразованием YES; для AMM этот endpoint не подходит. | Last trade и midpoint не являются исполнимой ценой. Для NO нужно корректно преобразовать стороны книги. Сама доступность REST-ответа не подтверждает пригодную свежесть; AMM требует отдельной модели и проверки. |
| Limitless CLOB | Официальные [Fees](https://docs.limitless.exchange/user-guide/fees) описывают разные taker buy/sell fee, фактические поля исполнения и возможные профильные параметры. Общая таблица не даёт точную формулу для любого аккаунта и рынка. | Нельзя выдавать приблизительную ставку из таблицы за точный расход. Требуется воспроизводимый источник применимой ставки или надёжной верхней границы в нужных единицах. |

## Единый расчёт допуска

1. Когда действие трейдера обнаружено, сохранить момент обнаружения и проверить давность **сигнала** по действующему preset (для новых входов сейчас 30 секунд по [ADR-0012](decisions/0012_paper_mvp_defaults.md)). Это отдельная проверка от свежести книги.
2. Получить книгу **той же площадки, рынка, исхода и стороны** на момент решения. Сохранить время ответа, предоставленный источником timestamp/hash или версию, идентификаторы рынка/исхода, сырые уровни и происхождение данных. Не заменять отсутствующий timestamp временем загрузки: оно подтверждает лишь момент получения ответа.
3. Проверить открытость рынка, валидность уровней, валюту и размер. Для покупки пройти по ask от лучшей цены до полного желаемого объёма; для продажи — по bid. Сортировку нормализовать явно. Рассчитанная цена — средневзвешенная по реально используемым уровням; spread и глубина уже влияют на неё и не добавляются повторно отдельной выдуманной надбавкой.
4. Все используемые уровни должны удовлетворять **явно заданной допустимой цене**. Если подтверждённого объёма в этих границах недостаточно на всю покупку — пропуск по [ADR-0025](decisions/0025_skip_buy_when_verified_liquidity_cannot_cover_full_copy.md). Если пригодность/свежесть книги неизвестна — показывать действие трейдера без виртуального исполнения по [ADR-0024](decisions/0024_show_missing_market_data_without_simulated_fill.md).
5. Перед резервом получить воспроизводимую оценку **возможных списываемых** расходов для полного объёма в правильной валюте и с правилами округления. Бюджет проверяется на сумму покупки и этот верхний расход по [ADR-0022](decisions/0022_reserve_expected_copy_expenses_in_paper_budget.md). Если защитную оценку подтвердить нельзя, новая покупка не допускается; неизвестное не равно нулю. В закрытой альфе сервисная комиссия 0%, виртуальную информационную комиссию показывать отдельно по [ADR-0005](decisions/0005_execution_fee_and_partner_policy.md).
6. Сохранить snapshot входных данных и версию правил расчёта вместе с решением. Фактический paper-результат формировать только из подтверждённых частей, без фиктивных fill/P&L. После допуска частичные результаты и отмена остатка следуют [ADR-0026](decisions/0026_keep_confirmed_partial_fill_and_cancel_remainder.md) и [ADR-0027](decisions/0027_reconcile_fills_while_remainder_cancellation_is_pending.md).

Историческая цена сделки трейдера, последняя сделка на рынке, midpoint, график и карточка рынка подходят для контекста, но не доказывают цену полной paper-копии в момент решения. При неизвестных данных экран должен показывать именно неизвестное, а не рассчитанную прибыль или «0» расходов.

## Что ещё нужно измерить, прежде чем разрешить автоматический расчёт

- **Возраст книги.** На записанных ответах обеих площадок измерить лаг `source timestamp → receive time`, долю ответов без timestamp, разрывы и повторы. Для Limitless отдельно проверить, даёт ли документированный поток обновлений и сверка с REST доказуемую свежесть для CLOB. Числового порога свежести книги сейчас нет; 30 секунд давности сигнала его не заменяют.
- **Допустимая цена.** Определить утверждённый предел цены/отклонения для полной покупки, формулу округления и пользовательское отображение. Пока параметр не установлен, «ликвидности по допустимой цене хватает» нельзя вычислить честно.
- **Расходы.** Проверить применимый рыночный тариф Polymarket и персональный/рыночный тариф Limitless на реальных разрешённых ответах, включая asset units и округление; сопоставить оценки с фактическими полями исполнения. Общие справочные диапазоны не использовать как точные значения. AMM Limitless исследовать отдельно.
- **Контрольные примеры.** Записать и воспроизвести: полный объём, недостаточная глубина, устаревший/недатированный ответ, неизвестная комиссия, покупка YES/NO, частичное исполнение после допуска. Только после этого утвердить площадочные пороги и перевести сценарий в исполняемый.

Пока эти проверки не завершены, макет может показывать расчёт на явно помеченных демонстрационных данных и состояния пропуска. Он не должен обещать, что рыночный расчёт в обеих площадках уже готов.
