# Репозиторий: карта, сохранение и завершение работы

Действующий порядок от **19.10.2026**, по поручению владельца. [Главная](../README.md) · [Документация](README.md) · [Реестр внешних архивов](storage/catalog.json).

## Что считается сохранённым

Каждый содержательный законченный блок и работа перед длительным перерывом должны иметь копию вне компьютера. Локальный commit, stash, worktree, временная ссылка на скачивание или сообщение в чате сами по себе не закрывают сохранение.

| Материал | Постоянное место | Подтверждение |
| --- | --- | --- |
| Документы, навыки, спецификации, исходники, небольшие fixtures и результаты | GitHub, ветка задачи; после проверки — main | Удалённый commit SHA и читаемый diff; для завершённого блока — PR/merge и CI |
| Большие выгрузки, Parquet, потоки наблюдений, тяжёлые медиа | Google Диск | Успешная загрузка, обратное чтение метаданных, размер; SHA256 и manifest в GitHub |
| Приватный handoff, прежние версии, резервная история Git | Закрытая папка Google Диска | Адрес файла/папки, состав, SHA256, инструкция восстановления и проверка распаковки/восстановления |
| Кэши, зависимости, временные сборки | Только локально, в ignore | Возможность получить из сохранённых исходников; уникальные данные сюда не относить |

Обычный файл Git ограничен **10 MiB**. Большие исходные данные выносятся на Диск с manifest, даже если общий объём укладывается в лимит. Исключения требуют отдельного обоснования в PR; лимит не подменяет проверку содержимого. Секреты не сохраняются в репозитории, резервных архивах или manifests. Чувствительные материалы хранятся с существующим закрытым доступом; публикация ссылки не должна менять права Диска.

Реестр `storage/catalog.json` — единственный каталог внешних архивов. Он ссылается на подробный manifest области, а не дублирует сотни записей. Для нового архива указываются назначение, постоянная ссылка, дата сверки, размеры/SHA256, место manifest и способ восстановления. Не использовать временные download URL. Сохранять честную границу: локально проверенный SHA256 и удалённый размер не означают повторное хеширование скачанных байтов. Перед удалением единственной локальной копии уникальных данных отдельно скачать архив, проверить его SHA256 и восстановление; иначе локальную копию сохранить.

## Роли папок

| Каталог | Ответственность и точка входа |
| --- | --- |
| Корень | README RU/EN, правила участия, безопасность и AGENTS; сюда не складывать новые исследовательские выгрузки |
| `docs/` | Согласованные продуктовые документы, спецификации и текущая навигация; [README](README.md) — вход, [DOCUMENT_INDEX](DOCUMENT_INDEX.md) — полный исторический каталог |
| `docs/decisions/` | Решения и предложения ADR с явным статусом |
| `docs/design/` | Читаемые контракты экранов, living maps, инструкции и доказательства дизайн-пакетов |
| `design/client-ui-kit/` | Машиночитаемые tokens/manifest/QA и [handoff](../design/client-ui-kit/HANDOFF.md) клиентского kit |
| `design/qa-*/` | Исторические файлы проверок и построения Figma; их дата не делает их текущей картой интерфейса |
| `research/<тема-дата>/` | README, код эксперимента, конфигурация, небольшие входы, результаты, ограничения и manifest данных |
| `.agents/skills/` и `docs/ai-system/` | Инструкции навыков отдельно от знаний, обучения и свидетельств оценки; frozen eval replicas не редактируются ради текущих правил |
| `apps/`, `packages/`, `infra/` | Границы будущей реализации и планы инфраструктуры; наличие папки не означает готовый сервис |
| `artifacts/` | Окончательные опубликованные презентации; тяжёлые/временные версии — на Диске |
| `scripts/`, `.github/` | Проверки и рабочие процедуры репозитория |
| `references/` и родительский `sources/` | Исходные материалы только для чтения; не переименовывать и не редактировать synced файлы |

Сохранять существующие пути и ссылки. Новые материалы размещать по назначению; повторное имя в `docs/design/` и `design/` не означает дублирование. Не создавать новый numbered-документ или новый каталог для каждой реплики. Долгоживущую тему обновлять на месте, законченный эксперимент оформлять одним датированным пакетом.

## Как выбирать актуальный источник

1. Явное решение владельца и действующие принятые ADR задают продуктовые границы. Неоднозначный конфликт вынести в открытый вопрос, не принимать новую финансовую логику молча.
2. [ROADMAP](ROADMAP.md) определяет очередь, [PROJECT_STATE](PROJECT_STATE.md) фиксирует последний результат и историю. Дата записи не превращает предложение в решение.
3. Живые карты [клиента](design/client/sitemap.md) и [админки](design/admin/sitemap.md), handoff и связанный последний пакет задают актуальные узлы и пределы проверки.
4. Нумерованные ранние документы, старые QA и презентации — исторические свидетельства. Старые «следующие шаги» не разрешают работу, которую текущий этап ещё не разрешает.

## Цикл задачи

**Начало.** Обновить сведения GitHub, зафиксировать baseline main SHA, проверить dirty/untracked/ignored-файлы и активные рабочие копии. Одна задача — одна короткоживущая ветка `docs/`, `research/`, `design/`, `feat/`, `fix/`, `chore/` или `maintenance/`. Worktree нужен при параллельной работе/изоляции; для последовательной небольшой задачи достаточно ветки в основной папке. Чужую активную работу не трогать.

**Сохранение.** После содержательного блока commit и push в ветку задачи. До паузы сохранить незаконченный материал в этой ветке/draft PR, ясно указав оставшуюся работу. Большие и закрытые данные загрузить на Диск, проверить обратным чтением, записать manifest/SHA256 и обновить каталог. При ошибке публикации обозначить локальный статус и препятствие; не писать «сохранено» по одному намерению загрузить.

**Проверка.** `npm run check`, `npm run test:repository`, `git diff --check`, содержательное чтение diff и соразмерные предметные проверки. В PR — результат, основания, тесты, ссылки на данные и оставшиеся ограничения. Обновить журнал; очередь и ADR менять только при изменении соответствующего решения.

**Объединение.** Проверенный результат объединять в main после CI и review в пределах поручения. По постоянному разрешению владельца для проектных материалов повторное согласие на commit/push/PR/merge и уборку завершённой задачи не требуется. Это не разрешает deploy, сделки, изменение аккаунтов/прав доступа или публикацию секретов/чувствительных данных. Историю main не переписывать.

**Завершение.** Проверить наличие результата в удалённой main и сохранность данных. Обновить основную папку до main. Удалить ветку завершённого PR на GitHub, затем ветку и принадлежащий этой задаче worktree локально. До удаления worktree отдельно проверить ignored-файлы: чистый status их не покрывает. При уникальных остатках сохранить/сверить архив либо оставить задачу явно незавершённой. Не применять `reset --hard`, `clean` или `--force` ради чистого статуса.

## Что убирается автоматически

Workflow `cleanup-merged-branch.yml` обрабатывает только **merged PR того же репозитория** и ветки с префиксами задач. Он не исполняет код PR, не делает checkout и удаляет head только с проверкой точного SHA. Default/base branch, ветки forks, закрытые без merge PR и ветки, продвинувшиеся после review, остаются для отдельной сверки. Результат фиксируется в Actions. Это не архиватор уникальной работы.

Локальные ветки/worktrees убирает агент, завершавший задачу: GitHub не управляет папками компьютера. Закрытый без merge PR удалять только после проверки, что изменения перенесены либо явно сохранены в архиве. При отсутствии команды удаления в плагине допустима одноразовая ограниченная GitHub-задача с точными SHA; её служебная ветка тоже удаляется. Массовая уборка всегда сверяет активные PR и новые commits, а не только возраст веток.

## Критерий завершённого блока

- Результат доступен на GitHub или Диске; указаны проверенные ссылки и SHA/manifest.
- CI и предметные проверки пройдены, ограничения записаны.
- PR объединён/закрыт с ясной причиной; у завершённой задачи нет забытой head-ветки или worktree.
- Основная рабочая папка синхронизирована с main и чиста; работа других задач сохранена.
- В финальном сообщении указаны результат, постоянная ссылка и реальные оставшиеся препятствия.

[Срез уборки и восстановление](REPOSITORY_MAINTENANCE_2026-10-19.md) хранит исторические итоги, а не текущий список веток. Состав GitHub и доступность Диска проверяются заново перед удалением или восстановлением.
