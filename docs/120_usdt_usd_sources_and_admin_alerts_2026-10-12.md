# USDT/USD: источники курса и уведомления администраторам

Дата проверки: **12.10.2026**. Основание: поручение найти источник рыночного курса и предусмотреть уведомления при настраиваемом отклонении. Это исследование и контракт для разработки; мониторинг, аккаунты провайдеров и рассылка сейчас не запущены.

## 1. Решение для проекта

Внутренний учёт **1 USDT = $1** сохраняется. Отдельный серверный процесс получает рыночную котировку, сравнивает её с $1 и уведомляет администраторов по настраиваемому правилу. Процесс не пересчитывает прошлые обязательства и не создаёт в продукте функцию обмена.

Рекомендация для реализации: **Kraken — основной оперативный источник прямой пары USDT/USD; CoinGecko — дополнительная сверка агрегированной цены**. HTML-скрейпинг не нужен. Платный тариф, регистрация и окончательная production-конфигурация этим исследованием не приобретаются. Конкретные пороги устанавливают Owner, без зашитого числа.

## 2. Проверенные источники

| Источник | Что получаем | Доступ и ограничения |
| --- | --- | --- |
| Kraken Spot REST | Прямая USDT/USD, best bid/ask и last trade | Публичный endpoint без торговых полномочий; лимиты public API нужно соблюдать. REST Ticker не даёт timestamp каждого ценового поля |
| Kraken WebSocket v2 ticker | Best bid/ask, data timestamp; режим обновления bbo | Для production-оперативности предпочтительнее по свежести evidence. WS-соединение и подписку USDT/USD ещё проверяем в интеграционном spike |
| CoinGecko Simple Price | USD-оценка актива tether и last_updated_at | Demo API key, cache/plan/лимиты, attribution. Бесплатная месячная квота не подходит для опроса каждую минуту весь месяц |

Официальные основания: [Kraken REST Ticker](https://docs.kraken.com/api-reference/market-data/get-ticker-information), [Kraken WS ticker](https://docs.kraken.com/exchange/api-reference/spot-websocket-v2/ticker), [Kraken public rate limits](https://support.kraken.com/gb/articles/206548367-what-are-the-api-rate-limits-), [CoinGecko Demo Simple Price](https://docs.coingecko.com/demo/reference/simple-price), [CoinGecko pricing](https://www.coingecko.com/en/api/pricing), [CoinGecko API credits](https://support.coingecko.com/articles/1864417806-how-does-coingecko-api-count-the-api-usage-credit).

Read-only проверка [публичного Kraken запроса](https://api.kraken.com/0/public/Ticker?pair=USDTUSD) вернула error=[] и USDTZUSD с bid/ask/last. Это подтверждает доступность пары в момент проверки, не production-SLA, свежесть каждой сделки или вечную доступность из нашего будущего хостинга. Торговые запросы не выполнялись. CoinGecko key не создавался, успешный authenticated вызов не заявляется.

Запрос CoinGecko: `GET https://api.coingecko.com/api/v3/simple/price?ids=tether&vs_currencies=usd&include_last_updated_at=true`, ключ в `x-cg-demo-api-key`, только на сервере. Использовать ID tether, не неоднозначный поиск по символу.

На дату проверки Demo предусматривает 10 000 запросов/месяц. Один запрос в минуту — 43 200 за 30 дней; один каждые 5 минут — 8 640 за 30 дней или 8 928 за 31 день, без повторов и остальных потребителей. Поэтому бесплатный CoinGecko — периодическая сверка с резервом бюджета; более частая сверка требует подходящего плана. Месячный лимит/атрибуцию перепроверить перед подключением. Основной Kraken reader общий для всего проекта, не отдельный на пользователя/площадку.

CoinGecko агрегирует данные и может включать ту же биржу: это иной источник оценки, но не гарантированно независимое подтверждение. Не считать USDT/USDC или USDT/pUSD прямой USD-котировкой.

## 3. Котировка и проверка качества

Для Kraken предлагаемый price basis — midpoint `(bid + ask) / 2`, дополнительно сохранять bid/ask/spread и data timestamp. Midpoint — индикатор отклонения, не гарантированная цена исполнения/конвертации. Last trade не использовать как единственное доказательство текущей цены; WS-документация допускает давность last до 24 часов.

REST полученное время `fetched_at` не заменяет время рыночного события. При неизвестном source timestamp записать null/unknown, не выдумывать свежесть. До live проверить WS timestamp, heartbeat/reconnect/snapshot, доступность инструмента, spread, валидность bid/ask и adapter precision. Нет нового WS update не обязательно означает network outage: здоровье транспорта и свежесть цены — разные признаки.

`PriceObservation`: asset=USDT, quote=USD, source, pair/id, basis, price/bid/ask, source_time, fetched_at, freshness, spread, verification, adapter_version, policy_version, safe error. Decimal, не binary floating point для сравнения границ.

Ошибки/429/timeouts/нулевая или отрицательная цена/crossed book/устаревшее время/слишком широкий spread дают degraded/unknown. Недоступность API никогда не заменяется ценой $1. При расхождении источников выше настраиваемого допуска — отдельный source-disagreement, не молчаливое усреднение до «нормы».

## 4. Настройки в админке

Owner управляют версией `MarketDeviationPolicy`; просмотр и доставка доступны по соответствующим security/notification scopes. Конкретные числа — ручная настройка, изменение журналируется. Защитные пороги выплат из ADR-0043 — другая policy; их правила двух Owner не переносим автоматически на все ценовые поля.

| Поле | Назначение |
| --- | --- |
| warning_deviation_pct | Абсолютное отклонение от $1 для уведомления |
| confirm_duration / distinct_samples | Как долго/сколько различных свежих наблюдений подтверждают отклонение; один кешированный ответ не считается несколькими независимыми наблюдениями |
| evaluation_interval | Частота оценки; transport/read frequency и cache отдельно |
| max_price_age / max_spread | Допустимое качество котировки |
| source_disagreement_pct | Порог расхождения источников |
| recovery_deviation_pct + stable_duration | Условия возвращения цены к норме; recovery threshold ниже warning для защиты от постоянных переключений |
| reminder_interval / escalation | Частота повторного напоминания и повышение важности |
| recipients / channels | Два Owner и дополнительные действующие уполномоченные администраторы; проверенные каналы доставки |
| critical_deviation_pct / route_scope | Отдельный защитный gate денежных маршрутов по ADR-0043; не включается только потому, что сработал warning |

Validation: положительные интервалы/пороги, recovery < warning, critical не ниже warning, совместимость с source freshness/cache и доступной квотой, отсутствие пустых обязательных получателей. Threshold и подтверждение не имеют принятого численного default; пример 0,5% только объясняет расчёт, не утверждает настройку.

Формула: `signed_deviation_pct = (price_usd - 1) × 100`; `absolute_deviation_pct = abs(signed_deviation_pct)`. При пороге 0,5% цены $0,995 и $1,005 достигают границы. Сравнение `>=`, не изменение за последние 24 часа. Направление вверх/вниз отражать в сообщении.

Минимальный экран ADM-15 «Курс USDT/USD»: текущая рыночная цена, отклонение, исходные цены и время, здоровье источников, действующая версия/пороги, редактирование Owner, история сигналов, получатели и результат тестовой доставки. Общий источник для обеих площадок; scope блокировки маршрута отдельный. ADM-01 показывает важное предупреждение, ADM-10 — доставку, ADM-04 — инцидент, ADM-12 — изменения policy.

## 5. Когда и что уведомляем

Состояния: normal → pending_deviation → warning_open → price_recovered; отдельно source_unavailable/source_disagreement. Возвращение цены в норму закрывает рыночный сигнал после stable window, но **не снимает аварийную денежную блокировку автоматически**.

После подтверждённого превышения warning порога создаём один incident/event и задачи уведомления по получателям. Событие содержит цену, signed/absolute deviation, threshold, basis, источник/source time, длительность, подтверждение/расхождение вторым источником, policy version, incident link и состояние денежных маршрутов. Если CoinGecko unavailable, раннее предупреждение по валидному основному источнику допустимо с явной пометкой «без второй сверки»; не выдавать его за подтверждение двумя источниками.

Пример синтетического сообщения: «USDT/USD: $0,992; отклонение −0,8%, порог 0,5%. Источник Kraken, время …; проверка CoinGecko … . Денежные маршруты: … . Инцидент …». Адреса клиентов/секреты в сообщение не включаются.

В админке — обязательный устойчивый сигнал и notification center. Для оперативного получения предлагаем приватный admin Telegram-канал/чат и резервный email: это security-уведомления сотрудникам, не массовый клиентский маркетинг. Каналы и адресаты проверяются при настройке; нет уже запущенной рассылки. Неподключённый внешний канал явно обозначается и не считается доставленным; production требует проверенного оперативного канала.

Dedup key: asset + quote + rule + episode + recipient/channel; не отправлять сообщение каждую минуту. Напоминать по policy, уведомить о повышении важности, расхождении/потере источника и восстановлении. Acknowledge означает «администратор увидел», не устранение проблемы и не разрешение на платёж. Persistent outbox, retries/backoff, provider delivery IDs, sent/delivery_unknown/failed отдельно; timeout не доказывает, что сообщение не доставлено. Для каналов без idempotency возможный дубль при unknown явно учитывать.

Warning, critical monetary gate и source-quality guard — разные события. По ADR-0043 подтверждённое критическое отклонение блокирует только настроенные затронутые новые side effects; уже отправленные наблюдаются. При отсутствии обязательного валидного price check критический маршрут не объявляется healthy; до live политика деградации настроена и испытана. Снятие аварийного gate — Owner + независимый уполномоченный сотрудник; ручное закрытие notification не снимает gate.

## 6. Что проверить при разработке

Границы порога в обе стороны, отличия deviation от 24h change, длительность и distinct samples, hysteresis, один источник недоступен/оба недоступны, stale cached quotes, unknown timestamps, spread/disagreement, quota budget/429, смена policy при открытом episode, dedup/reminders/escalation/recovery, Telegram/email delivery_unknown, смена/отзыв получателя и отсутствие секретов. Убедиться, что ledger/прошлые обязательства не пересчитываются и обычная warning не включает рубильник сама.

До production измерить источник/доставку из выбранного региона хостинга, оформить разрешённое использование/attribution, проверить реальный WS и CoinGecko key/plan, настроить все численные параметры и пройти тестовую доставку. Исследование не заменяет эти испытания и не запускает постоянное наблюдение сегодня.
