# Проверка точной арифметики частей позиции

19.10.2026. Объект — [контракт 133](../../133_exact_position_arithmetic_contract_2026-10-19.md). Исходный main: `e2119dc92f541130f4353c9f4aa616e7f1ec176e`. Числа и денежные единицы в примерах synthetic; актуальные параметры площадок не запрашивались.

Запуск: `python3 docs/qa/exact-position-arithmetic-2026-10-19/reference_test.py`.

Результат: **16 тестов прошли**. Проверены:

- Внутренние пропорции 1/3 и 2/3 при целой сумме; неизменность суммы количеств/денег/расходов.
- Одинаковая итоговая атрибуция при перестановке двух уникальных fills и замене их одним фактом с теми же общими суммами, для одной фиксированной раскладки заявки.
- Ровно $10 освобождённой стоимости при трёх продажах из исходных 3 долей/$10; отсутствие повторного списания BUY-расхода через атрибуцию.
- Сохранение стоимости/расходов/денег при split/detach; совпадение суммарной стоимости при эквивалентном пропорциональном закрытии частей.
- Удержание выделения при cancel requested, снятие лишь неисполненного остатка при окончательном подтверждении; дедупликация, конфликт одинакового ID с другими фактами и конфликт fill после финальной отмены.
- Исполнение ранее отправленной продажи после смены режима на manual, без отрицательного долга цели.
- Перенос хвоста на примере 7.03 → 5.28 → 2.64, зачёт ручной продажи, отдельная история позднего и нового независимого BUY.
- Выделение автоматического SELL по требованиям частей без превышения каждого требования; точное сравнение стоимости с лимитом без скрытого округления; округление доказанной верхней денежной оценки вверх.
- Дополнительный точный перебор **484 сочетаний** начальных количеств 1–11, стоимостей 1–11 и четырёх долей: `0≤r≤q`, остаток долга меньше синтетического шага после продажи, стоимость сохранена.

## Предел доказательств

Это reference-модель арифметики на Python Fraction и локальных объектах. Она **не является кодом приложения** и не доказывает атомарность БД, отдельные исходы/tenant isolation, конкуренцию между разными выбранными группами, crash/restart, устойчивую очередь, реальный источник fill IDs/порядка, пригодность книги/комиссий или параметры/минимумы площадки. Модель принимает корректные исходные дроби; валидация production-wire/числовых границ требует отдельной реализации.

Некоторые тесты проверяют чистые алгебраические тождества с рациональным объёмом заявки; это не свидетельство, что такой ордер допустим на площадке. Все реальные общие размеры/fills и денежные движения должны проходить профиль единиц/шага/расходов из контракта до атрибуции. Память/производительность больших знаменателей и production-представление не измерялись; Python Fraction не является решением о стеке БД.

Прежний [пакет 132](../late-fill-sell-rounding-2026-10-19/README.md) сохраняется как историческая проверка предложенных floor/атомарных способов. Его прохождение не заставляет выбирать их для нового контракта.

После явных ответов владельца 19.10.2026 ADR-0055 и контракт 133 приняты в части точных внутренних долей и формулы переноса/зачёта. Это изменение статуса не расширяет охват reference-проверок и не подтверждает production-реализацию.
