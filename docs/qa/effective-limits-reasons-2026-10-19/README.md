Reference-модель проверяет **28 сценариев**: min для одинаковой квоты без повторного вычитания usage; отдельные остатки разных областей/временных окон; перестановки источников; равные binding sources; отсутствие optional против неизвестной mandatory policy; нулевой cap; неизвестный counter; primary/secondary для cash/position/day; давность/книга/fee/service/reconciliation; действия BUY против SELL; сохранение прошлого вердикта; несовместимые единицы; неизвестный размер; конфликт rule ID; точная граница; основной наиболее тесный остаток; минимум рынка; непроведённая проверка; неподходящая область; процент после доказанной нормализации; некорректный check.

Наблюдение 19.10.2026: все 28 reference-тестов прошли. Перебор всех шести порядков трёх правил сравнивает полный результат, не только основной code. Денежные проверки используют точные Fraction, не float. Сценарий «общий cap 100 / usage 95» выявляет ошибку простого min сырых потолков; пример «system 15/session 20/individual 12, usage 9» выявляет повторный вычет одного и того же резерва/использования.

## Пределы

Это pure reference-оценка переданных синтетических checks/rules/counters. `allowed_by_checks` означает только отсутствие препятствия **среди переданных и проверенных правил**, не разрешение создать реальную операцию. В частности, кейс SELL доказывает лишь неприменимость BUY-квоты к SELL; собственные SELL-правила/ликвидность/полномочия не реализованы.

Не проверены production-atomicity/CAS/concurrency, источник полного mandatory manifest/подлинность rule/counter, auth/tenant/scope isolation, нормализация currencies/процентных баз, event time/DST, реальные книга/minimum/fees, outbox/replay или UI. В модель уже переданы применимость и правильные единицы/суммы usage, включая резервы всех версий; она не доказывает их происхождение. Проверенно отсутствующий optional override задан явно и не моделирует сетевую ошибку получения политики.

Состояния новых решений здесь не заменяют жизненный цикл ранее отправленного unknown-ордера. Отсутствие нового допуска не освобождает его резерв. При неполноте/недостоверности данных production-система должна сохранять evidence и действовать по обязательным gates, а не считать сокращённую reference-модель полным исполнителем. Figma/приложение/live этой проверкой не меняются.
