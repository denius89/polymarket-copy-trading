## 4. Реестр

Приоритет относится к указанному этапу. «Высокий» на T4 не блокирует независимую подготовку V00. Ведущий отвечает за адресную правку; соседние чаты сверяют её. Закрытие — отдельная запись с новым Git SHA/Figma nodes и фактической проверкой.

### X01. Вход и второй фактор

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V01. Приоритет: высокий. Ведущий: UX + бэкенд.
- Фактически: Final mobile RU/EN пишет «2FA не нужна»; проверенные экраны подтверждения показывают email-код. UI117 всё ещё называет MFA/recovery невыбранными.
- Принятое правило / требование: Подключение TOTP добровольно, но после подключения он обязателен при новом входе. Полный login подтверждается Q01; email-код сам по себе не открывает защищённый draft.
- Исправление / следующий шаг: Уточнить текст и карту состояний email → TOTP/renew → подтверждённый вход; добавить управление фактором, потерю устройства и unknown. Проверить четыре варианта. Не утверждаем отсутствие любых TOTP-кадров во всём файле: проверен конкретный маршрут.
- Критерий закрытия: RU/EN mobile/desktop и handoff дают одинаковый путь с/без TOTP, ошибкой и восстановлением; переход до полного login исключён.
- Источники: [Auth policy](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/auth-policy.md#L79); [Auth API](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/backend-auth-contracts-addendum.md#L97); [UI117](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/117_user_interface_technical_specification_2026-10-09.md#L106); [RU email](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2532-9419); [EN email](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2532-14764).
- Происхождение: UI-01, BE-X04.

### X02. Минимум бюджета $50 вместо $100

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V02–V04. Приоритет: высокий. Ведущий: UX.
- Фактически: Профиль трейдера RU/EN mobile показывает «Бюджет запуска от 50,00 $ / $50.00».
- Принятое правило / требование: ADR-0058 устанавливает минимум бюджета $100.
- Исправление / следующий шаг: Согласовать подпись и связанные состояния с минимумом $100. Не придумывать отдельный смысл $50.
- Критерий закрытия: Во всех четырёх версиях нет обещания запуска с бюджетом ниже принятого минимума; ошибки формы ссылаются на ту же policy.
- Источники: [ADR-0058](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/decisions/0058_paper_mvp_numeric_settings_policy.md#L9); [RU профиль](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2498-28378); [EN профиль](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2502-19420).

### X03. Полный каталог и демонстрационная статистика шире Q02

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V02. Приоритет: высокий. Ведущий: UX + бэкенд + API + скор.
- Фактически: UI117 обещает фильтры, score, период и поиск адреса; RU каталог показывает обе площадки, 24 результата и отбор. Профиль с пометкой «демо-данные» содержит +$5,48, 12 закрытых сделок и 14 «моих копий». Эти поля не приходят из Q02 и не относятся к новой пустой сессии.
- Принятое правило / требование: Q02 первого среза выдаёт разрешённые синтетические identity/source/availability одной площадки за запрос, фиксированный порядок traderId; без score, доходности, поиска и клиентской сортировки.
- Исправление / следующий шаг: Связать V02 с отдельным точным набором состояний. Недоступные фильтры не представлять работающими; иллюстративные результаты оставить отдельным примером. Если нужен общий показ двух площадок — явно описать два независимых запроса, частичный отказ и границы пагинации, не расширять Q02 молча.
- Критерий закрытия: Каждое показанное поле и действие сопоставлено Q02 либо явно отделённому примеру; нет score:0 и вымышленного торгового результата.
- Источники: [Q02](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/backend-api-forms-addendum.md#L396); [UI117](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/117_user_interface_technical_specification_2026-10-09.md#L110); [Каталог](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2532-20141); [Профиль](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2498-28378).
- Происхождение: UI-03/04, BE-X03, S01, API-04.

### X05. Повтор команды и неизвестный запуск

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V03–V05. Приоритет: высокий. Ведущий: UX + бэкенд.
- Фактически: UI117 обобщает повторы изменяющих команд; Final показывает «Запускаем демо», а handoff прямо оставляет pending/unknown и полную матрицу ошибок открытыми.
- Принятое правило / требование: Q05 восстанавливает C04/C06. Для C06 сохраняются исходные ключ и payload; неизвестный C05 допускает отдельную явную новую проверку и не создаёт CommandReceipt. Auth/claim имеют свои протоколы.
- Исправление / следующий шаг: Таблица действий для каждой операции и конкретные состояния ожидания, unknown, проверки результата, отказа. Timeout не переводить в подтверждённый успех.
- Критерий закрытия: Все ветви связаны с контрактами; повтор C06 не создаёт второй запуск, C05 не попадает в Q05. Доказательство в runtime — позднее.
- Источники: [Повторы](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/backend-contracts.md#L196); [UI117](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/117_user_interface_technical_specification_2026-10-09.md#L297); [Открытые состояния](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/design/client/final-handoff-2026-10-18.md#L34); [Запуск](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=2498-29000).

### X06. Пустой запуск не обещает подключённое копирование

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V05. Приоритет: средний. Ведущий: UX + бэкенд.
- Фактически: UI117 описывает ожидание допустимого сигнала, что без оговорки обещает действующее копирование.
- Принятое правило / требование: Первый срез сохраняет copying_not_connected / EMPTY / no_trade_data и показывает предупреждение на проверке.
- Исправление / следующий шаг: Назвать пустую демо-сессию и неподключённое копирование явно. Не заменять её автоматически готовым активным примером.
- Критерий закрытия: Проверка и главная одинаково объясняют отсутствие копирования; нулевые суммы следуют сохранённому snapshot.

### X07. Админка подставляет первую сессию вместо отсутствующей

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V06. Приоритет: высокий. Ведущий: Админка + бэкенд + БД.
- Фактически: Учебный HTML app.js:22–23 при неизвестном ID подставляет первого пользователя/первую сессию. Макет 3971:5 показывает демонстрационную S-DEMO-002 с операциями.

- Исправление / следующий шаг: Убрать fallback из учебного сценария; связать состояния с Q06. Списки операций/событий требуют отдельных разрешённых данных, их нельзя выдумывать из пустой сессии.

### X08. Восстановление владельцев отстало от принятого D02

- Статус: **исправлено в Figma/документах; runtime не проверен**. [Повторная сверка](corrections.md). Этап: V01 / recovery. Приоритет: высокий. Ведущий: Админка + бэкенд.
- Фактически: Макет 4028:175 и access-recovery.js:40 ведут потерю доступа обоими во внешнее восстановление даже при наличии кодов. README учебного single-маршрута не показывает независимое согласие второго владельца.
- Принятое правило / требование: Single требует отдельного approver. Pair с сохранёнными личными кодами — общий версионированный case, ограниченные новые credentials и подтверждения обоих. Нет нужного кода — отдельный незакрытый emergency.
- Исправление / следующий шаг: Перенести поздние single/pair правила в экраны и учебный маршрут. Два ключа одного человека не заменяют согласие другого владельца.
- Критерий закрытия: Обе ветки показывают участников, ожидание, версию, ограничения и подтверждения; emergency не обходит закрытый доступ.
- Источники: [Учебная логика](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/design/admin/rebuild/prototype/access-recovery.js#L40); [Маршрут](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/design/admin/rebuild/access-recovery/README.md#L9); [D02](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/backend-auth-d02-contracts.md#L181); [Политика §18](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/auth-policy.md); [Макет](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=4028-175).

- Фактически: UI117:123 оставляет численные ограничения открытыми; начало API-forms оставляет Q06 права/аудит открытыми, хотя поздние разделы их приняли.
- Принятое правило / требование: Действуют ADR-0058/политика130 и поздние Q06 §§13–14.
- Исправление / следующий шаг: Пометить старые формулировки историческими, поставить ссылки на действующие правила. Развести возраст сигнала30с и пригодность книги2с; минимум fixed$5 не минимум каждой покупки.
- Критерий закрытия: Читатель получает один актуальный ответ без повторного согласования.
- Источники: [UI117](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/117_user_interface_technical_specification_2026-10-09.md#L123); [Политика130](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/130_paper_copy_settings_numeric_policy_proposal_2026-10-18.md#L12); [API-forms](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/backend-api-forms-addendum.md#L13); [Q06](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/technical/first-session/database-q06-absence-design.md).
- Происхождение: ADM-X04, API-05.

### X11. Устаревший или отозванный скор во время пересчёта

- Статус: **открыто**. Этап: До публичного скора. Приоритет: высокий; решение открыто. Ведущий: Скор + админка + UX + владелец.
- Фактически: Пакет09 сохраняет прежнюю публикацию до новой; ADR0011 требует актуальных данных. Приоритет устаревания/отзыва явно не задан.
- Принятое правило / требование: Нельзя показывать утратившее пригодность число как актуальный результат.
- Исправление / следующий шаг: Рекомендация: прежний балл остаётся только пока пригоден и не отозван; иначе статус без числа одновременно в карточке и каталоге. Ручной поиск и существующие сессии сохраняются, проверки исполнения независимы. Это предложение ещё не принято.
- Критерий закрытия: Владелец принимает точное правило; публикация и UI проверены на пересчёт/сбой/устаревание/отзыв.
- Источники: [Пакет09](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/design/admin/package-09/data-rating-contract.md#L33); [ADR0011](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/decisions/0011_shadow_controls_rating_admin_and_ui_foundation.md#L41).
- Происхождение: S02.

### X12. Исследование, демонстрационный рейтинг и отчёт сессии — разные сущности

- Статус: **открыто**. Этап: До расчёта/публикации скора и отчётов. Приоритет: высокий; будущая зависимость. Ведущий: Скор + API + БД + админка.
- Фактически: Демо R-1/R-2 и исследовательский shrinkage не имеют принятого перехода в публичный0–100. Карточка публикации4200:1138 показывает синтетические версии. Оценка сессии14дней и минимальная история трейдера30дней могут быть смешаны в передаче.
- Принятое правило / требование: Рамка и веса30/25/25/20 приняты; конкретная формула и её доказательства ещё нет. Недостаточность≠0; история трейдера, версия данных/методики/публикации и отчёт сессии различаются.
- Исправление / следующий шаг: Разделить нормативную рамку, примеры и кандидаты. Задать provenance/версии и критерии проверки формулы; законченная14-дневная сессия не даёт автоматический допуск к рейтингу. Не менять веса и не публиковать ручной балл.
- Критерий закрытия: Методика с независимой проверкой принята отдельно; UX/API показывают периоды и достаточность каждого объекта, без смешения.
- Источники: [Пакет09](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/design/admin/package-09/data-rating-contract.md#L39); [Кандидат](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/research/trader-score-accelerated-2026-10-18/CANDIDATE_DECISION.md#L3); [14 дней](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/decisions/0050_shadow_assessment_boundary_and_exit_only_tail.md); [ADR0011](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/decisions/0011_shadow_controls_rating_admin_and_ui_foundation.md#L41); [Публикация](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=4200-1138).
- Происхождение: S03/S04, ADM-X03; не противоречие принятой формулы.

### X13. Polymarket: дата отключения Data API v1 и accounting

- Статус: **открыто**. Этап: T4 / данные скора. Приоритет: высокий. Ведущий: API + скор.
- Фактически: Справочник указывает24.10 и исключение accounting; актуальная миграция указывает02.11.2026 и прекращение /v1/accounting/snapshot без эквивалентаv2.
- Принятое правило / требование: Нельзя строить загрузку на документированно прекращённом экспорте. Data API v2 не тождествен Trading Protocol V2.
- Исправление / следующий шаг: Обновить датированный справочник; v2/trades и v2/activity рассматривать отдельно с проверкой полноты cashflows. Документированный full_history=True SDK — кандидат, а не гарантия полноты. Не использовать transaction_hash как уникальный fillID.
- Критерий закрытия: План загрузки не зависит от старого fallback, фиксирует SDK/wire/coverage/cursor и условия недостаточных данных.
- Источники: [Старый справочник](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/api/polymarket/public-data.md#L9); [Миграция](https://docs.polymarket.com/migrate/data-api-v1-to-v2); [Analytics](https://docs.polymarket.com/market-data/public-analytics).
- Происхождение: API-01/02; прочитана документация, отключение запросом не наблюдалось.

### X14. Limitless: авторизованный feed и публичные события перепутаны

- Статус: **открыто**. Этап: Limitless T4. Приоритет: средний. Ведущий: API + бэкенд.
- Фактически: Справочник помещает get-feed-events среди публичных GET; текущая страница требует JWT.
- Принятое правило / требование: Публичный /events — отдельный маршрут с MINED CLOB-сделками, taker-семантикой и необязательным профилем; не полный поток выбранного лидера.
- Исправление / следующий шаг: Развести маршруты и доступ; токен Shadow не считать токеном Limitless.
- Критерий закрытия: У каждого источника указаны права, охват и ограничения атрибуции; реальная полнота проверяется отдельно.
- Источники: [Справочник](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/api/limitless/public-data.md#L5); [Feed](https://docs.limitless.exchange/api-reference/markets/feed-events); [Events](https://docs.limitless.exchange/api-reference/trading/market-events).
- Происхождение: API-03.

### X15. Свежесть, комиссия и полный сигнал ещё не доказаны

- Статус: **открыто**. Этап: T4 / допуск профиля. Приоритет: блокер активации; не V00. Ведущий: API + бэкенд + БД + скор.
- Фактически: Старые записи подтверждают ограниченные наблюдения, но не точность часов издателя/полноту произвольного лидера/все расходы. Legacy SDK использовал rank.feeRateBps/fallback300; текущий signing требует effectiveFeeRateBps владельца. Точная legacy-кривая не доказана.
- Принятое правило / требование: ADR0059 требует свежесть2с, fetch1с, ошибку часов≤250мс и применимые расходы конкретного профиля. Успешное соединение, receive time или нулевая подписанная ставка этого не доказывают.
- Исправление / следующий шаг: Сохранить закрытый допуск профилей. Для каждой площадки/семейства отдельно связать IDs, время наблюдения, gaps, книгу, fees, условное исполнение и свой учёт. COLLATERAL проверять отдельно через gross/fee/net; в админке разделить связь/свежесть/полноту/допуск.
- Критерий закрытия: Независимые доказательства времени, восстановления, комиссий/settlement и полноты, затем отдельное решение активации. Paper по реальным сигналам и live не разрешаются этой сверкой.
- Источники: [ADR0059](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/decisions/0059_clob_market_profiles_freshness_price_and_fees.md); [Аудит137](https://github.com/denius89/polymarket-copy-trading/blob/d04a796/docs/137_profile_activation_audit_2026-10-19.md); [Signing](https://docs.limitless.exchange/developers/eip712-signing#field-reference); [Fees](https://docs.limitless.exchange/user-guide/fees#reading-the-exact-fee-programmatically); [COLLATERAL](https://docs.limitless.exchange/developers/migrate-to-new-trading-venues#fees-in-order-results); [PM WS](https://docs.polymarket.com/market-data/realtime-data); [Limitless REST](https://docs.limitless.exchange/api-reference/trading/orderbook#snapshot-and-price-freshness); [Limitless WS](https://docs.limitless.exchange/developers/websocket/market-data#orderbookupdate).
- Происхождение: S05, API-06/07; незакрытые доказательства, не новый продуктовый выбор.

## 5. Исторический порядок после исходного аудита

X01–X10 выполнены последующим пакетом; текущий следующий шаг — пункт4 ниже. Списки1–3 сохранены для связи с исходным поручением.

1. X01/X08/X09: вход и восстановление в клиенте/админке по уже принятым правилам.
2. X02–X06/X10: бюджет, каталог, форма, ошибки/unknown, честный пустой запуск и актуальный handoff.
3. X07: одна сессия в клиенте/админке, права и состояния отсутствия; адресный Present-проход затронутых RU/EN mobile/desktop.
4. Профиль Oracle: реальная доступность ресурса, исполнители/доступы, внешние evidence/backup/ключи. Не устанавливать компоненты до отдельного поручения V00.
5. V00 по D03/D04 с доказательствами; затем V01–V07 по карте. X11–X15 — перед соответствующими score/API/T4 этапами. Не приписывать V00 проверку всех будущих возможностей.

Для X01–X10 новые продуктовые решения не нужны: синхронизируются существующие принятые правила. X11 — рекомендация к будущему решению владельца. X12/X15 — ещё не полученные методологические/технические доказательства. Потеря необходимого резервного кода остаётся отдельным G01; ни этот отчёт, ни AP-01–06 не разрешают аварийный обход.
