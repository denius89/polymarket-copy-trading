Меняются Figma, карты экранов, тексты передачи и документация. Код приложений, HTML/JS учебных прототипов, SQL, сервер и API не меняются. Действующим источником соответствующего сценария становится исправленный Figma и точный контракт. X11–X15 не закрываются.

## Повторная проверка

**Структура Figma.** Прочитаны четыре email-gate,84 Auth-кадра и их границы: содержимое новых кадров не выходит за нижний край. Повторно прочитаны четыре пары fixed/% и четыре профиля, четыре launch-корня и восемь кнопок запуска; проверены переходы к review и отсутствие установки созданной сессии до учебного подтверждённого ответа. Чтение реакций и макетные переменные не являются реальными проверками прав.

**Клики в Present, выполненные ведущим:**

- RU mobile: каталог → настройка; TOTP → потеря устройства → заявка на рассмотрении; ожидание запуска → unknown после окна ожидания → ручное чтение → отдельно выбранный подтверждённый учебный ответ → EMPTY с200 доступно/0 резерв/0 позиции и неподключённым копированием.
- EN mobile: защита выключена → свежий email → подключение → защита включена → отдельный email/TOTP для отключения → новый email-вход → проверка Q01 → первый каталог. Пройден конкретный подготовленный успешный ответ, не ввод/доставка реальных кодов.
- RU desktop: согласие на claim → подтверждённый перенос → явный новый C05 → review fixed200/20, отдельная кнопка запуска и предупреждение COPYING_NOT_CONNECTED. Также просмотрен профиль с минимумом100.
- EN desktop: истечение challenge → renew → снова TOTP; профиль с минимумом100. Дополнительно пройден каталог → fixed →3% → review → email →Q01 → явный claim → новый review с сохранёнными3% → отдельный запуск → учебный expired → новая проверка с3%. Обратное переключение3% → fixed20 →3% сохранило оба подготовленных значения. Каталог просмотрен в Present — шапка и содержимое не перекрываются; EMPTY осмотрен на снимке, карты связей прочитаны.
- Админка: текущая сессия → ограниченные денежные группы; отдельный сценарий отсутствующей текущей сессии. Pair recovery: два отдельных кода/ключа → одна версия → подтверждение A → ожидание B при закрытом рабочем доступе → подтверждение B → отдельное завершение. Ветка без кода оставляет доступ закрытым. Профиль → «Мои сеансы»: один текущий вход, отдельная история.

**Визуальная проверка.** Снимки каталогов, CATALOG_CHANGED, EMPTY и Auth в [evidence](evidence/), X05 mobileRU/desktopEN и админский пакет проверены. Новые формы используют существующие Inter-стили и кнопки. Полный обход всех экранов/ошибок, все языковые варианты админки и свободное редактирование значений не заявляются.

**Независимая проверка.** Бэкенд не нашёл противоречий в новом Auth-handoff. В X05 исправлены два замечания: HTTP200 C05 может содержать отрицательный review; окончательный отказ C06 следует разрешённому nextAction, а не всегда ведёт к настройкам. БД подтвердила S01/AP09-соответствие; displayName текущего каталога Q02 отделён от сохранённого summary.traderDisplayName.
