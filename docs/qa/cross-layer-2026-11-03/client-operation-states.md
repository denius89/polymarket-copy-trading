# X05 · Исход сохранения, проверки и запуска

03.11.2026 · Клиентский Figma первого сценария. [Карта узлов](client-operation-states.json).

| Действие | Видимое состояние | Следующий шаг |
| --- | --- | --- |
| Сохранение настроек C04 | Ожидание и неизвестный исход показаны отдельно от окончательного отказа | При неизвестном исходе прочитать результат исходной операции через Q05. Подтверждённое сохранение открывает явную проверку настроек. |
| Проверка настроек C05 | Ответ проверки не подтверждён либо прежняя проверка устарела | Пользователь явно запускает новую проверку. HTTP 200 показывает новый review в сохранённом режиме fixed/%. При `allowedToStart=true` доступно отдельное подтверждение запуска. При `allowedToStart=false` показываются причины и разрешённое следующее действие из `nextAction` и `nextActionParams`. |
| Запуск C06 | Ожидание, неизвестный исход и окончательный отказ имеют разные состояния | При неизвестном исходе прочитать статус исходного запуска. Следующий шаг при окончательном отказе задаёт ответ. Подготовленный пример показывает разрешённый возврат к настройкам. При мешающей текущей сессии разрешённый `view_session` или `view_summary` открывает соответствующий объект по `nextActionParams`. Подготовленный учебный успех открывает сохранённую пустую сессию. |

Q05 начинает чтение сразу после обнаружения неизвестного результата C04/C06. Одновременно выполняется одно чтение, каждое до 5 секунд. Следующие интервалы после завершения чтения — 1, 2, 5 и далее 10 секунд. Автоматическое окно длится до 30 секунд. Новое чтение начинается только при достаточном остатке для полного 5-секундного бюджета. Затем доступна ручная проверка исходного запроса. Ключ операции и область доступа сохраняются. Для C05 пользователь явно запрашивает новую проверку с новым review; Q05 и обычный receipt к C05 не применяются.

В Figma основная карточка показывает состояние операции и доступное действие пользователя. Для демонстрации развилок откройте отдельный блок «Проверка макета» / «Prototype checks» внизу карточки. По умолчанию он свёрнут. Кнопки внутри подставляют учебный ответ и сворачивают блок. Таймер ожидания показывает переход к ручной проверке после 30 секунд. Сетевой поллинг и длительность отдельных чтений задаются контрактом для будущей реализации.

Для прохода откройте существующую проверку fixed или %. Явный запуск ведёт в прежний кадр ожидания. Откройте «Проверка макета» и выберите неизвестный исход, затем нажмите «Проверить статус запуска». В состоянии чтения снова откройте блок проверки макета и выберите неизвестный результат или подготовленный учебный ответ об успехе исходной операции. Для устаревшей проверки и потерянного ответа самой проверки выберите «Проверить настройки заново». Должна открыться проверка текущего режима с отдельной кнопкой запуска, если новый review разрешает старт.

Для C04 в блоке проверки макета выберите учебное ожидание сохранения, неизвестный исход и ручную проверку статуса. Подтверждение сохраняет исходный черновик и открывает явный переход к проверке настроек. Конкретный учебный окончательный отказ возвращает к настройкам; общая реализация следует разрешённому nextAction ответа.

Проверены реакции четырёх корней и восьми кнопок запуска на fixed/% review. Таймер 30 секунд меняет состояние без навигации к сессии. Ручные проверки сохранения и запуска не меняют флаг сохранённого черновика и не запускают новую команду. Ветка первого входа на экран ожидания сохраняет режим, не выставляет аккаунту статус созданной сессии и не очищает черновик. Подтверждённый учебный результат открывает существующий EMPTY; неизвестный C05 и устаревший review ведут только в существующие кадры проверки. Результаты чтения реакций записаны в карте. Снимки показывают отрисовку ожидания. Полный проход кликами в Present в этой проверке не проводился.
