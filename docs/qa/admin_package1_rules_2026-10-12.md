# Первый пакет админки — проверка правил для дизайна

Дата: 12.10.2026. Область: оболочка, ADM-01, ADM-02, ADM-03; RU/EN. Это чеклист и синтетические примеры для дизайн-пакета, не отчёт о проверке созданных фреймов и не новые продуктовые решения.

Источники: [115](../115_admin_console_technical_specification_2026-10-09.md), [118](../118_admin_console_figma_design_brief_2026-10-09.md), [119](../119_admin_security_review_changes_2026-10-12.md), [120](../120_usdt_usd_sources_and_admin_alerts_2026-10-12.md); ADR-0029/0031/0039/0043 и торговые ADR-0014–0028. Текущее поручение основателя разрешает начать Figma пакетами; более старое «дизайн не начинался» в ROADMAP — историческое состояние, не новое ограничение.

## Оболочка и доступ

- Постоянно видимы среда, demo/live, площадка, язык, профиль сотрудника и состояние ограничений. Demo и production не различаются только цветом.
- Owner — системная роль двух персональных сотрудников. Operations объединяет поддержку/операции; Auditor, Marketer, Ops Lead — изменяемые пресеты или кастомные роли, не дополнительные неизменяемые системные роли.
- Раздел без view-права скрыт. Deep link без права — отдельный отказ. Недоступное действие на разрешённом экране объясняет состояние; секреты и запрещённые сведения не раскрываются даже в tooltip/search/summary.
- Права действуют по среде, площадке и классу данных. Разрешение читать пользователя не открывает автоматически его деньги/обращения/связанные сущности. Export — отдельное право, не часть просмотра.
- Поиск по разрешённым ID: результат, пустой результат, нет прав. Нельзя через сообщения об отказе раскрывать существование чужих staff-аккаунтов.
- Истёкшая/отозванная staff-сессия, отсутствие доступа, общий сбой загрузки. Не добавлять саморегистрацию сотрудников.
- Возврат сохраняет фильтры и позицию списка. Переключение контекста закрывает либо требует отменить текущую форму; подтверждение не переезжает в другую среду.
- Ссылка в последующие ADM-пакеты не должна быть мёртвой: обозначенный экран следующего пакета с возвратом и пояснением. Он не объявляется реализованным разделом.

## ADM-01 — обзор

- Сводка: активные сессии, инциденты, очередь, актуальность, ограничения. Счётчик открывает соответствующий список с перенесёнными фильтрами.
- Обе площадки: подключение, последнее подтверждённое обновление и конкретные проблемы. Рабочий публичный каталог не означает готовность торгового исполнения/вывода.
- Три разных состояния: подтверждённый ноль; источник не подключён; данные неизвестны/устарели. Нельзя суммировать доступный фрагмент и подписывать как полный итог.
- Денежные агрегаты только при нужном scope. Бюджеты пользователей не являются поступлениями сервиса. В demo реальные поступления/партнёрские обязательства не выдумываются.
- Требует внимания: тип, важность, площадка, время, ответственный, переход. Для unknown — ссылка на инцидент/сверку, не «повторить перевод».
- USDT/USD: важное отклонение, источник/время; отдельные stale/unknown/source-disagreement. Отсутствующий timestamp не заменяется временем запроса. Warning не активирует route stop автоматически. Порог — Owner-настройка без выдуманного production default. Внутренний учёт 1 USDT = $1 не меняется.
- Applied ограничения отдельно от запрошенных: недошедший ack показывается как неполное применение/неизвестно, не «проект отключён».

## ADM-02 — пользователи и VIP

- Список: разрешённый ID, создание, язык, площадки, статус, VIP, активные сессии. Фильтры ID/площадка/VIP/статус/период; пустой фильтр отличается от отсутствия пользователей.
- Деталь: разрешённый контекст, подключения без секретов, сессии, обращения, применимые условия, история изменений. Ссылки ограничены своими scopes.
- VIP назначает, меняет и завершает только Owner. Кастомное право/название роли этого не обходят. Другой Owner не должен утверждать обычный пользовательский VIP.
- Форма: существующий версионированный профиль либо разрешённые индивидуальные параметры; начало, окончание или бессрочно, причина; preview до/после и применимая версия.
- Состояния: нет VIP, будущий, активный, завершённый/истёкший; validation, конфликт overrides, конкурентное изменение, повторный просмотр, сохранение, подтверждённый результат.
- Применимость назначения и итоговый тариф показаны отдельно. В alpha действующая service fee = 0%; VIP не должен обещать изменение 1% → 0,5% как текущий рабочий тариф. Числа paid-этапа показывать лишь в отдельно обозначенном сценарии будущей настройки.
- VIP пользователя не означает partner VIP и не даёт обход risk/emergency/venue gates. Снятие/истечение не пересчитывает историю; влияет только по effective contract.
- UTC `[from,to)` в технической аннотации; в форме понятная явная зона времени. Нет неоднозначного «завтра» без точной даты.

## ADM-03 — сессии и команды

- Список: ID, пользователь, площадка, трейдер, demo/live, состояние, причины ограничений, последнее событие; фильтры по тем же признакам и периоду.
- Деталь: settings/version, бюджет и резервы при разрешённом доступе, позиции, ордера, активность, принятые/пропущенные сигналы и причины; связанные тикеты/инциденты.
- Настройки/сделки/баланс не редактируются вручную. Не добавлять покупку, продажу, вывод, impersonation или универсальное «закрыть всё» от имени пользователя.
- `session.pause`, `session.resume_demo`, `session.disconnect_demo` проверяются отдельно. Operations не получает право live submit/close; resume снимает только разрешённую demo-паузу.
- Отдельные причины: user pause, risk pause, venue restriction, GLOBAL_STOP/TECH_MODE. Снятие одной не снимает остальные. Кнопка resume не является аварийным recovery и не восстанавливает risk pause без соответствующего domain-условия.
- Pause: выбор конкретной сессии/области, понятное последствие, подтверждение, команда принята, применение подтверждено/неизвестно/отказ. Указаны actor/reason/time. Повторный клик не создаёт дубли.
- Обычная пауза запрещает новые BUY/увеличения. Она не равна глобальному stop; наблюдение/сверка сохраняются. Допустимые сокращения риска по user-правилам не включаются автоматически при аварии.
- Resume при другой оставшейся блокировке показывает «пауза снята, копирование остаётся ограничено: …», а не зелёное «активна». Ранее пропущенные BUY не догоняются.
- Disconnect demo: запрос → обработка → подтверждённое завершение. Это тот же domain workflow, не удаление данных/позиций. Поведение завершения при открытых позициях пока BL-05–08; не изобретать автоматическую ликвидацию. Прототип успеха допустим для fixture без позиций и незавершённых ордеров.
- Partial order fill допустим: исполненная часть сохранена, остаток ожидает отмены; pending reserve удерживается. Late fill до подтверждения отмены учитывается. Не использовать правило «нет частичных выплат» для торгового ордера.
- Unknown order удерживает подтверждённые необходимые резервы и запрещает рискованное повторение; неизвестная цена/расход отображается «нет данных», не 0.
- Fresh demo = одна активная сессия, пустая история. При нехватке полной суммы/глубины новая BUY пропускается целиком; размер не обрезается до остатка. Daily reset имеет зону сессии, unresolved reserve переносится.

## Синтетические данные для согласованного прототипа

Все ниже — отдельные учебные fixtures с явной отметкой «Пример / Sample», без рабочих адресов/ключей и без заявления о фактических событиях проекта. Не копировать fixtures в историю новой реальной/demo-сессии.

| --- | --- | --- |
| Owner | Owner 1 и Owner 2, отдельные identity | Owner-only VIP; отсутствие второго approval для обычного VIP |
| Operations | users.view_minimal, operations.view, session.pause/resume_demo/disconnect_demo; без finance aggregate | Скрытие денег сервиса и VIP-действий; разрешённые demo-команды |
| Auditor | read-only subset; без export | Нет действий и автоматического экспорта |
| Fresh demo | U-DEMO-001, S-DEMO-001, Limitless, RU, бюджет $200; reserve $0; исполненные покупки $0; позиции/история пусты; fee 0% | Подтверждённые нули, первая сессия без нарисованных сделок |
| Active sample | U-DEMO-002, S-DEMO-002, Polymarket, EN, выделено $200; свободно $160, резерв BUY $20, исполненные расходы BUY $20; fee 0%; цена позиции неизвестна | $160+$20+$20=$200 по cash-allocation fixture; не equity/P&L, не доход сервиса |
| Multi restriction | S-DEMO-002: demo-пауза + venue restriction; снятие разрешённой паузы оставляет venue restriction | Независимость причин; нет ложного resume success |

| VIP | U-DEMO-001, profile Demo VIP v1, start 12.10.2026 12:00 UTC, indefinite, причина «Тест интерфейса»; base/effective fee 0% | VIP active не создаёт paid fee в alpha; будущий вариант start 13.10.2026 12:00 UTC |
| Freshness | Полное обновление 12.10.2026 12:00 UTC; отсутствующий source timestamp = «Время не предоставлено» | Stale и неизвестность не подменяются живыми данными |

Число активных сессий fixture: до завершения S-DEMO-001 — 2 существующих активных жизненных цикла, из них состояние копирования S-DEMO-002 ограничено. Если карточка называется «Копируют сейчас», это другое определение: не подставлять число 2. После подтверждённого завершения S-DEMO-001 счётчик существующих активных demo-сессий — 1. Не суммировать demo бюджеты в реальные финансы.

Для отдельного макета USDT warning разрешён учебный пример $0,994 = −0,6%, со словами «Учебное правило», без объявленного production threshold. В основном demo обзоре безопаснее показывать «Мониторинг не подключён», а warning разместить отдельным состоянием.

## Минимальные маршруты проверки RU/EN

1. Обзор → счётчик → отфильтрованный список сессий → деталь → назад с сохранёнными фильтрами.
2. Пользователи → деталь → Owner VIP форма → preview → save → подтверждённая версия; затем изменить/завершить.
3. Operations → пользователь: VIP read при scope или скрыт; назначение недоступно, денежные данные сервиса отсутствуют.
4. Session pause → pending → applied; неизвестный результат → ссылка на проверку без blind retry.
5. Resume разрешённой demo-паузы при venue restriction → ограничение остаётся.
6. Disconnect пустой demo → pending → confirmed; назад в список, история сохранена.
7. Active partial-fill fixture → отмена остатка ожидается/unknown → сохраняется fill/reserve, нет «повторить BUY».
8. Revoked staff session → повторный вход; deep link без scope → отказ; не происходит повтор команды.
9. Обзор: обе площадки и health unknown; USDT sample warning/unknown → обозначенный ADM-15/04 маршрут с возвратом, если следующий пакет ещё не готов.
10. VIP conflict/version changed → обновлённый preview; не сохранять устаревшую версию.

## Граница проверки

Приёмка нового пакета требует структурного и визуального evidence, проверки destinations и прохода Present; этот документ не подтверждает их выполнение. Общий fallback/state component допустим вместо множества экранов, но каждый значимый маршрут должен иметь рабочую destination и обратный переход. Реестр GitHub должен различать созданное/проверенное/ещё не покрытое; пользовательские RU/EN mobile/desktop не считаются автоматически обновлёнными этим admin-пакетом.
