## Поддержка

Новые экраны не создавались. Использован существующий общий сценарий поддержки, который не привязан к случайной сделке:

- RU: `673:412` → `714:970` → `714:1029` → `714:1088` → `714:1137` → `714:1188` → `714:1247`;
- EN: `671:412` → `714:1536` → `714:1595` → `714:1654` → `714:1703` → `714:1754` → `714:1813`.

Это кликабельная демонстрация состояний. Figma не отправляет письмо и не создаёт настоящее обращение.

## Проверка

- Через Figma MCP повторно прочитаны изменённые подписи, родительские кнопки и назначения переходов.
- Получены и просмотрены рендеры восьми затронутых композиций: onboarding, профиль трейдера, главная с подготовленным примером и список обращений на RU/EN.
- На рендерах нет обрезки новых подписей, наложений или сломанного auto layout.
- Дублирующие CTA удалены только после сравнения их назначений.
- Реакции возврата к списку трейдеров сохранены.
- Короткие подписи «Трейдеры» / Traders повторно проверены на RU/EN рендерах без обрезки и нарушения компоновки.
- После удаления ошибочного переключателя пустая главная RU/EN содержит только действие изменения лимитов. Отдельные launcher-кнопки «Активное демо» / Active demo по-прежнему устанавливают SessionStage `active` и открывают `905:9074` / `905:9713`.
- Кнопки создания обращения ведут в существующие blank-формы с переходом до подтверждения отправки.

Ручной Present этой итерации не выполнен: Computer Use не получил разрешение на управление приложением Figma. Структурная проверка реакций и визуальные рендеры не заменяют человеческий проход прототипа. Следующий контроль — пройти desktop RU/EN в Present и получить подтверждение коллеги; бизнес-аудит, админка, frontend и API этим отчётом не запускаются.
