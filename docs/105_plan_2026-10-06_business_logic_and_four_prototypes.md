# План на 6 октября 2026 · бизнес-логика и 4 прототипа

## Результат дня

1. **Один файл с бизнес-логикой MVP** — `docs/MVP_BUSINESS_LOGIC.md`. Это понятная продуктовая спецификация демо-копирования для основателя, дизайнера и разработчика. Она собирает согласованные правила из [рабочего документа 100](100_paper_copy_business_logic_working_draft_2026-10-05.md) и [ADR](decisions/README.md), отделяет ещё открытые вопросы и не выдаёт нарисованные варианты за принятые решения.
2. **Четыре отдельные кликабельные версии в Figma:** mobile RU, mobile EN, desktop RU, desktop EN. Для каждой — собственная ссылка запуска в Present, связный основной путь и подготовленный пример активного демо. Все четыре доступны с [одного стартового листа](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=3-2).

## Порядок работы

### 1. Собрать единый файл бизнес-логики

- Свести в один порядок: путь пользователя, сущности и денежные определения; выбор фиксированной суммы или процента от сделки трейдера (3% по умолчанию); условия допуска и пропуска; порядок сигналов; дневной лимит и полночь зоны сессии; резерв покупки и возможных расходов; цену, ликвидность, частичное исполнение, отмену остатка; продажу и закрытие позиции; статусы и данные, которые показывает интерфейс.
- Для каждого правила отметить **«согласовано»** со ссылкой на ADR либо **«открыто»** с конкретным вопросом. В первую очередь сохранить открытыми незакрытые части BL-05/BL-06 и BL-07/BL-08 из [документа 100](100_paper_copy_business_logic_working_draft_2026-10-05.md): точный учёт частей позиции, пороги цены и свежести книги, модель расходов, завершение сессии и сочетание лимитов.
- Добавить короткие числовые примеры на бюджете $200 и таблицу «событие → проверка → статус → что видит пользователь». Сверить формулировки с [экраном настройки размера копии](101_copy_size_mode_figma_and_logic_2026-10-05.md), [частичным исполнением](102_partial_fill_and_remainder_visibility_2026-10-05.md) и [источниками цены/расходов](103_paper_price_liquidity_fee_evidence_2026-10-05.md).
- Проверить, что файл не содержит противоречий с действующими ADR и не обещает реальные сделки в paper-MVP. Открытые вопросы оставить явно отмеченными, если за день не будет решения владельца продукта.

### 2. Собрать четыре прототипа

- Зафиксировать стартовый экран и отдельную ссылку Present для каждой комбинации устройства и языка. Сохранить [«Начать здесь»](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=3-2) общей точкой входа, а [карту экранов](https://www.figma.com/design/lxPP2um7FvIbt02K8eeH4T?node-id=1664-2) — схемой маршрутов.
- Для каждой версии пройти и соединить **первый запуск**: знакомство/сторис → каталог → профиль трейдера → настройка копирования → проверка → запуск → новая пустая демо-сессия. На desktop вместо сторис — обзорный экран.
- Отдельно в каждой версии проверить вход в **подготовленное активное демо**: главная → рынки/трейдеры → позиции и заявки → события и история копирования → средства и отчёт → помощь и профиль. Подготовленный пример не должен выглядеть автоматическим продолжением новой пустой сессии.
- Исправить разрывы переходов, неверные «Назад», клики в архивные экраны и переходы между RU/EN или mobile/desktop. Для действий, которые ещё не работают в прототипе, показать понятное состояние вместо немого клика.

### 3. Приёмка и передача

- В Present вручную пройти оба маршрута на всех четырёх версиях. Проверить кликабельность основных действий, условные ветки после проверки настроек, возврат из деталей и ключевые состояния ожидания/пропуска/ошибки. Сверить текст и числа с единым файлом бизнес-логики.
- Выдать четыре прямые ссылки Present и одну ссылку на стартовый лист. К каждой версии приложить короткий статус: **пройдено / найденные разрывы / исправлено / оставшийся открытый вопрос**. Не объявлять прототип готовым только потому, что все кадры существуют.

## Критерий готовности

Владелец проекта может открыть любой из четырёх прототипов по прямой ссылке, пройти первый запуск и подготовленное демо без выхода на другой язык, устройство или архивный экран. В `docs/MVP_BUSINESS_LOGIC.md` для каждого существенного решения виден его статус и источник; неопределённости названы прямо.
