Набор предназначен для последующей разработки Mobile/Desktop RU/EN. Это нативные Figma-компоненты, экземпляры, variables и styles, а не картинка с каталогом элементов.

## Происхождение дизайна

Набор основан на четырёх текущих пользовательских страницах: Mobile RU `33:2`, Mobile EN `29:2`, Desktop RU `205:2`, Desktop EN `186:2`. Совместимые существующие токены, стили и masters переиспользованы; отдельная конкурирующая визуальная система не создавалась.

Правила и границы взяты из [стандарта 41](41_product_design_and_frontend_standards.md), [исправлений 113](113_button_copy_and_reaction_fixes_2026-10-06.md) и [технической спецификации 117](117_user_interface_technical_specification_2026-10-09.md). Короткие пользовательские подписи сохраняют смысл. EN/RU — содержимое общего компонента, а не разные реализации финансовой логики.

Существующие элементы служат визуальной основой. Добавленные presentation states закрывают потребности будущей разработки; не означают, что соответствующий серверный сценарий реализован или новый бизнес-процесс утверждён.

## Содержание набора

- Foundations: семантические цветовые токены, текстовые роли и правила применения визуальных основ.
- Controls: существующие кнопки/поля/переключатели, дополнительные checkbox/select/textarea/segment/nav/link, иконки, icon button и spinner.
- Data: status/venue/mode badges, денежные значения и freshness, metric/account/trader/record/session/rules cards, адрес, пагинация и каркас графика.
- Patterns: alert/state panels, подтверждения и receipts, funds breakdown, Copy Ticket, support/feedback, публичные сообщения, меню/фильтр/строка таблицы и onboarding.

Иконки имеют нативную геометрию; элементы данных — редактируемые текстовые слои. Составные паттерны используют экземпляры компонентов. Review board показывает применение, а не новую страницу продукта.

## Свойства и варианты

Общие текстовые свойства создаются только для одинакового содержимого во всех соответствующих вариантах. Состояния с разным смыслом сохраняют собственную подпись: unknown не получает известную сумму, pending не превращается в confirmed, ошибка не заменяется обычным helper text.

RU/EN поддерживаются через доступные text properties и overrides. Уникальный текст состояния переводится в его контексте; не нужно detach экземпляра. Числа, единицы и смысл действия сохраняются при замене языка.

Варианты управления включают применимые default, hover, focus, pressed, disabled, loading и error-представления. Не каждый компонент обязан иметь каждый вариант: статус данных и состояние кнопки — разные сущности. Loading icon button использует отдельный фиксированный spinner, независимый от общего icon swap.

Визуальная доступность не равна серверному разрешению. Причину запрета задаёт действующая capability/policy, а UI показывает её понятным текстом.

## Финансовая семантика

Набор сохраняет принятые различия:

- Requested/accepted — принятие запроса; confirmed — подтверждённый результат.
- Unknown/pending не превращаются в failed после timeout; повторное исполнение не предлагается как обычный retry.
- Недоступная сумма не равна нулю; stale значение сопровождается признаком свежести.
- Частичное исполнение показывает исполненную часть и остаток; резерв не является расходом.
- Фиксированная сумма и процент относятся к размеру копируемой BUY; процент считается от BUY трейдера, не от бюджета пользователя.
- Передача позиции в ручное управление не означает продажу.
- Подготовленный пример отделён от собственной новой EMPTY-сессии.

Суммы и проценты в экземплярах — демонстрационные данные. Они не задают тарифы, численные диапазоны или системные defaults. Generic segmented control не утверждает дополнительные risk-профили. Alpha-комиссия и остальные правила остаются в действующей бизнес-логике.

Code Connect не создавался: реализованных frontend-компонентов пока нет. Связь дизайна с кодом станет отдельной задачей после появления реализации.

## Проверка и ограничения

При подготовке исправлены обнаруженные проблемы компонентов: высота/наложение рядов, применение общего text default к разным состояниям, ширина вложенных support/feedback полей, подмена loading-иконки общим icon swap.

Окончательные структурные assertions и visual QA фиксируются в [qa.json](../design/client-ui-kit/qa.json). При незавершённом экспорте или проверке этот отчёт не заменяет результат QA и не объявляет проверку пройденной. Наличие компонента не доказывает пригодность всех его комбинаций для каждого экрана.

Визуальная проверка UI kit отдельно от пользовательской приёмки прототипов. Ручной Present в этой задаче не выполнялся. Работоспособность исходных продуктовых переходов заново не заявляется.

## Дальнейшее применение

Использовать kit в новых или отдельно порученных изменениях. Массовая миграция существующих экранов не проводилась и автоматически не требуется. При будущей замене проверять текст, размеры, состояния и переходы на Mobile/Desktop RU/EN.

Открытые вопросы спецификации 117 сохранены для этапа программирования по решению основателя. UI kit не закрывает их случайными текстами/числами макета. Реальные отправки поддержки, trading/funding, signer, API-регистрации и live остаются за отдельными поручениями и gates.
