# ADR-0068. Разделение сбора и копирования в закрытом демо Polygon

24.11.2026. Решение ограничено проверкой Polymarket в закрытом демо.

Четыре компонента получают разные обязанности. Сборщик один раз читает подтверждённые диапазоны Polygon для отслеживаемого адреса и атомарно фиксирует блоки и курсор в локальном SQLite. Обработчик трейдера читает диапазоны по порядку и отмечает покупки в существующей очереди PostgreSQL. У каждой подписанной сессии своё задание на то же исполнение. После потери ответа обработчик перечитывает подтверждённый курсор PostgreSQL.

Отдельный процесс книг открывает одну подписку на нужный рынок и фиксирует один снимок для сигнала. Для пилота он согласует окно двух заранее заданных получателей и использует исходное время площадки и получения. Данные передаются через закрытый Unix-сокет. Смена состояния книги, повтор запроса после истечения времени или неверная идентичность приводят к отказу. Синхронизация с фиксированной парой ограничена пилотом: общий рынок и подтверждение сигнала следует подготавливать централизованно, чтобы масштабировать копирование без ожидания каждого подписчика.

Компонент копирования читает те же блоки из SQLite с правом на чтение и обрабатывает задания в отдельных экземплярах для двух сессий. Каждый рассчитывает свою покупку по общей книге и применяет собственные лимиты. Существующая транзакция сохраняет исполнение, позицию и движение демо-баланса, включая запись в «Активности». В приёмке сравниваются оба сохранённых снимка книги, возраст книги и соответствие одной покупке и одному списанию в каждой сессии.

Для этой схемы применяются отдельный [обработчик трейдера](../../tools/demo-signal-delivery/closed_polygon_trader.py), [приём диапазонов](../../tools/demo-signal-delivery/closed_polygon_ingress.py) и [сервис книг](../../tools/demo-signal-delivery/closed_shared_polygon_book.py). Подключение Limitless, динамический список адресов и выпуск на основной стенд требуют отдельной приёмки.
