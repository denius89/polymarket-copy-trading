# ADR-0007: Limitless как первая интеграция

Дата: 25.09.2026. Статус: принято в части первого партнёрского spike; опциональность Polymarket заменена ADR-0008.

## Контекст

Изначально первым кандидатом был Polymarket, а Limitless рассматривался как второй adapter. После read-only аудита команда Limitless дала проекту полное добро и обещала поддержку. Официальный Programmatic API содержит отдельный flow для платформ: partner sub-accounts, scoped HMAC tokens и delegated signing.

Для регистрации предоставлена обязательная партнёрская ссылка `https://limitless.exchange/?r=FutureHaus`. По сообщению основателя, она даёт будущие преимущества и скидку 10% на комиссии; точные условия скидки ещё нужно получить письменно.

## Решение

- Limitless становится первой площадкой для интеграционных spikes и кандидатом на первый execution adapter.
- Аккаунт проекта регистрируется только через ссылку FutureHaus до подачи заявки на Programmatic API.
- Первый запрос scopes: `trading`, `account_creation`, `delegated_signing`.
- Scope `withdrawal` не выдаётся execution worker и не входит в первый торговый spike.
- Polymarket исследуется параллельно и обязательно входит в целевой продукт по ADR-0008.
- MVP, реальные пользовательские сделки и публичный запуск остаются заблокированы действующими gates.
- Партнёрское одобрение не заменяет проверку GEO, Terms, контроля средств, recovery, latency, liquidity и экономики.

## Почему

Limitless предоставляет более прямой платформенный путь для автоматической торговли от имени связанных sub-accounts и обещает интеграционную поддержку. Это снижает риск недоступности API и ускоряет техническую проверку. Оно не устраняет риски managed wallet, delegated signing и переменных taker fees.

## Последствия

- Документы и презентация должны называть Limitless первым партнёрским spike, а Polymarket и Limitless — двумя обязательными площадками продукта.
- Ближайший технический пакет строится вокруг Programmatic API, HMAC secrets, server-wallet trust boundaries и безопасного withdrawal path.
- Экономика должна учитывать фактические Limitless fees и отдельно показывать сценарий с неподтверждённой 10% скидкой.
- ADR-0001 остаётся действующим в разделении ролей Polyfox и execution-площадок, но его порядок площадок заменён этим ADR.
- Подробный checklist находится в `docs/20_limitless_partner_integration.md`.
