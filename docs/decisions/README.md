# Архитектурные решения

[ADR-0063](0063_supabase_user_auth_provider.md) — принято 27.10.2026: Supabase Auth для входа пользователей. Запрошен второй фактор; [почтовый сервис, лимиты кодов и область TOTP](../technical/first-session/auth-policy.md) пока предложения. Предметный допуск Supabase/Mailgun открыт из-за условий по wagering; выбор региона не снимает AUP. Staff/Owner вход отдельно, код и подключение сервисов не выполняются.

[ADR-0062](0062_paper_first_modular_backend_and_first_slice.md) — принято 27.10.2026: paper-first, модульный TypeScript/PostgreSQL сервер, первый общий сценарий клиента/админки. [Схема/команды/приёмка](../technical/first-session/README.md) — подготовленный проект T0; код и миграции не поручены. ADR-0042 принят только в соответствующей части.

[ADR-0043](0043_admin_money_security_and_incident_recovery.md) — принято 12.10.2026: protected recipient/пороги, independent money recovery, PARTNER_PAYOUTS_OFF, isolation/compromise, funding lifecycle, audit integrity и безопасный restart. Уточняет ADR-0030/0031/0032/0037/0040/0041; обычные выплаты/тарифы не получают обязательного второго подтверждения.

[ADR-0013](0013_consolidated_ux_and_risk_boundaries.md): принятые уточнения первого входа, сводок, средств и управления. Формулы/пороги финансовой автопаузы остаются предложением.

[ADR-0014](0014_fixed_paper_copy_size_and_settings_scope.md): фиксированная сумма новой копии в первом paper-сценарии, сохранённые ограничения ADR-0012 и ясная область настроек.

[ADR-0015](0015_repeat_buy_signals_in_paper_copy.md): повторная самостоятельная покупка того же исхода проверяется и копируется, если хватает действующих лимитов.

[ADR-0016](0016_proportional_trader_exits_in_paper_copy.md): частичный выход трейдера пропорционально сокращает отслеживаемую виртуальную позицию; полный выход закрывает её.

[ADR-0017](0017_copy_size_fixed_or_percent_of_trader_trade.md): для новых покупок пользователь выбирает фиксированную сумму или процент от суммы конкретной сделки трейдера.

[ADR-0018](0018_skip_buy_when_full_copy_exceeds_limits.md): если полная желаемая сумма новой покупки не помещается в действующие лимиты, сигнал пропускается с причиной без автоматического уменьшения суммы.

[ADR-0019](0019_daily_buy_limit_resets_at_session_local_midnight.md): дневной лимит новых paper-покупок обновляется в местную полночь часового пояса, закреплённого за сессией.

[ADR-0020](0020_carry_unresolved_buy_reserve_across_daily_reset.md): резерв покупки с неизвестным итогом сохраняется после полуночи до сверки и временно уменьшает доступный лимит нового дня.

[ADR-0021](0021_reserve_pending_buy_in_budget_and_position_limit.md): ожидающая покупка удерживает сумму также в свободном бюджете и лимите позиции до подтверждения итога.

[ADR-0022](0022_reserve_expected_copy_expenses_in_paper_budget.md): бюджет резервируется на сумму paper-покупки вместе с возможными списываемыми виртуальными расходами.

[ADR-0023](0023_process_competing_paper_buy_signals_in_arrival_order.md): конкурирующие покупки рассматриваются по порядку поступления; проверка и резерв не дают дважды использовать один лимит.

[ADR-0024](0024_show_missing_market_data_without_simulated_fill.md): при недостатке свежей цены или данных о ликвидности действие трейдера видно, но фиктивная копия и результат не создаются.

[ADR-0025](0025_skip_buy_when_verified_liquidity_cannot_cover_full_copy.md): если подтверждённой ликвидности по допустимой цене не хватает на полную копию, новая покупка пропускается целиком.

[ADR-0026](0026_keep_confirmed_partial_fill_and_cancel_remainder.md): если уже начатая покупка исполнена лишь частично, подтверждённую часть сохраняем, остаток отменяем и показываем его резерв до подтверждения отмены.

[ADR-0027](0027_reconcile_fills_while_remainder_cancellation_is_pending.md): подтверждённое исполнение во время отмены увеличивает позицию и уменьшает остаток; полное исполнение показывается как «отмена не успела».

[ADR-0028](0028_paper_quote_depth_and_expense_evidence.md): цену paper-копии проверяем по полной глубине книги в момент решения, расходы — по применимому доказуемому тарифу; неизвестные данные не заменяем нулём.

[ADR-0029](0029_configurable_admin_roles_and_unified_operations.md): Owner остаётся встроенным, Operations объединяет операции и поддержку, остальные доступы задаются кастомными ролями и изменяемыми пресетами.

## Как добавить решение

1. Использовать следующий номер и короткое имя файла.
2. Указать дату и один из статусов: `предложено`, `принято`, `заменено`, `отклонено`.
3. Описать контекст, решение, причины, последствия и способ проверки.
4. Добавить строку в эту таблицу и ссылку из тематического документа.
5. Если новый ADR заменяет старый, обновить статус обоих документов без удаления истории.
