# ADR-0067: интерфейсы Shadow и доставка на тестовый полигон

Дата: 04.11.2026. Статус: **стек принят; реализация, интеграция и развёртывание поручены; готовность не подтверждена**.

## Основание

Владелец принял предложение React + TypeScript + Vite, Tailwind CSS и общего UI-kit по текущей Figma, двух приложений user/admin в одном репозитории, адаптивного клиента mobile/desktop и словарей RU/EN.

Прямой ответ: «Да, согласуем этот стек. Запускай реализацию всех интерфейсов по плану, подключай к бэку и разворачивай на полигоне. Двигайтесь дальше сами, ко мне только важные вопросы».

Первоисточник: административный чат `01a0ce2b-2536-7242-924b-75a454d26e56`, userMessage `01a1a860-969d-7fe1-84ea-323f2f0f9a90`, turn `01a1a860-960a-7602-9e9e-63e3715ee1cd`. Источник прочитан непосредственно 04.11.2026. [Индекс разрешений](../CURRENT_AUTHORIZATIONS.md) не заменяет это прямое сообщение.

## Решение

- React и TypeScript — реализация пользовательских и административных интерфейсов.
- Vite — сборка обоих приложений. Проверенные static build-артефакты размещаются на существующем Oracle; dev server не используется как постоянная раздача.
- Tailwind CSS и собственный UI-kit — реализация согласованных компонентов и токенов Figma. Библиотечные defaults не заменяют утверждённый дизайн.
- `apps/web` — адаптивный клиент, mobile/desktop, RU/EN; `apps/admin` — админка с отдельной аутентификацией и серверными полномочиями; `packages/ui` — общие визуальные компоненты и токены.
- Общий репозиторий и совместимые контракты не означают общий доступ к секретам или право клиента принимать решения о полномочиях. Скрытая кнопка не является проверкой доступа.
- Точные версии зависимостей и вспомогательные библиотеки фиксирует ведущий фронтенда после проверки совместимости и актуальных официальных источников. В репозитории сохраняется lockfile; каждую обычную библиотеку повторно согласовывать с владельцем не требуется.
- Модульный TypeScript-бэкенд и PostgreSQL из ADR-0062 сохраняются. Проверочные адаптеры V00 и HTML-прототипы не объявляются готовым продуктовым API/фронтендом.

## Объём и порядок

Весь утверждённый клиентский интерфейс и админка реализуются по актуальным живым картам, с состояниями, переходами и API-интеграцией. Сначала общий UI-kit и сквозной сценарий, затем остальные принятые маршруты. Проверенный первый сценарий не закрывает все интерфейсы.

Реализация включает необходимые принятые контракты API/хранения, их адресные проверки и развёртывание совместимых пакетов на закрытом полигоне. Непринятые правила не придумываются из макетов. Старый режим подготовки документов не запрещает новое явно порученное исполнение; разрешение не является свидетельством успешной приёмки V01–V07.

План, распределение участков и критерии — в [плане реализации](../technical/frontend/README.md).

## Сохраняющиеся ограничения

- Только закрытый тестовый полигон, синтетические аккаунты/данные и внутренняя тестовая почта, без новых расходов. Публичный запуск не поручен.
- Реальные деньги, торговые подписи, переводы, live-исполнение и новые внешние доступы не включаются.
- Отдельное решение «Пока только модель, перенос закрыт» для D03-08 сохраняется: фактический guest claim/P04 выключен. Описанная модель не подменяет внешнее доказательство или работающую операцию.
- Закрытый P04 влияет также на применимые защищённые операции вне claim. Разрешение UI/API-кода не разрешает активировать C04/C05/C06/Q06 без требуемого контроля. Узкий испытательный профиль Auth не приравнивается к выполнению общих гарантий; недостающая предпосылка выносится владельцу с конкретным перечнем зависимых действий.
- Синтетический user не становится staff/owner. Неподдержанный API не возвращает фиктивный успех. Разрешённая синтетическая витрина явно помечается и отделяется от рабочего API.
- Ключи и секреты не попадают в браузер, исходники, публичные артефакты или логи. Неподтверждённая операция отображается как неизвестный исход по действующему контракту.
- Персональный доступ второго владельца отложен по его ответу «давай это оставим на потом» на запрос публичного SSH-ключа. Это не блокирует реализацию и не разрешает использовать общий ключ.
- Автоматические отказы приложения не обходятся. После проверки нового прямого основания допустима предметная повторная попытка; при неустранимом отказе сохраняется точный блокер.

## Критерий результата

Для каждого маршрута различаются вёрстка, API-интеграция, проверка в браузере и фактическая установка. Экран готов, когда сверены дизайн/адаптивность/язык, переходы, loading/empty/error/unknown и разрешённые действия, реальный API и серверные права, а проверенная версия установлена на полигоне. Отсутствующий backend не скрывается за статусом «готово».

Для всей поставки нужны карта полного покрытия, проверка четырёх клиентских вариантов и админки, изоляция аккаунтов, проверенные перезапуск и восстановление, инструкция доступа и точный список оставшихся закрытых возможностей.
