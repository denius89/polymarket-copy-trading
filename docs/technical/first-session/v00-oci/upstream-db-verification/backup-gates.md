# Backup evidence: что требуется сейчас и до допуска следующих функций

04.11.2026. Сверка документов БД, без действий на сервере. Исходный baseline `41123ec`;
обновление main `373bf2a` / PR238 прочитано перед сохранением.
Ни продуктовые правила, ни назначения хранителей этим документом не меняются.

По [серверному срезу PR238](../v00-exit-checklist.md) один шифротекст уже загружен
и виден в приватном OCI бакете. Это именно synthetic PITR упражнение, без установленного
Auth и нового bridge. Обратное чтение, сравнение и restore из скачанного объекта
ещё открыты; загрузка не переименовывается в подтверждённое восстановление.

**Текущее поручение владельца прямо включает внешнюю доставку копии/WAL и восстановление
из неё.** Это обязательный результат текущего блока V00. Отдельно паспорт D03 §5
задаёт V01→D03-04–10/12, а полный D03-13/14 относит к V07. Поэтому нельзя молча
превратить все будущие финансовые restore-cases или уже накопленные семь дней истории
в новое предварительное условие изолированного user V01. Это вывод из указанной карты
зависимостей, не снятие требований резервирования или разрешение V01.

Прежний кандидат размещения на Mac не делает личный Mac обязательной площадкой:
владелец выбрал Oracle, а текущий внешний получатель — приватное OCI хранилище.

Второй ключ по поручению владельца отложен. Это не доказательство независимой custody
и не разрешение записать двух проверяющих из предположения. Отсутствующие IAM/ключ/
получатель/защищённый канал блокируют только зависящую от них проверку; точный вопрос
консолидирует ведущий серверный чат. Общий запрет «всё остановлено» и повторное
разрешение V00 не требуются.

Этот перечень не объявляет весь D03-13 выполненным и не разрешает переносить его
необходимые restore-гарантии «на потом», когда открывается именно восстановленный
Auth. Для текущего upstream V00 сервер ведёт итоговую таблицу фактов/остатка, а БД
проверяет новые safe source/restored snapshots и полноту связей после их получения.
