# Остаток V00 и условия допуска V01

04.11.2026. Исходный срез `41123ecb0586679facbd036dca43b3747e7f4b80`. Объём продолжения указан в [действующих разрешениях](../../../CURRENT_AUTHORIZATIONS.md). Раздел 5 [паспорта D03](../backend-auth-d03-validation-passport.md) связывает V01 с D03-04–10/12. Это допуск конкретных операций, поэтому результаты для пользовательского, административного и восстановленного пути фиксируются раздельно.

## Более поздние этапы и условия открытия восстановленной среды

| Источник | Что проверяется и когда |
| --- | --- |
| D03-01–03, паспорт §§3/5 | На V00 подтвердить применимый набор fixtures, строгий транспорт, миграции/права и независимые транзакционные барьеры для выбранных путей. Остальной manifest78 и контрактные проверки V02–V05 предъявляются на соответствующих операциях. Тестовые версии нескольких схем не подтверждают весь каталог. |
| D03-11, паспорт §5 | Полные scope/catalog и audit проверки Q02/Q04/Q06 на V02/V06, включая владельцев и смену ревизии. |
| D03-13, D03-14, паспорт §5 | На V07 подтвердить полный внешний restore/evidence и сквозной user/admin UI, Auth, БД и аудит одной версии, включая observer C06. Ежедневные и последние семь успешных внешних копий относятся к эксплуатационной политике. |
| D03-12/13, operations §5 | До любого открытия восстановленной среды подтвердить доверенный внешний head/epoch, сплошную WAL цепь, stale grants/proofs и каждый unresolved исход после точки копии. Изолированный PITR упражнения не даёт разрешения на reopening. |

Итог допуска V01 выставляется отдельно после сверки применимого набора доказательств. Копия упражнения содержит только синтетический PITR набор, без базы установленного Auth.
