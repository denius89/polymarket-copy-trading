# Работа с Oracle и закрытым демо

Применять вместе с [реестром разрешений](../../../CURRENT_AUTHORIZATIONS.md) и [доказательствами V00](README.md). Этот порядок ведения работ не меняет допуски.

## Выпуск и восстановление

Для каждого сервиса или сборщика оператор фиксирует среду, проверенную версию, Git-коммит или хеш пакета и место хранения проверенной копии. Если связи между установленным пакетом и исходниками нет, явно указать пробел. Поручение на выпуск уточняет целевую среду и пакет. В записи выпуска сохранить резервную копию, проверки после установки, условие отката и фактический результат. Для восстановления указывать дату и охват подтверждённого прогона.

## Диагностика

Ведущий и оператор используют одну запись инцидента. В ней указаны среда, версия, время, обезличенная сессия, последняя подтверждённая отметка, состояние процесса и исход записи в БД. При неизвестном исходе сверить состояние до повтора операции. Отдельно проверять, как интерфейс показывает остановленный процесс и устаревшее наблюдение. Сырые закрытые свидетельства сохранять по действующему порядку, в журнал добавлять ссылку и безопасное резюме.

Для тайм-аутов сохранения диапазонов и остановки измерять задержку и число проверок истории при одинаковом объёме данных. Начинать с изолированной среды. Проверять атомарность, повторы, целостность истории и согласованность балансов. Различать локальные измерения и наблюдения на Oracle. Для ожидания события указать источник подтверждения, критерий успеха, ответственного и момент окончания ожидания.

## Веб-приёмка

Для сценариев интерфейса применять только встроенный браузер ChatGPT. Фиксировать версию приложения, среду, пройденный сценарий и наблюдение. БД и API подтверждают отдельную часть результата. Один общий итог включает обе проверки, если сценарий их требует.
