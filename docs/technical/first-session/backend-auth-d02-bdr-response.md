## 1. Основа и статус

P01–P05/U01–U03 приняты; собственная схема **78 = 36 Shadow + 42 Auth**. D02/v6 остаётся проектом, текущий принятый реестр v5. Передача БД сверяется с поздней прямой человеческой инструкцией о принятии U01–U03; прежнее межчатовое расхождение статуса снято и не переоткрывается.

Ни одно BDR не объявлено закрытым автором исправления: статус всех строк — **«исправление подготовлено, ожидает повторной вычитки БД»**. Ниже адреса итоговой редакции, а не прежние номера строк baseline. Исходный лист замечаний и история ADR не переписаны.

## 3. Решения владельца и рекомендация

**Для внесённых исправлений изменение принятых P01–P05/U01–U03 не требуется:** старый TOTP ответ сохранён, таблицы/колонки/unique не добавлены, evidence не ослаблен, нового исключения witness нет. Реализация не разрешена. Дополнительная точность новых форматов/маршрутов/аудита остаётся частью будущего **единого принятия D02/v6 после повторной вычитки**, а не автоматически принятой этим ответом.

Отдельное возможное расширение — поддержать самостоятельный security incident через новый AC41 purpose=security_incident. Оно потребовало бы: draft=NULL; closed gate и новая epoch/run одной T; полный inventory всех исполнителей/dispatch; доказанный drain/outcome; отдельное проверенное инфраструктурное разрешение reopening; точные audit/witness наборы. Это изменение принятого AC41 и операционного протокола, **не включено в исправления**.

**Рекомендация:** сейчас оставить incident reserved и завершить сверку текущего D02. Включение отдельного incident run согласовать с владельцем вместе с операционным паспортом D03/H06; не выбирать его за пользователя ради заполнения enum. Точно так же добавление отдельного root для непотреблённого bootstrap handle/manifest, если оно понадобится будущей политике физического удаления, требует адресной дельты и решения, а не обхода P04.

## 4. Повторная сверка и доказательства

Просьба БД проверить по каждому BDR исправление, источник и контрпример; особенно: K/P при совпадающем UUID и отсутствии AC05, source_case_version после pair, AC33 reset actor=approver, все result refs/NULL, границу W01–W05/W06–W10, неподдерживаемый incident, late reenroll при независимом block и точные bytes трёх source proofs. При новом замечании назвать конкретную строку/вариант; решение о закрытии — результат повторной вычитки.

Для будущего manifest перечисляются все 78 таблиц, а не дополнительные 5 totals. AS/HR/HE должны применять уточнённые варианты, включая нулевые **неприменимые** AC33 pair и обязательные ненулевые proof chains, lawful до-case NULL и полный recovery-registration комплект. Неизвестный обязательный parent/closure остаётся ошибкой, не нулём.
