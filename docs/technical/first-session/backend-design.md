## 2. Уже принятые инварианты

- Один текущий paper-слот пользователя для Polymarket и Limitless вместе; locale и новое устройство не создают другой слот.
- Несколько независимых черновиков; версия ввода, историческое владение и признак использования — разные понятия.
- Review, settings, финансовая история и snapshot неизменяемы. Версия формата не является версией ресурса.
- C06 одной транзакцией сохраняет сессию, settings, initial funding, журнал и две проводки, snapshot, окончательный receipt/details, аудит, outbox, слот и отметку used исходного draft.
- Исходные draft и review используются для запуска не более одного раза по всей истории.
- Funding поясняет проводки, не зачисляет бюджет второй раз. При старте free=equity=B, reserved/positionCost/positionValue/tradingResult=0; торговая история пуста.
- Пользователь и администратор читают один сохранённый snapshot с теми же ID/version/asOf. Чтение его не пересчитывает.
- Постоянный пользователь отличается от login и paper-сессии. Владелец 1 и владелец 2 — два равноправных staff-участника с личными входами.
- Истёкший draft/review не удаляет durable receipt. Неизвестный исход не означает отказ или разрешение нового ключа.
- Существующая физическая спецификация содержит 34 прикладные таблицы. Дополнение C04 частично отражено принятыми физическими блоками 1–2 (scope/result/details/last_input_receipt_id); target/FK/post-claim блок 3 предложен. Этот пакет не выдаёт его за принятое или испытанное.

## 3. Серверные модули и границы

Модульный TypeScript-бэкенд, отдельные API и worker, одна PostgreSQL с раздельными служебными схемами/правами Auth и Shadow. Сохраняется [ADR-0062](../../decisions/0062_paper_first_modular_backend_and_first_slice.md); все компоненты полного BaaS автоматически не подключаются.

| Модуль | Ответственность | Основные данные |
| --- | --- | --- |
| User Auth | Email/TOTP, доверенная identity, полный login, сроки/отзыв/восстановление | users, user_auth_identities, auth_sessions, login policies; закрытое хранилище Auth |
| Staff Auth | Личный passkey, служебный login/slot, bootstrap и recovery | staff_principals, staff_auth_identities, staff_login_slots; хранилище credentials/challenges |
| Staff Access | Действующие назначения, целые области grants, разрешённые группы ответа | staff_assignments, staff_assignment_grants, audit_authorizations |
| Catalog & Policy | Обе площадки, происхождение, revisions, опубликованные правила и текущий допуск | venues, catalog_sources, traders/revisions, paper policies/controls |
| Setup Drafts | C04, текущий ввод/version/TTL, guest proof и claim | setup_drafts, draft_ownerships, draft_claim_receipts |
| Setup Review | C05, неизменяемый результат и копия проверенного ввода | setup_reviews |
| Paper Start | C06, повторный допуск и весь atomic start | slot/session/settings/funding/journal/entries/snapshot |
| Command Results | Область ключа, fingerprint, окончательный исход и Q05 | command_keys, command_receipts, command_receipt_details |
| Session Reads | Q04/Q06, согласованные settings/snapshot, аудит выдачи | paper_sessions, session_snapshots, settings_revisions, audit |
| Local Observer | Обработка сохранённого факта старта | outbox_events, consumer_event_receipts |
| Compatibility & Recovery | Полный обход форматов, безопасные отчёты, backup/WAL и сверка | Изолированные копии и защищённые внешние пакеты доказательств |

API устанавливает actor/realm/environment, проверяет формат и выполняет предметную команду. БД независимо защищает связи, уникальность, полноту и атомарность. Worker не становится вторым создателем сессии/финансирования. Ни пользовательский браузер, ни административный экран не получают прямую запись в прикладные таблицы.

## 4. Путь первого сценария

1. Каталог и гостевой черновик могут предшествовать входу. C01–C03 подтверждают identity; подключённый TOTP обязателен для полного user-входа.
2. При гостевом продолжении выполняется доказанный claim. Старый guest review остаётся историческим; после входа нужен новый C05.
3. C04 сохраняет ввод и устойчивый результат. C05 читает согласованное состояние и сохраняет собственный review, но не создаёт слот/сессию.
4. Явный C06 проверяет актуальный допуск и сохраняет весь комплект. После commit отвечает 201; потерянный ответ восстанавливается через тот же ключ.
5. Q04 читает сохранённый снимок. Q06 получает тот же снимок в разрешённой проекции и сохраняет аудит до успешной выдачи.
6. Worker независимо подтверждает наблюдение стартового факта. Его задержка не отменяет commit C06.

После входа показывается собственная текущая/блокирующая сессия; при её отсутствии продолжается доступный draft либо открывается предусмотренный каталог/итог. Вход не запускает и не возобновляет копирование. Невосстановленный черновик на другом устройстве не подменяется вымышленным.

## 5. Статус H01–H06

| Зависимость | Что согласовано документально | Что остаётся до подтверждения реализации |
| --- | --- | --- |
| H01 | Контуры, привязка, cookies/CSRF, guest/claim, сроки и принятый recovery | Конкретный Auth-комплект, одноразовость, обход прямых маршрутов, конкуренция refresh/verify/recovery |
| H02 | Форматы/отображение, C04, fingerprint, реестры и T01–T17: парсер, причины, ошибки/HTTP, повторы/чтения | Полные машинные схемы/отображение details, физическая сверка, декодеры/векторы; точные границы — §24 контрактов |
| H03 | Назначения/grants, коды, текущая проверка, evidence Q06 | Проверенная публикация из доверенного источника, scope/revoke/expiry-тесты |
| H04 | Один consumer, lease30s, без renewal, бюджет5s, пять попыток и dedup | Worker, таймауты и crash/lease испытания |
| H05 | Кандидаты PostgreSQL/драйвера, точная арифметика, уровни ограничений и роли | Совместимый комплект, физическая детализация C04, SQL/constraints/query plans и испытания по отдельному поручению |
| H06 | Алгоритм срока, фиксируемая tzdb, полный обход, отчёты, копии/WAL и барьер восстановления | Проверенная библиотека/образ, место и доставка копий, ключи, непрерывность WAL, реальный restore и измеренные recovery limits |

«Согласовано» не означает «зависимость испытана и закрыта». Согласование пакета не является готовностью первого стенда.
