# Приёмка первого сквозного сценария

27.10.2026 · Часть [проекта T0](README.md). **Требования к будущей проверке, не отчёт о выполненных тестах.** Код, реальная БД и auth пока не реализованы; у всех пунктов статус «запланировано».

## 1. Условия и данные

Изолированная test-среда с настоящей PostgreSQL, контролируемыми clock/почтовым транспортом, двумя пользователями U1/U2 и отдельными staff identities: назначение с разрешённым просмотром U1, назначение вне области U1 и отозванное назначение. Это тестовые экземпляры согласованных прав, не новые роли продукта. Никаких live secrets/денежных endpoints. Выбранный способ production auth проходит отдельную проверку перед использованием с реальной почтой; mock не доказывает его безопасность.

Для Polymarket и Limitless — разные явно синтетические trader IDs и dataOrigin, без активации рыночных профилей и фальшивого публичного рейтинга. Два разных источника не объединяются одним адресом. Примеры не фактические сделки/доходы.

Основная настройка: B=200 USD, p=10%, d=15%; F=20 USD **либо** q=3%; P=20, D=30. Для теста явно задана допустимая IANA-зона и её подтверждение на review. Второй допустимый пример B=300, F=20, p=10%, d=15%: P=30, D=45. Используется актуальная `paper-mvp-settings-v1` и согласованные версии ограничений.

## 2. Успешный путь и интерфейс

| ID | Действие / предусловие | Проверяемый результат |
| --- | --- | --- |
| A01 | Новый пользователь с лендинга вводит email и подтверждает | Один user/login; открыт выбор трейдера, нет paper-сессии и funding. Email не запускает демо |
| A02 | Гость выбрал venue/trader, fixed/% и дошёл до review; затем вошёл | Свой draft и шаг/язык сохранены; параметры показаны снова; отдельное подтверждение C06. Нельзя присвоить чужой draft по ID |
| A03 | Review → отдельный start, отдельно fixed и percent | Одна session, одна revision1, один initial flow/journal, snapshot1 и receipt; правильно сохранён выбранный mode. При percent не применяется минимум fixed $5 |
| A04 | Сразу после старта | Free200, reserve0, positions0, equity200; нет ордеров/торговых событий/позиций. Понятное ожидание/доступность источника без фиктивной сделки. Funding не торговый доход и не изменение активного B |
| A05 | Сотрудник открывает эту сессию в админке | Тот же sessionId, settingsRevisionId, snapshotVersion/asOf и суммы. Сравнение одной версии; отдельная admin-модель не рассчитывает новые деньги |
| A06 | Reload, прямой URL, logout/login; Back и переключение RU/EN | Та же сессия и деньги; клиентский кэш прежнего пользователя очищен. Выход не отключает копирование, вход не возобновляет pause; язык не меняет зону/лимит/slot |
| A07 | Задана валидная B300; либо F21 при B200/p10/d15; либо q3,2% | B300 создаёт free300/P30/D45 без подстановки200; F21 и неверный шаг q отклоняются у поля, без скрытого округления и start |
| A08 | Проверка B=100/1000 и вне границ/шага; q=1/20 и вне шага0,5; p/d по политике | Допустимость совпадает с ADR-0058, включая F≤floor(min(P,D)) и p>d. Кнопка/сервер не расходятся; неактивное поле не становится вторым способом копии |
| A09 | Просмотр подготовленного example; новое демо после выхода из него | Example не создаёт user-session/funding, его история не импортируется. Новая сессия остаётся EMPTY |
| A10 | Все пути A01–A06 в RU/EN × mobile/desktop | Одни правила/команды, понятные локализованные причины и суммы; клавиатурный проход/фокус ошибок, узкие 320/360 и desktop1280/1440, масштаб текста200% не скрывают подтверждение/возврат |

Отдельный полный проход — для каждого sizing mode и venue; не требуется полный декартов перебор всех чисел на каждом viewport. Числовые границы проверяются доменно/API, а критический путь — в браузере.

| A17 | После входа найдена active/paused/exit-only либо stopped с manual/unknown/dust | Новая сессия не создаётся даже с новым ключом/другой venue; draft сохранён. Подписан фактический блокер. Full stop/reset не имитируются — используются изолированные состояния/fixtures |
| A18 | В БД неизвестный результат/потеря связи с БД; UI видит тайм-аут | Нет оптимистичного успеха/свободного бюджета и повторного старта с новым ключом. Возврат к receipt после восстановления. Unknown не равен отказу |

| A20 | Restore backup тестовой среды и повтор чтения/доставки | Сохраняются current slot, session/revision, funding, receipt и snapshot; нет новых команд площадкам и повторного funding. Проверка восстановления нужна до принятия стенда |

## 4. Вход и разграничение доступа

| ID | Попытка | Результат |
| --- | --- | --- |
| A21 | Неверный/истёкший/использованный код, resend, параллельный verify, автоматический GET login-link | Не создают лишнего user или paper-сессии, не сбрасывают защиту и не расходуют link простым GET; draft не теряется. Выполнить конкретные выбранные TTL/cooldown/attempt сценарии после их фиксации |
| A22 | Вход нового/существующего email, флуд отправки/проверки | Внешний ответ не раскрывает существование аккаунта; выбранные rate limits работают, ошибки почты честные, сырые сообщения провайдера не показаны |
| A23 | U2 читает session/receipt/draft U1; меняет userId/venue/environment/role в запросе | Нет доступа и раскрытия существования чужого объекта; поля из браузера не расширяют scope и не включают live |
| A24 | Staff без области/с отозванным назначением; отзыв между открытием списка и деталями | Нет чужих сумм/сессии. Прямой URL/API и кэш не обходят отзыв; разрешённое чтение аудитируется. Пользовательский вход не превращается в staff вход |
| A25 | Запрос изменения с чужого сайта, после logout/expiry; просмотр журналов/URL/browser storage | CSRF/серверный отзыв работают; кодов/cookies/секретов и чужих данных в логах/localStorage нет; постоянных credentials в URL нет. Одноразовый login-link не утекает в логи/referrer, адрес очищен после обмена. 401 не запускает новое демо после повторного входа |
| A26 | Открыта auth-ссылка на другом устройстве без восстановленного draft | Честное отсутствие черновика с возвратом/новой настройкой; чужой handle не присваивается. Нет автоматического start |

## 7. Что означает «первый сценарий готов»

Условие будущей готовности: все применимые A01–A41 должны быть подтверждены на реализованном срезе, найденные блокирующие дефекты — устранены. Сохранены версия приложения/схемы, конфигурация теста без secrets, IDs сценариев, результаты DB/API/browser и короткие доказательства RU/EN. Для race/crash — управляемая точка сбоя и состояние БД после восстановления. Число тестов не заменяет эти результаты.

До начала реализации должны быть закрыты вход/защита/хранение, staff access, время и размещение из [README](README.md). Необязательный провайдер/точная версия библиотеки не выбираются этим документом. Нереализованные команды явно недоступны; экран прототипа не считается работающей кнопкой сервиса.

Успешная приёмка первого среза разрешает обсуждать T3, **не объявляет готовыми** копирование, score, обе рыночные интеграции, все G01–G07, весь paper-релиз или live. Текущее поручение заканчивается документами; выполнять A01–A41 в приложении сейчас негде.
