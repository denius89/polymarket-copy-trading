Runbook нельзя согласовать в текущем порядке: закрытие 22 до проверки VPN/2222 создаёт lockout. Проверка VPN с самого сервера не подтверждает административный доступ извне; provider console grant ещё pending. До закрытия старого пути это stop condition.

Исправленная последовательность для staging Ubuntu 24.04:

1. Preflight: назначить ответственного и окно; сохранить SSH/firewall конфигурацию, зафиксировать Docker version и получить version-specific официальный SSH/runtime источник. Команды сейчас не подготовлены: глава отсутствует.
2. Получить console access и проверить вход/recovery; сохранить действующую office-CIDR сессию на 22. Подготовить обратимые изменения с отдельным владельцем rollback.
3. Настроить ограниченный путь VPN/2222 параллельно старому. Проверить новую независимую SSH-сессию с административного клиента через VPN, авторизацию и необходимые права. При неуспехе откатить добавление, 22 оставить.
4. Только после этих проверок ограничить старый доступ; перепроверить новую сессию и console recovery. При lockout использовать проверенную console и сохранённую конфигурацию.
5. Убрать privileged app и docker.sock mount из предложенной схемы; healthcheck должен иметь минимальные права без управления daemon. Совместимость решения зависит от неизвестной версии runtime.
6. Secrets оставить ограниченными сервисной identity; world-readable запрещён. Зафиксировать безопасную доставку/ротацию без раскрытия значений.

TLS истекает через семь дней: отдельно проверить renewal timer и тест обновления с восстановлением конфигурации при сбое. До evidence всех проверок статус «staging hardened» не присваивать. Серверные действия не выполнялись.
