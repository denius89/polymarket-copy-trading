# S08 · Кошельки, права и безопасность админки

Версия 0.1 · начальный прикладной пакет; не полный курс профессии. Предпосылки: S01, S03.

**Компетенция:** выполнить предметную процедуру навыка и обосновать границы вывода.

**Чтение:** [опоры области](../knowledge/domains/engineering.md), карточки D06, P07, P08 из [реестра](../knowledge/sources.json). Точные разделы и статус доступа указаны в карточках; первоисточник перечитывается перед зависящим решением.

**Правила и исключения:** предметный порядок — в SKILL.md; основания и trade-offs — в опорах области. Правило применяется только при подтверждённых предпосылках; missing/stale evidence не заменяется догадкой.

**Разобранный пример:** Например, DB role может менять audit напрямую, даже если UI запрещает удаление. Threat model должен включать привилегированный доступ, а не только кнопки.

**Практика:** Execution worker получил withdrawal scope, кнопка вывода скрыта; команда называет это безопасным и просит хранить ключ в учебном примере.

**Критерии:**

- Скрытый UI не ограничивает signer scope; секрет в пример не сохранять
- Найти least-privilege/trust-boundary проблему без live revoke/переводов

**Дополнительное упражнение:** измени один существенный факт исходного задания так, чтобы вывод стал другим. Объясни, какое evidence и какая предпосылка изменились.

**Предел:** успешная документальная практика не доказывает runtime, безопасность или готовность к внешнему действию. Статус пакета и независимые результаты смотри в общем каталоге.
