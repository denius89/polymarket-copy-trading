# S04 · Финансовый UX и UI

Применяй к существующему проекту и текущему поручению. Для границ подготовки, evidence и выбора источников прочитай [общие правила](../../../docs/ai-system/OPERATING_RULES.md). Подготовка процедуры не является разрешением выполнять описанные внешние действия.

## Процедура

1. Установи конкретную задачу пользователя, состояние денег/данных, роль и контекст viewport/локали. При визуальной оценке загрузи доступный Impeccable явно; если его нет, обозначь это, не блокируя проверку смысла.
2. Проверь иерархию и последовательность: статус, затронутые деньги/риски, последствия и следующий шаг. Отличай pending, unknown, estimated, paper и live словами, а не одним цветом.
3. Оцени сетку/контейнеры, spacing, типографическую шкалу, числа/единицы, плотность таблиц и графиков по актуальному kit. Не заменяй токены эстетическим предпочтением.
4. Проследи loading/error/empty/stale/permission denied и действия user/admin; учитывай RU/EN expansion, keyboard/focus, масштаб и reduced motion. По картинке не объявляй runtime-доступность.
5. Выдай наблюдения по frame/node и evidence, severity по последствиям, минимальную правку/вопрос. Внесение дизайна — только если поручено; до него читать актуальный Figma workflow.

## Знания и проверка

Для предметной работы: [пакет S04](../../../docs/ai-system/learning/S04.md) и нужный раздел [опор области](../../../docs/ai-system/knowledge/domains/design.md). Прочитай относящиеся первичные материалы, а не только индекс; не загружай учебные задания при каждом простом запросе.

Результат: конкретный ответ в рамках поручения с основаниями, ограничениями и существенными рисками. Выбирай формат по задаче. Проверяй следующие свойства:

- Найти ложную определённость результата и недостающий контекст.
- Ограничить охват RU mobile; не заявить runtime/EN QA или изменить макет.

Смежные процедуры: S03, S05, S08. Это зависимости знаний/проверки, не команда автоматически запускать все навыки или агентов.
