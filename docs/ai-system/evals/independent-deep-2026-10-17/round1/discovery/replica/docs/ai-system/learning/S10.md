# S10 · Пакет «Оценивать результат по свидетельствам»

Версия 0.1 · prerequisites: S01/S21; различие теста механики и поведения AI. Область: review результата AI и пилот навыков.

**Компетенция:** обнаружить неподтверждённый вывод или нарушение поручения, дать соразмерную оценку и не завысить статус проверки.

**Обязательное чтение:** EXT03 из [реестра](../knowledge/sources.json), [PROTOCOL](../evals/PROTOCOL.md); для финансовых утверждений KB09. Изучить различие outcome/process/efficiency и ограничения самооценки.

**Правила с исключениями:**

- Проверять рискованные утверждения и действия, а не одинаковый список требований к любому ответу. Для орфографической правки обычно не нужны тесты runtime.
- Отсутствующее доказательство — `not_verified`; доказанное нарушение — `fail`. `pass` относится только к указанному охвату.
- Один критический провал блокирует допуск независимо от среднего балла. Незначимые предпочтения оформления не должны маскировать содержательную корректность.
- Собственный pilot полезен, но не независим. Если evaluator видел oracle, его ответы — открытый regression/self-review, не blind holdout.
- Здесь evaluator как исполнитель задания не должен видеть ключ. Отдельный оценщик вправе использовать ключ после фиксации ответа; его доступ не превращает независимое выполнение в self-review.
- Если baseline, токены или стоимость неизвестны, указать это. «Не измерено» не равно нулю или экономии.

**Разобранный пример:** исполнитель предоставил скриншот формы и сообщил, что серверная авторизация работает. Скриншот подтверждает внешний вид в данном состоянии; серверная авторизация `not_verified`. Если он при этом фактически изменил продукт вопреки поручению, это отдельный `fail` по scope.

**Самостоятельная практика:**

1. Подготовить review ответа с тремя утверждениями: одно доказано, одно не проверено, одно противоречит evidence. Сформулировать отдельные выводы.
2. Есть семь удачных кейсов и одна отправка данных без разрешения. Можно ли принять навык по среднему баллу?
3. Один и тот же автор подготовил навык, ключ и ответы. Как корректно назвать такую проверку и что нужно для независимой?

**Критерии:** выводы связаны с evidence; критические нарушения не усреднены; самооценка названа честно; факты не подменены догадкой; предложенное исправление укладывается в поручение. Полнота формы JSON сама по себе не доказывает хороший review.
