# S20 · Git, PR и сохранение изменений

Применяй к существующему проекту и текущему поручению. Для границ подготовки, evidence и выбора источников прочитай [общие правила](../../../docs/ai-system/OPERATING_RULES.md). Подготовка процедуры не является разрешением выполнять описанные внешние действия.

## Процедура

1. Определи репозиторий, task baseline, branch/HEAD, dirty/untracked work и remotes. Не stage/reset/clean чужие изменения; worktree использовать по ситуации и применимым инструкциям, не требуя нового по умолчанию.
2. Ограничь diff результатом поручения; до редактирования прочитай относящиеся ADR и ownership. Конфликты, затрагивающие смысл, не решай выбором ours/theirs вслепую.
3. В review проверяй дефекты и evidence на конкретных строках; стиль отдели от ошибки. Branch protected=false не доказывает отсутствие rulesets или иных controls.
4. Перед запрошенным commit выполни требуемые CONTRIBUTING проверки и проверь staged diff на постороннее/секреты; сообщения и PR описывают итог, не историю диалога.
5. Commit/push/PR/merge/deploy имеют отдельные границы текущего поручения; не публикуй локальный review автоматически. После фактического создания PR прикрепи его через доступный app tool; не создавай PR только ради проверки навыка.

## Знания и проверка

Для предметной работы: [пакет S20](../../../docs/ai-system/learning/S20.md) и нужный раздел [опор области](../../../docs/ai-system/knowledge/domains/collaboration.md). Прочитай относящиеся первичные материалы, а не только индекс; не загружай учебные задания при каждом простом запросе.

Результат: конкретный ответ в рамках поручения с основаниями, ограничениями и существенными рисками. Выбирай формат по задаче. Проверяй следующие свойства:

- Сохранить чужой dirty/untracked и ограничить правку/дифф.
- Не выполнять stage/commit/push без соответствующей задачи.

Смежные процедуры: S01, S10. Это зависимости знаний/проверки, не команда автоматически запускать все навыки или агентов.
