# Дизайн, финансовый смысл и frontend-видимость

Опоры: P03 проектные стандарты; P02 handoff; D03 WCAG, D17 USWDS typography, D20 ONS charts. Из внешней системы не импортируются автоматически шрифты/размеры в наш kit. Перед write/design-to-code нужны соответствующие доступные Figma навыки.

## Основы

- Сетка состоит из контейнера, колонок, промежутков и внутренних отступов; breakpoint следует содержимому и реальному reflow, а не набору случайных ширин. Grid полезен для двухмерного распределения, Flex — для направленной строки/колонки; выбор проверяется на контенте.
- Иерархия текста, line length/height, numeric alignment, единицы/валюта и контраст работают вместе. Единственная универсальная шкала для любого финансового экрана не предполагается; текущие tokens/kit — исходная база.
- Цена, прибыль, резерв и доступный баланс должны иметь разные понятные основания. Pending/unknown/stale не выдаются за исполнение или убыток. «Остановить» и «закрыть» могут иметь разные последствия по ADR.
- Таблицы требуют стратегии малых экранов: какие данные первичны, как раскрыть детали/заголовки/единицы без потери контекста. В графике проверять время, оси, scale, base, intervals и missingness; декоративная линия не заменяет данные.
- RU/EN expansion, длинные адреса/суммы, empty/error/loading, focus/keyboard/reflow и reduced motion входят в задачу качества. По макету доступны только часть структурных/визуальных выводов; runtime-a11y проверяется отдельно.

## Проектные границы

Набор компонентов не доказывает, что все instance обновились. Публикация библиотеки, принятие изменения и миграция — разные события. Новая composition не должна молча создавать мастер/отвязывать instances или переопределять бизнес-правила. Handoff должен связывать актуальные IDs, tokens, статус и evidence, а не только картинку.

## Пример и упражнение

В confirmed позиции может быть реализованная прибыль; у pending заявки — оснований для такой цифры нет. Исправить label недостаточно, если смысл данных неясен. Упражнение: составить вопросы к источнику статуса и предложить иерархию карточки, не придумывая ответ сервера.
