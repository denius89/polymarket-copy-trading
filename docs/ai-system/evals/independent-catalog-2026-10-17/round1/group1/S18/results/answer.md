# Review учебного runbook

Заявление о полной изоляции необоснованно. Docker socket внутри web container открывает путь управления daemon в пределах его реальных полномочий; если daemon управляет хостом с высокими правами, компрометация web может распространиться на хост и другие контейнеры. `privileged=true` дополнительно расширяет доступ к устройствам и возможности процесса. Точный набор последствий зависит от runtime/OS, но представленные настройки уже противоречат обещанию самостоятельной изоляции.

Предлагаемая правка runbook: удалить это обещание, обосновать необходимость каждого расширенного права, по умолчанию исключить daemon socket и privileged из web. Если управление контейнерами действительно нужно, выделить контролируемый сервис/интерфейс с минимальными разрешёнными действиями и собственной аутентификацией; socket proxy сам по себе не доказательство безопасности. Rootless также требует проверки совместимости и не гарантирует абсолютной границы.

Перед конкретными шагами нужны OS/version, runtime/version, provider, daemon mode, identities, mounts, capabilities, сети и recovery path. Пока они неизвестны, команды hardening и совместимость — `not_verified`.

Runbook должен включать preflight инвентаризации, проверку нового доступа и console recovery до закрытия старого, ограниченный rollout, критерии остановки и rollback. Verification: эффективные привилегии, отсутствие socket/опасных mounts, доступность приложения и восстановление доступа в изолированной среде. Дополнительно проверить доставку secrets, TLS renewal, patching и ресурсные лимиты. Здесь выполнен только review: серверные команды, подключения и изменения не выполнялись.
