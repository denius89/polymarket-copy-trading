# Operations review

По supplied snapshot эксплуатационная готовность не подтверждена. 100% uptime по ping показывает только успешность конкретной проверки за её неизвестное окно. Он не подтверждает доступность пользовательского пути, своевременность котировок или исполнение финансовых операций.

Wallet address в metric label создаёт высокую cardinality и риск привязки телеметрии к пользователю; email в логах добавляет персональные данные без указанного основания. Предлагается убрать эти поля из общего потока: использовать ограниченные labels статуса/причины/компонента, а связность расследования обеспечивать operation ID в контролируемых logs/traces. Operation ID также не следует превращать в безграничный label. Доступ и retention существующих записей требуют отдельного согласованного решения, не произвольного удаления.

Alert «ошибка» не actionable. Для каждого класса отказа нужны назначенный владелец, условие с окном, severity, ссылка на runbook и recovery criterion. Для котировок предложить SLI возраста последнего валидного обновления, долю просроченных ответов и отдельно задержку доставки; контролировать и молчание источника. Для критического пути — долю подтверждённых результатов, задержку и возраст submitted/unknown операций. Цели SLO и thresholds пока не приняты.

Минимальная проверка в изоляции: остановить поступление котировок и убедиться, что freshness alert возникает, маршрутизируется владельцу и очищается после восстановления. Origin bypass, reconnect amplification и capacity остаются not_verified: данных о топологии и нагрузке нет. Настройки и рассылки не выполнялись.
