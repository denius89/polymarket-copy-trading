# План QA для user/admin flow

Цель: одновременные cancellation и partial fill, включая дубли, должны давать согласованные лоты, деньги и остаточный резерв в обеих ролях. Текст кнопки проверяет лишь отображение. Та же PnL function в expected создаёт круговой oracle: одинаковая ошибка способна сделать тест зелёным.

| Сценарий | Независимое ожидаемое свойство | Уровень |
|---|---|---|
| Один fill доставлен дважды | Один экономический эффект и одна запись результата | Integration |
| Partial fill перед cancel confirmation | Исполненная часть сохранена; отменён только подтверждённый остаток | Integration |
| Cancel request и fill одновременно | Запрос отмены не стирает подтверждённый fill | Concurrency |
| Поздний fill после уведомления об отмене | Сверка по внешним идентификаторам и времени; без двойного учёта | Integration |
| Timeout/restart и повторная доставка | Unknown сохраняется до подтверждения; без resend и преждевременного освобождения резерва | Recovery |
| User/admin читают итог | Общие подтверждённые факты; tenant/role scope проверен сервером | E2E |

Порядки событий повторить с фиксированными event IDs, временем и детерминированными точками конкуренции. Денежный oracle — отдельно заданный ledger fixture с вручную проверенными fills/fees и сохранением баланса; expected не вызывает продуктовую функцию. Проверять, что изменение количества лотов равно сумме уникальных подтверждённых fills, а резерв соответствует подтверждённому остатку. Для неизвестных venue semantics ожидается reconciliation, а не выдуманный порядок финальности.

Выполнение планируется только на изолированном synthetic/staging стенде без реальных credentials и отправки сделок. Coverage и визуальный успех остаются вспомогательными свидетельствами. Код и тесты здесь не реализованы; перечисленные свойства ещё не проверены runtime.
