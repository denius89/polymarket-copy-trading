# Предварительное сравнение инфраструктуры

Два предложенных сервера в одной zone не обеспечивают независимость при отказе zone. Общая DB остаётся общей точкой отказа и потери состояния; общий signer — зависимость исполнения и отдельная граница доверия. Разделение приложений не устраняет эти риски.

| Вариант | Польза | Ограничение / условие выбора |
|---|---|---|
| Два VPS в одной zone + общие DB/signer | Возможность разделить процессы, обслуживать приложение поочерёдно | Отказ zone и общих компонентов затрагивает оба сервера; сопровождение команды |
| VPS в разных zones + проверенная стратегия DB/recovery | Снижение зависимости от одной zone | Межзонная задержка/egress, репликация, failover и signer требуют отдельной проверки |
| Managed приложение/DB + отдельно ограниченный signer | Часть сопровождения у провайдера | Квоты, lock-in, размещение, стоимость и фактические failure domains требуют проверки |

Выбор отложен до region/residency, RPO/RTO, SLO, нагрузки/freshness, бюджета и доступности дежурных. Нельзя вывести подходящие RPO/RTO из числа серверов.

Модель полной стоимости: compute + DB/storage/IO + egress + backups/retention/restore drills + telemetry + сетевые controls + secrets/signer custody + support/on-call. Указанный compute тариф — только компонент; числового значения в fixture нет. Остальные статьи неизвестны, не равны нулю.

Проверить нагрузку, отказ zone/DB/signer и восстановление в изоляции; после restore сначала read-only reconciliation submitted/unknown, затем контролируемое возобновление. Оценить экспорт/перенос данных и стоимость выхода. Ресурсы не создавались, тарифы извне не запрашивались.
