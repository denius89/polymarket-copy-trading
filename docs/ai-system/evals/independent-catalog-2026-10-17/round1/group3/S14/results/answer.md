# Проверка validation claim

Заявление о независимой оценке score в начале квартала этим дизайном не подтверждается. Universe сформирован по выживанию и заработку к концу следующего квартала: при историческом cutoff исследователь использует сведения из будущего и исключает неуспешных/исчезнувших участников. Полученная выборка не представляет доступный тогда набор адресов. Это survivorship и selection leakage; направление и величину искажения по fixture измерить нельзя.

Обучение всех preprocessing параметров на полной истории дополнительно переносит будущую информацию в раннюю оценку. Даже без использования outcome непосредственно нормализация, заполнение пропусков и отбор признаков должны оцениваться внутри обучающего окна.

Повторная проверка: определить target net copier outcome, baseline, горизонт и universe по сведениям, доступным на cutoff; сохранить неуспешные и исчезнувшие адреса с корректной обработкой missingness. Разделить периоды последовательно на train/validation и новый нетронутый holdout. Fit preprocessing только на train каждого прохода. Исключить пересечение связанных адресов и общих events между независимыми группами; пограничные outcome horizons отделить, чтобы будущие labels не попадали в обучение.

Метод и параметры заморозить до финального holdout, результаты сообщать вместе с coverage, групповой неопределённостью и чувствительностью к latency/fees/depth. Уже использованную будущую историю нельзя объявить новым holdout. Численное преимущество score и прибыльность остаются not_verified; формула не менялась, пересчёт не выполнялся.
