# Календарный компонент C06

Реализует принятый `paper-evaluation-deadline-v1` из `backend-operations.md §3`:
14 местных календарных дней с сохранением местного времени; overlap — первое
вхождение; gap — первый существующий момент после пропуска. Для gap выбран
момент перехода, а не стандартное Temporal `compatible`, которое сдвигает время
на величину пропуска и может сохранить неверные минуты.

`calculateEvaluationDeadline(startedAt, ianaTimezone, profile)` получает
защищённые значения `c06_prepare` и заранее закреплённый оператором профиль.
Выход содержит UTC deadline с миллисекундами, версию алгоритма и tzdb.
Функция не читает сеть/БД/часы, не создаёт новую дату старта и не меняет настройки.
Она вызывается между prepare/finish на одном соединении, внутри одной
Serializable-транзакции. Ошибка расчёта означает техническую недоступность и
откат текущей попытки, а не отклонённый пользовательский ввод. Неизвестный
COMMIT имеет собственный протокол Q05 и не превращается в доказанный откат.

Библиотека закреплена как `@js-temporal/polyfill=0.5.1`. Типы API проверены по
[исходнику этой версии](https://github.com/js-temporal/temporal-polyfill/blob/v0.5.1/index.d.ts);
семантика перехода описана в
[документации Temporal](https://tc39.es/proposal-temporal/docs/zoneddatetime.html#getTimeZoneTransition).
Библиотека использует данные часовых поясов среды. Поэтому проверяются фактические
`process.versions.node/icu/tz`, а не название пакета или часовой пояс машины.
Профиль должен совпасть полностью; UTC fallback, автоматическое принятие текущих
версий и пересчёт сохранённого срока не допускаются.

Локальный проверочный профиль хранится в `test/calendar-profile.local.json`:
Node24.9.0, ICU77.1, tzdb2025a. Это не профиль Oracle. Для серверной проверки
оператор предоставляет отдельный принятый JSON через `CCT_CALENDAR_PROFILE_FILE`;
нельзя генерировать его из текущих версий только ради зелёного теста. До активации
нужны закреплённый digest образа, совпадение версии пакета/lock, измерение
фактических версий и проверки в этом же образе. Произвольная подмена ICU data
переменными/параметрами запуска не входит в проверенный профиль. Одно совпадение
строк версий не доказывает целостность образа или пригодность всех IANA-зон.

`test/deadline-vectors.json` — вручную заданные ожидаемые UTC значения: обычные
даты, високосный/годовой переход, миллисекундные границы Warsaw, получасовые
переходы Lord Howe, пропуск даты Apia. Ожидания не вычисляются тестируемым builder.
`verify-deadline-vectors.py` независимо проверяет эти фиксированные значения через
Python zoneinfo: допустимые локальные кандидаты и первое вхождение либо скачок
через отсутствующее время между соседними миллисекундами. Это дополнительная
проверка, не замена испытания закреплённого Node образа.

Модуль не включает HTTP/DB adapter, не активирует START и не подтверждает полный
H06, атомарность C06, доверенность серверных часов, restore или внешний P04.
