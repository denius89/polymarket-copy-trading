## Существующее поведение

Recovery получает один HTTP admission и один durable attempt, связывает их
с исходной операцией и конкретной subject transaction. Бюджет берётся из
исходного ingress clock. Неизвестный COMMIT не разрешает выдавать cookie или
исполнить операцию новым ключом. Обычный completion replay использует свой
закрытый permit. Runtime/ingress/witness подключения разделены; реальный запуск
требует явного `V00_RECOVERY_QUOTA_ENABLED=1` и корректной private конфигурации.

Эти утверждения описывают сохранённый исходник; данная работа не проводила
нового Oracle/Auth/browser прогона и не удостоверяет всю композицию. Код
настоящего staff-входа, его открытые RPC и публикация staff-пакета сюда не входят.

## Проверка сохранения

Проверяются пять exact source blobs против исходного commit и архива,
синтаксический разбор Python, предметное чтение и отсутствие явных секретов
в составе, repository checks и scoped diff check. Новые behavioral tests
не создаются для byte-identical переноса. Полные ограничения и команды
проверок указываются в PR; прежние runtime результаты не объявляются новыми.

Не включать в публикацию архив целиком, private config, базы, секреты или
сырые runtime свидетельства. Дальнейшие изменения поведения — отдельный diff.
