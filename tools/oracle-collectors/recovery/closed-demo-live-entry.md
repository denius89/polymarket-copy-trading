# Общий профиль живого сборщика закрытого демо

Входной процесс читает профиль подтверждённой сессии и защищённое сопоставление роли с локальным соединением PostgreSQL. Он сверяет название и адрес закрытой базы, роль подключения, кошелёк, релиз, настройки и срок сессии. Для Limitless область дополнительно читается через узкую функцию владельца существующего финансового назначения. Готовность отправляется после успешной сверки.

В рабочем режиме используются существующие источники и операции демо-покупки. В режиме `--check` выполняются только проверки области и чтение. Модуль ставится рядом с точной версией кода площадки, а параметры рецепта находятся в защищённом файле `venue-runtime.json`. Пакет Polymarket должен включать `closed-polymarket-runtime-ready.patch`, пакет Limitless — `closed-limitless-continuous-runtime.patch` и SQL чтения области. В режиме просмотра проверены обе текущие сессии, а профиль с подменой кошелька отклонён на обеих площадках.

Для новой сессии задайте в защищённой настройке запуска площадки `requirePreparedAnchor: true`. В `writerServices` добавьте к назначенной роли поле `activationAnchor` с идентификатором сети `chainId` (137 или 8453), десятичной строкой `number` и хешем `hash`. Для Limitless номер совпадает с `discoveryBlock`, а для новой сессии используется собственный файл контрольной точки. Ту же проверку можно выполнить без запуска обработки через `--check --require-prepared-anchor`.

На Polymarket процесс сверяет номер и хеш с сохранённым подтверждением стартового блока своей сессии. На Limitless оба источника Base подтверждают номер, хеш и время стартового блока, а высота входит в общую финализированную цепочку. Блок должен быть создан до момента активации сессии либо в эту же секунду. При повторном запуске сверяется и первоначальный блок, и сохранённый курсор. Расхождение отклоняет запуск до сигнала готовности. Прежние процессы могут продолжать использовать свой профиль без этого параметра.

Если у той же сессии уже есть контрольная точка старого формата, первый запуск с подтверждённым блоком дополняет её идентичность только после сверки исходного блока и сохранённого хеша. Высота и хеш курсора сохраняются. Режим `--check` выполняет эту сверку без записи.

23 ноября на закрытом Oracle Polymarket переключён на новый вход. При штатной остановке сохранены блок 97843172 и отметка журнала 180. Новый процесс продолжил с этой точки, прошёл до 97843217, открыл ту же сессию и не переписал финансовый снимок. Повторная привязка вернула тот же идентификатор работающего экземпляра. Режим записи сохраняет сбор после первого подтверждения, пока длится согласованное окно.

На Limitless установлен и проверен новый формат профиля. Текущий старый процесс продолжает работу. Переход в рабочий режим требует устойчивой точки чтения Base: в прежнем сборщике курсор сканера остаётся в памяти и не является квитанцией обработки всего диапазона. Завершение уже принятых покупок определяется правилами финальности действующего финансового адаптера.

Этот проход не зафиксировал новой виртуальной покупки. Отдельное окно Tokor завершилось без покупки. Среди причин отказа были истечение времени ожидания книги и котировка по нескольким ценовым уровням. Основной /app не изменялся.
