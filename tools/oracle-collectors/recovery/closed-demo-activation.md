# Очередь запуска финансового обработчика демо

После подтверждения C06 наблюдатель создаёт одну заявку на запуск по идентификатору исходного события. Отдельная роль получает заявку на ограниченное время и передаёт её установленному адаптеру площадки. После обрыва следующая попытка получает тот же идентификатор с новой арендой. Подтверждение старой аренды отклоняется. Заявка завершается только пока сессия активна и очередь видит актуальное финансовое назначение площадки.

Адаптер получает одну ограниченную JSON-запись через стандартный ввод. В ней есть площадка, кошелёк, сессия, редакция трейдера и идентификатор заявки. Ответ содержит тот же идентификатор заявки и UUID фактически запущенного экземпляра. Адаптер обязан переиспользовать уже созданный экземпляр для повторного вызова, а также сверять завершение сессии и останавливать её процесс. Отдельная активирующая роль не может сама произвести покупку, выбрать роль исполнителя или менять таблицы.

Установку выполнять после пакета привязки финансовых назначений, во внутренней базе закрытой копии. Активирующая роль получает использование схемы `demo_delivery` и вызов `activation_release()`, `claim_activation()`, `finish_activation(uuid,uuid,uuid)`, `defer_activation(uuid,uuid)`. Файл настройки службы содержит точные имя и адрес базы, идентификатор релиза, имя роли, имя локального соединения и абсолютные пути двух установленных адаптеров. Разрешены только защищённые от посторонней записи каталоги. Запись сессии в очередь не требует выполнения службы активации.

Для маршрута через брокер после SQL профиля установите `closed-demo-provisioning.sql`. Выдайте активирующей роли вызов `claim_activation(text[])`. Сборщик получает заявку через брокер после появления согласованного финансового назначения и его привязки в очереди. Ожидающая назначения заявка сохраняется, другие готовые демо продолжают запускаться. Для прямого адаптера остаётся прежний вызов без параметров.

Отдельный оператор подготовки может читать `pending_demo_assignments(text)` только с явно выданным правом. Функция возвращает до 16 действующих подтверждённых заявок выбранной площадки. По идентификатору C06 оператор повторно проверяет состояние перед созданием назначения, а после сбоя находит прежнюю заявку. Функция не создаёт роли PostgreSQL и не меняет настройки сессии. Для Polymarket нужны финансовое назначение и подтверждённая стартовая точка Polygon, для Limitless — финансовое назначение и подтверждённая стартовая точка Base. Подготовка этих назначений остаётся у адаптеров площадок.

## Сверка

В двух временных PostgreSQL на закрытом Oracle фоновые службы обработали по две сессии каждой площадки. Истёкшую заявку получили повторно с тем же ID, старый токен не подтвердил запуск. Контрольный адаптер подготовил реальные тестовые привязки через штатные операции площадок. Один архивный сигнал дал по одному исполнению, позиции и списанию в каждой сессии. Повтор сигнала не изменил снимки. У обычной роли приложения отсутствует доступ к аренде заявок.

На постоянной закрытой копии включена только очередь. Существующие финансовые назначения сохранены. Реальные адаптеры для подготовки и запуска новой сессии из каталога или по адресу требуется установить отдельно. Основной /app в этой проверке не участвовал.

### Проверка допуска новой сессии

Запустите `node verify-closed-demo-provisioning.mjs <путь к модулю PGlite>` из каталога пакета. Временная база проверяет обе площадки, запрет вызова для обычной роли, пропуск заявки без финансового назначения и повтор после активации. Перед включением требуется подключить утверждённые адаптеры площадок и подтвердить сквозной запуск на закрытой копии.
