# Установка сборщиков в изолированной среде

Пакет собран из снимка исходников PR №269. В `releases.json` указаны три версии исходников, а в `install-lock.json` — версии платформы, SHA‑256 SQL и колёс драйвера, порядок миграций и из каких сохранённых пакетов взяты файлы. Архив содержит исходники, SQL, шаблоны, библиотеку драйвера и манифест `SHA256SUMS`. Его сборка и распаковка не запускают процессы.

## Сборка из Git

Нужны Python 3.10+ для упаковки, закрытый файл с исходным HTTPS-адресом Polymarket и каталог двух колёс, указанных в lock. Колёса доступны в ранее сохранённом пакете `personal-buy-rehearsal-candidate4` в `worker/wheels`. Их можно отдельно загрузить на совместимом Linux ARM64 / CPython 3.14 командой `pip download --only-binary=:all: --no-deps --require-hashes -r <lock requirements> -d <wheels>`. Сборщик принимает только точные SHA‑256.

```sh
python3 -B tools/oracle-collectors/build_install.py \
  --oracle-origin-file "${CCT_ORACLE_ORIGIN_FILE}" \
  --wheel-dir "${CCT_PINNED_WHEELS}" \
  --output /tmp/oracle-collector-install.tar.gz
```

Файл сборки содержит восстановленный приватный адрес в двух исходниках, поэтому храните архив как закрытый операционный артефакт. Для получения такой же сборки используйте тот же коммит, те же входы и версию упаковщика. После распаковки в новый закрытый каталог выполните `sha256sum -c SHA256SUMS` из корня распакованного пакета.

## Среда и настройки

Цель персональных сборщиков — Linux ARM64, CPython 3.14 и PostgreSQL 17.11 с совместимой схемой Shadow. В изолированное окружение установите колёса из архива, без обращения к индексу:

```sh
python3.14 -m pip install --no-index --find-links wheels --no-deps --require-hashes \
  -r install/requirements-oracle-cp314-aarch64.txt --target private-driver
PYTHONPATH="$PWD/private-driver" python3.14 -c 'import psycopg; assert psycopg.__version__ == "3.3.9" and psycopg.pq.__impl__ == "binary"'
```

Для каждой отдельной сессии заполните её JSON по шаблону и установите права `0600`. Writer и issuer используют разные LOGIN и разные службы libpq. Файлы `PGSERVICEFILE`, `PGPASSFILE` и доверенный сертификат подготовьте отдельно. В репозитории только шаблоны. Идентификаторы сеансов, учётные данные, записи о покупках и остатки не переносятся. Настройки интерфейса и Web-приёмка находятся за пределами этого пакета.

## SQLite общего Polymarket

`install/sqlite/baseline-schema.json` содержит определения пяти таблиц из сохранённого базового выпуска. Для новой изолированной БД задайте согласованные значения в целых микродолларах и выполните:

```sh
python3 -B install/prepare_sqlite.py ./new-ledger.sqlite --policy /path/to/private-policy.json
```

Утилита использует миграцию `storage.install` из сверенных исходников, проверяет неизменность снимка и создаёт базу без активного writer. Существующий файл она не перезаписывает. Для переноса действующего журнала требуется остановленная совместимая копия, сверка схемы и отдельная приёмка. `polymarket-v2.json.example` описывает параметры запуска `app_run.py` и источник приватного адреса. Исторические операторские модули рядом с ним сохранены как исходники установленного пакета.

## PostgreSQL персональных сборщиков

Этот слой устанавливается на отдельную совместимую копию базовой БД Shadow. Она должна содержать схемы `polygon` и `polygon_live_activity`, предусмотренные роли и подтверждённые назначения сессий. Этот пакет фиксирует слой сборщиков поверх исходной схемы; он не создаёт приложение Shadow и Auth с нуля. Миграция writer сверяет хеши определений функций исходной схемы. При несовпадении остановитесь и установите точный исходный выпуск, к которому относится миграция.

Порядок зафиксирован в манифесте: writer → segment → decision-gap → Tradecraft → history-cost. Патч Tradecraft требует, чтобы обе привязки были подготовлены в совместимой копии до его применения. Назначения, доказательства финальности и значения доверенных ролей проверяет оператор. SQL не заменяет эту процедуру. Для изолированной копии выполняйте файлы в указанном порядке через `psql -X -v ON_ERROR_STOP=1 -f <file>`, подключаясь к заранее проверенной локальной БД. Файлы содержат собственные транзакции. После частичного сбоя зафиксируйте достигнутый шаг и восстановите исходную копию до повтора цепочки.

Завершённая установка требует проверки разрешений issuer/writer, соответствия назначенной сессии и чтения согласованного снимка. Исторический cutoff остаётся зафиксирован в исходниках. Пакет не продлевает окно и не запускает сборщики. Неизвестный исход операции сперва сверяется по исходному ключу.

## Выполненная проверка

Временная SQLite прошла создание схемы без активного writer. Запись без прав и повторное создание поверх файла отклонены. В PGlite 0.3.15 на синтетических сессиях прошла цепочка из пяти PostgreSQL-скриптов. При повторе события Tradecraft оставалась одна запись пропуска без изменения баланса, следующий блок принимался. Проверка BreakTheBank подтвердила два диапазона по 64 заголовка, сохранение денежного снимка и отказ на разрыве цепочки. Это локальная проверка схемы, отдельная от установки на штатный PostgreSQL и запуска нативного драйвера Linux ARM64. Колёса сверены с архивом и манифестом.
