# Сверка закрытой среды для staff Q06 · 20.11.2026

**Итог по архиву.** Версия PostgreSQL, архитектура и формат чтения совместимы с пакетом. Для уже настроенной базы первичная процедура установки не подходит. Текущие назначения, выделенная сеть и сертификаты нового служебного адреса требуют отдельного подтверждения.

Сверен пакет из `main@0e0b93e`, объединённый в [PR №279](https://github.com/denius89/polymarket-copy-trading/pull/279). За ориентир взята сохранённая конфигурация закрытого Oracle V00 и локальные архивные срезы 18–19 ноября. Действующий сервер в этой сверке не опрашивался.

| Область | Что подтверждено | Что остаётся проверить |
| --- | --- | --- |
| PostgreSQL и Q06 | В архивном SELECT от 19.11 зафиксирован PostgreSQL 17.11, та же версия использована в изолированном прогоне. Декодеры `pilot/responses.ts` и `live-buy/reader.ts` побайтно совпали с пакетом. Оба используют `live-buy-session-v1`. Сверены SHA-256 81 файла сохранённых исходников по манифесту. | Для целевой БД подтвердить состояние схемы `pilot_staff`, ожидаемую версию SQL-проекции и совпадение двух назначенных снимков с текущими личными слотами. Совпадение декодера не подтверждает состояние БД. |
| Существующий staff-профиль | В инвентаризации от 18.11 уже были две допущенные служебные учётные записи и два назначения. На момент этого среза одно из назначений указывало на прежнюю сессию. Пакетный `provision` отклоняет существующий профиль, а `bind_sessions` допускает только первичную привязку. | Снять актуальные признаки профиля и совпадения назначений со слотами. Для уже настроенной базы согласовать работу с существующим профилем либо отдельную совместимую БД. Сохранение исторической привязки аудита обязательно. |
| Хост и сеть | Сохранённая конфигурация V00 подтверждает Linux ARM64, Docker Compose и внутреннюю сеть Docker без опубликованных портов БД. Пакет рассчитан на два отдельных процесса внутри защищённого bridge. | На выбранной среде подтвердить конкретный защищённый bridge, маршруты шлюза к двум приватным адресам процессов и доступ процессов только к подготовленной PostgreSQL. Порты БД и API должны оставаться закрыты извне. |
| HTTPS и клиентские сертификаты | Код архивного шлюза включает `CERT_REQUIRED` и загрузку клиентского CA. Новый отдельный шлюз проверен локально с тестовыми сертификатами и требует два разрешённых отпечатка. Архивный шлюз и новый шлюз имеют разные исходники. | Для выделенного служебного адреса проверить точное имя в SAN, цепочку и срок серверного сертификата, доверенный клиентский CA и два утверждённых отпечатка. Уточнить, где завершается TLS и как доступ ограничен закрытой сетью. |

Источники в Git — [манифест исходников 19.11](../oracle-demo-runtime/release-2026-11-19.json), [конфигурация V00](../../docs/technical/first-session/v00-oci/README.md), [закрытый пакет запуска](README.md), [операторский код staff](../staff-q06-local/kit/staff-db/004-operator.sql). Для фактов о БД использованы сохранённые срезы `demo-api-postgres-reconciliation-20261119.json` и `oracle-personal-inventory.jsonl`; данные учётных записей и настройки среды в отчёт не переносились.

Ближайшая проверка в выбранной среде сводится к одному чтению статуса профильной схемы и двух назначений, инвентаризации сети и сверке сертификата выделенного адреса. Пакетные команды `provision`, `activate` и `close_pilot` в это чтение не входят. Сверка проведена без подключения к Oracle, без записей в БД и без включения пилота.
