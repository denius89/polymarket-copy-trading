# S04 · Финансовый UX

Проверяй денежный смысл в указанном пользователем сценарии. Для визуального исполнения используй существующий UI kit и подходящий Figma workflow. Impeccable подключай для визуальной разработки или критики, когда он помогает задаче; финансовая вычитка сама по себе не требует его полного аудита.

- Установи роль, режим paper/live, площадку и состояние операции. Читай только затронутое принятое правило, не весь корпус финансовых ADR.
- Покажи статус, сумму/единицы, последствия и доступное действие. Pending, unknown, оценка и подтверждённый факт не должны различаться одним цветом. Unknown не превращается в отказ, нулевую комиссию или разрешение повторить платёж.
- Сохраняй структуру согласованного сценария. Не добавляй разделы, экраны, роли, показатели и финансовые правила ради полноты checklist. Если вариант состояния нужен в дизайне, сначала проверь существующий компонент/экран и возможность показать его там.
- Проверь только затронутые локали, размеры и состояния; при изменении общего компонента учти его потребителей. Не ограничивай задачу RU mobile из старого учебного примера и не объявляй EN/desktop проверенными без проверки.
- При порученной правке доведи её до проверяемого результата. Если требуется новое бизнес-решение, подготовь конкретный вариант и уточни только его; остальные согласованные правки продолжай.

Для Figma достаточно живого чтения и визуальной проверки затронутого дизайна; наличие макета не подтверждает серверную защиту или доступность с клавиатуры в приложении. Сообщай конкретный дефект/изменение и существенный оставшийся вопрос. Не составляй общий риск-отчёт для простой подписи.
