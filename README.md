# Controlled Copy Trading

Проект некастодиального сервиса контролируемого копирования сделок на prediction markets. Пользователь выбирает трейдера, задаёт бюджет и ограничения риска, а система объясняет каждое исполнение, пропуск и изменение позиции.

> **Состояние проекта:** идёт согласование продукта, экономики и архитектуры. Разработка MVP и реальные сделки ещё не разрешены.

## Быстрый вход в проект

Новому участнику достаточно пройти четыре шага:

1. Прочитать [текущее состояние](docs/PROJECT_STATE.md) — что уже решено, что является гипотезой и какой следующий результат нужен.
2. Открыть [карту документов](docs/README.md) — где искать продукт, экономику, архитектуру, GEO и исследования.
3. Посмотреть [актуальную дорожную карту](docs/ROADMAP.md) — текущий этап, очередь работ и условия перехода к разработке.
4. Перед изменениями прочитать [правила совместной работы](CONTRIBUTING.md) и [журнал решений](docs/decisions/README.md).

Вопросы безопасности и закрытые сообщения об уязвимостях описаны в [SECURITY.md](SECURITY.md).

## Коротко о продукте

- **Первый исследуемый пользователь:** мобильный клиент агентского канала с опытом USDT и ориентировочным бюджетом проверки $50–200.
- **Ценность:** проверить копируемость трейдера под свой бюджет, затем копировать с понятными лимитами, журналом и возможностью остановки.
- **Прямой продуктовый аналог:** Polyfox.
- **Execution-площадки:** Polymarket — первый кандидат; Limitless исследуется как альтернатива и возможный второй адаптер.
- **Интерфейс:** самостоятельный mobile-first web app; Telegram позже может использоваться для уведомлений.
- **Распределение:** реферальные агенты получают долю фактически полученной сервисной комиссии. Продукт не принимает клиентские платежи и не интегрируется с MobCash.

Рабочее позиционирование первой проверки: [документ 18](docs/18_first_validation_positioning.md).

## Что уже определено

- пользователь сохраняет контроль над кошельком и выводом;
- реальное исполнение выключено по умолчанию;
- система ведёт виртуальные лоты и не смешивает позиции разных источников;
- дневной лимит новых покупок и бюджет на трейдера блокируют увеличение риска;
- слишком поздняя покупка пропускается, а запоздалое закрытие требует актуальной сверки;
- критические уведомления нельзя полностью отключить;
- рейтинг не обещает доходность и отдельно показывает копируемость под бюджет;
- партнёрская программа и комиссии должны быть версионируемыми настройками.

## Главные открытые решения

1. Ранжировать GEO и подтвердить допустимую execution-площадку для первого запуска.
2. Подтвердить кошелёк, торговые полномочия и путь пополнения техническими spike-проверками.
3. Проверить позиционирование на 6–10 потенциальных пользователях.
4. Собрать готовую модель привлечения агента v0.
5. Согласовать окончательные документы продукта, архитектуры и плана.

Полный список и порядок работы находятся в [дорожной карте](docs/ROADMAP.md).

## Структура репозитория

```text
apps/                   будущие web app и фоновые процессы
packages/               доменная логика, адаптеры и тестовые инструменты
docs/                   продукт, экономика, архитектура, исследования и решения
docs/decisions/         короткие ADR с принятыми и предложенными решениями
research/               ограниченные исследовательские задания
artifacts/              презентации и готовые материалы
references/             локальные исходные материалы; могут отсутствовать в GitHub
infra/                  будущая инфраструктура
scripts/                проверки целостности проекта
```

Папки приложения пока содержат только описание будущих границ. Это сознательно: код начинается после завершения текущего decision gate.


## Ограничения безопасности

- не добавлять приватные ключи, seed phrase, session cookies и рабочие токены;
- не включать реальные ордера без отдельного решения основателя;
- денежные значения не рассчитывать через binary floating point;
- неизвестное состояние ордера блокирует новые конфликтующие действия;
- публичный запуск требует отдельных security- и legal-gates.
